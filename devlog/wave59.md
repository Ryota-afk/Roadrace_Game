# 第59弾：吸収された逃げが集団に復帰できるようにする

**状態**：**打ち切り・完了扱い（2026-08・ユーザー合意）**。詳細は末尾の「打ち切り」節。

## 診断（Opus・実測で確定）

第58弾Phase2後の`attack−hold`は+5.78で、狙った+1〜+3に届かなかった。原因の切り分けとして
「上振れが無い」「タイミングが悪い」「失敗時の罰が過大」の3仮説を実測で検証した。

- **上振れは既に出ている**：発火点0.60・n=96を成否で分けると、逃げ切れた場合（5位以内）は
  `hold`比 **−3.39着（大幅good）**。「刺されば勝てる」は成立していた。
- **タイミングは打ち手にならない**：発火点を0.30〜0.90まで7点振っても、どこで仕掛けても
  `attack`は`hold`に勝てない（0.90＝残り10%で仕掛けても大敗率45.8%）。カード提示位置を
  変える案は死んでいる。
- **失敗時の罰が過大（真因）**：吸収された場合（57.3%）は`hold`比 **+6.33〜+9.78着の大敗**。
  期待値 `0.427×(−3.39) + 0.573×(+6.33) = +2.18` は観測値と一致する。

⚠️**大敗の機構**：吸収時のenergyは攻撃側−85.9 vs 集団−72.3（`ENERGY_FLOOR`=−100）。
`energyPenaltyMul`比0.8935 < `keepThresh`0.915 → 即座に千切れる。千切れると`en.mode="solo"`
になり、`regen`は`sheltered=(mode==="draft")`が条件のため**回復が完全に0**になる。一度吐き
出されたら二度と戻れない死のスパイラル。⚠️`legsScaled`の下限効果と同様、第57弾で「不発」
表示を消しても割の悪さ自体は残っていた、という構造。

## 仕様（実装済み）

`pull`モードの「エースに合わせる」処理と同型の**線形減衰する一度きりの猶予**を`keepThresh`に足す。

- 新フィールド：`rejoinLeft`（猶予残りtick）・`rejoinDone`（一度きり保証）
- 発火：多人数グループのmode確定パスで`en.committedBreak && !en.rejoinDone`のとき
  `rejoinLeft = REJOIN_TICKS(45)`, `rejoinDone = true`
- 適用：`keepThresh`に`- REJOIN_KEEPTHRESH_RELIEF(0.08) * (rejoinLeft / REJOIN_TICKS)`を追加
- 消化：`conserveLeft`等と同じ履歴記録パスで`rejoinLeft--`
- リセット：`fromTick===0`の初期化ブロックと`resumeSim`冒頭の両方（`bridgedFrom`と同じ2箇所、
  Phase 1で踏んだ罠を再発させない）
- 適用範囲：プレイヤー・AI双方（第58弾が是正した非対称の再発を避ける）

コード変更は`src/sim/ticks.js`5箇所＋`src/sim/finish.js`1箇所のみ。`brk`・速度・
`ENERGY_REGEN_BASE`・`energyPenaltyMul`・同乗者選出条件・`bridgeCap`・カード発火タイミングは
一切変更していない。

## 実測結果（Sonnet）

### 合成データでの効果確認

実測値そのまま（吸収側energy−85.9・集団側−72.3）を再現した合成テストで、緩和なしは
即座に千切れる（0/29tick集団維持）のに対し、緩和ありは13〜18tick集団に留まれる
（`REJOIN_KEEPTHRESH_RELIEF`0.06〜0.20でスイープ、0.08で頭打ち）。**効果自体は実在する。**

⚠️**ただし0.08超に上げても改善しない**。ジッター（tickSpeedFactorの±3%）が原因かと
疑い`Math.random`を固定して再検証したが、ジッター無効化でも18/45tickで頭打ちのまま
（緩和なしは0/45tick）。**真因はジッターではなく、`positionTight`（集団内の位置に応じた
`keepThresh`の傾き）が時間とともに悪化する側へ効くこと**：低energyの選手は`ownCapable`が
低いため位置取り争いで後方(`posShare`↑)に押しやられ続け、`positionTight`が増える一方で
`rejoinRelief`は時間とともに線形減衰する——両者が同時に効くため、猶予期間内に収支が
追いつかない。

| 指標 | 導入前 | 導入後 |

**合成データでは効果が確認できるが、実レース集計では誤差範囲内の改善にとどまる。**
撤退基準（`hold`2着超悪化／平坦の逃げ30%超／`attack−hold`マイナス）には抵触していないが、
狙った+1〜+3には届いていない——第58弾Phase 1と同型の「機構は動くが効果不足」。

## 次の判断（Opus待ち）

効果が不十分な原因は特定済み（`positionTight`の悪化と緩和の減衰が競合し、猶予期間内に
収支が追いつかない）。考えられる方向：
- `REJOIN_KEEPTHRESH_RELIEF`をさらに上げる（0.08超は今回のスイープでは無効だったが、
  `positionTight`側の悪化を止める・遅らせる変更と組み合わせないと頭打ちのままの可能性）
- `positionTight`に`rejoinLeft`中は影響しない例外を作る（＝猶予期間中は位置取り争いで
  後方に落ちても`keepThresh`が悪化しないようにする）
- 現状の+5.78→+5.16という小さな改善で第58〜59弾を完了とする（撤退基準は満たしている）

いずれも設計判断のためOpusの検討が必要。

## 打ち切り（2026-08・ユーザー合意）

**第58〜59弾はここで完了扱いとし、`attack−hold`の数値を追う仕事は再開しない。**

理由：同じ1つの問題に第52弾から数えて**7回**挑戦し、効いたのは1回だけ（Phase2）。
毎回「機構を1つ特定→狭く直す→効かない→別の機構を特定」を繰り返しており、simは
相互作用する機構が多いためこの輪は無限に回せてしまう。⚠️さらに**目標値（+1〜+3）
自体がプレイ体験と結びついているか一度も検証されていない**——実測では仕掛けが決まった時は
`hold`比−3.39着goodで成功率42〜47%あり、「平均では損だが決まれば勝てる」は諸刃の剣として
むしろ正しい姿の可能性が高い。

再開する場合の条件：**数値ではなく「実際にプレイしてfelt problemとして観測されたか」を
先に示すこと。** 第57弾（このセッションで唯一確実に良くなった仕事）は実プレイ由来だった。

実装した機構（`bridgeCap`・`rejoinLeft`）はいずれも撤退基準を満たしており、
「仲間と一緒に逃げる」という当初の目的自体は達成しているため、**revertせず残す**。

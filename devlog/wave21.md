# 第21弾：拠点で選手が屋外でも過ごす（＋芝のはみ出し修正）

**状態**：設計合意済み・実装未着手（2026-08）

ユーザー指摘：「選手が外（コース以外）を歩いたり、ベンチに座ったり、ジムにいたりしてもいい
のでは」「緑色の四角（草？）が敷地を飛び出して見える」。
ユーザー選択：屋外の行き先は**ベンチ＋ジム＋散歩**／行き先は**ゲーム状態に連動させる**。

## 0. 先に片付けるバグ：芝の濃淡パッチが敷地からはみ出す

**実測**（`scatterPoints`の出力を直接評価）：

- 草むら（tuft）32点／うち濃淡パッチ 14枚
- **濃淡パッチ14枚中7枚が敷地矩形をはみ出す**。うち3枚は中心座標そのものが海の上
  （l = -8.1 / -8.2 / -8.3、敷地は lMin = -8）
- 例：(-8.6,-0.3) (-8.5,4.6) (-6.8,-8.1) (-5.3,-8.2) (-3.7,-8.3) (15.4,-0.3)

**原因**（2つ重なっている）：

1. `scatterPoints`のジッターが敷地の縁を越えた点を生む
2. 濃淡パッチは中心から**半幅1.1ユニットの菱形**なので、縁ぎりぎりの点は必ず外へ出る

現在の`within()`フィルタは`SCENE_BOUNDS`（＝カメラ可動範囲・海を含む画面座標）で切っており、
**陸地の形では切っていない**。

**修正方針**：座標を1点ずつ調整するのではなく、小川と同じく**陸地ポリゴンの`clipPath`で
形ごと切る**。`BaseView.jsx`に既にある`bv-land-clip`で`<Ground>`を包むだけ。散布数や
ジッター幅を将来変えても再発しない構造的な手当て。`<defs>`は現在Groundの後にあるが
可読性のためカメラ変換直下の先頭へ移す（SVGの参照順は不問なので挙動は変わらない）。

**検証**：海にかかっていた7枚が陸地の縁でぴったり切れること（実機スクリーンショット）。

## 1. 全体方針：サイクルの骨格は変えず「行き先」を一般化する

現行（`domain/season/riderActivity.js`）は96秒サイクルの6セグメント固定で、
**行き先の部屋だけ**が`destinationFor()`でゲーム状態（疲労）に応じて変わる。

```
ride 50s → approach 4s → walkIn 10s → work 18s → walkOut 10s → depart 4s
```

この骨格を**一切変えない**。`destinationFor()`の戻り値を「部屋key」から
**行き先オブジェクト**へ広げ、屋内行きなら現行どおり玄関→廊下→扉→持ち場、
屋外行きならラックから芝を歩いてベンチ／ジム／散歩路へ向かう。自転車をラックに
置いて徒歩、という点は屋内外で共通。

```js
// 変更前: destinationFor(riderId, fatigue, cycleIndex, roomKeys) -> "medical"
// 変更後: destinationFor(rider, riderIndex, cycleIndex, ctx)
//         -> { kind: "room"|"bench"|"gym"|"stroll", key, spot:{w,l}, pose, route }
```

## 3. 行き先の重み（ゲーム状態連動）

既存の思想「拠点を一目見ればチームの状態が分かる＝装飾ではなく情報」を踏襲する。
参照するフィールドは全て既存：`rider.fatigue`（0〜100）、`rider.type`（`TYPES`のキー
SPR/CLM/RUL/PUN/TT）、`rider.age`。選択は`riderHash01`で決定論的（`Math.random()`不使用）。

| 行き先 | 基礎重み | 状態による加減 | 意味 |
|---|---|---|---|
| medical | 1.0 | `tired = clamp((fatigue-35)/50, 0, 1)` として `+ tired * 5.0`（現行式を踏襲） | 疲れている選手が医務室に居る |
| training | 1.0 | `age <= 22` なら ×1.6 | 伸び盛りは練習場 |
| mechanic | 1.0 | — | |
| scout | 1.0 | — | |
| bench（4脚を1グループ） | 1.5 | `30 <= fatigue <= 60` なら ×1.6／`fatigue >= 85` なら ×0.4 | ひと休み。重度の疲労はメディカルへ流す |
| gym | 1.2 | type が SPR/RUL/PUN なら ×1.8／`age <= 22` なら ×1.3 | 脚質が絵に出る |
| stroll | 1.0 | — | 賑わい |

未解禁のジムはリストから外れ、重みは残りで再正規化される（＝Lv3で解禁した瞬間に
ジムへ人が向かい始める＝レベルアップの手応えになる）。

## 4. 同じ場所に複数人が重なる問題（純関数のままの解決）

現行の`riderActivityAt`は他の選手を見ない純関数。ベンチは1脚1人なので、素朴に
ハッシュで選ぶと2人が同じベンチに重なる。

**解決**：`riderActivityAt(rider, tSec, ctx, riderIndex)` に**ロースター内の並び順**を渡し、
`bench[(riderIndex + cycleIndex) % 4]` のように**決定論的かつ衝突しない**割り当てにする。
ジムも同様に、ジム周囲に**3つの立ち位置スロット**を定義し `slot[(riderIndex + cycleIndex) % 3]`
で割り当てる。純関数性は保たれる（引数が1つ増えるだけ）。

`riderIndex`は`BaseView.jsx`の`roster.map((r, i) => ...)`から渡す。

## 5. 散歩（stroll）の巡回路

敷地の外周を反時計回りに歩く折れ線（コース帯・小川・池・木・チームカーを避ける）。
`walkIn(10s) + work(18s) + walkOut(10s) = 38秒`を通しで1本の経路として扱い、
38秒で巡回路を1周する。

暫定の点列（実装時に検証器で当たりを取って確定する）：

```
(5.2,-5.4)ラック → (2.8,-6.8) → (-1.0,-7.2) → (-4.5,-7.0) → (-7.5,-5.0)
→ (-8.2,0.0) → (-7.8,4.5) → (-5.0,7.0) → (-1.0,7.6) → (2.5,7.0)
→ (4.5,4.0) → (4.4,0.0) → ラックへ戻る
```

## 7. 吹き出し（riderChatter）

ベンチ・ジムは「持ち場での作業(work)」相当なので喋ってよい。散歩は移動中なので
現行の「移動中は喋らない」方針に合わせて喋らせない。セリフ表
（`data/baseViewChatter.js`）に屋外用の分類を足すかは実装時に判断（既存の汎用セリフで
成立するなら足さない＝CLAUDE.md §7「足す前に消す・流用を検討」）。

## 8. ACTIVITY_CTXのゲーム状態依存化

現在はモジュール読み込み時に一度だけ静的に構築している。ジムの解禁を反映するため、
`useMemo(() => buildActivityCtx(g), [g.equip.grounds])`（依存は敷地整備Lvのみ）へ変更する。

**Wave F-3aの「純関数」設計は維持される**：`riderActivityAt`自体は引数だけから答えを
決める純関数のままで、その`ctx`がゲーム状態から作られるようになるだけ。Node単体テストも
`buildActivityCtx({equip:{grounds:N}})`を渡せば従来どおり機械検算できる。

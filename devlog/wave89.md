# 第89弾：自動プレイハーネスの作り直しと、第87・88弾の実測

**状態**：**ハーネスは直り48年目まで完走（エラー0件）。⚠️しかし実測の結果、第87弾の是正は2つとも目標未達と判明。是正案は未着手。**

## 動機

第87・88弾（年俸・人気度の是正、資金の使い道2種）は⚠️**実装は完了したが実測が未達**だった。
CLAUDE.md §10は「機能追加とバランス計測はセットで行う」「後で測るは禁止——実績として
測られたことがない」と定めており、⚠️**この状態のまま次の機能へ進むのは規約違反**である。

原因は第86弾で作った自動プレイハーネスが3回とも完走しなかったこと。この弾はまず
ハーネスを直し、そのうえで第87・88弾の数値を実測する。

## ⚠️特定した欠陥：危険な操作を「文言の列挙」でブロックしていた

旧ハーネスは破壊的操作を正規表現で列挙して避けていた：

```js
const BLOCK = /最初からやり直す|タイトルに戻る|モード選択に戻る|静かに引退|引退する|.../;
```

⚠️**マイライフの「キャリアを終える」導線を全部洗い出したところ、2つが漏れていた**：

| 文言 | 種別 | 旧BLOCKに一致するか |
|---|---|---|
| `静かに引退` | メニュー項目 | ○ |
| `最初からやり直す` | メニュー項目 | ○ |
| `今季限りで引退する` | 引退勧告のカード | ○（`引退する`を含む） |
| ⚠️**`ラストレースで引退`** | **メニュー項目** | ⚠️**×**（`引退する`とは別語） |
| ⚠️**`出走する`** | **上記の確認ボタン** | ⚠️**×** |

`hub.jsx:518`の「ラストレースで引退」には⚠️**年齢制限が無い**ため、
⚠️**自動プレイは何歳でもここから引退でき、引退画面から監督モードへ遷移できてしまう。**

⚠️**教訓：文言の列挙は、文言が増えるたびに漏れる。** 実際、第86弾で1つ塞ぎ、
第87弾で3つ足し、それでもまだ2つ残っていた。

## 作り直し：色（構造）で判定する

このゲームのUIには⚠️**破壊的操作を示す構造的な規約が既にある**（CLAUDE.md §9の
`T.color.bad`＝「負け・消耗」）。文言ではなくこれを使う：

| 対象 | 判定 | 根拠 |
|---|---|---|
| 確認ダイアログの**確定**ボタン | `background === T.color.bad` | `components/chrome.jsx:85` |
| 危険なメニュー項目 | `color === T.color.bad` | `hub.jsx`の`item(..., T.color.bad)` |
| 確認ダイアログの**キャンセル** | 文言`やめる`（常にこれを押す） | `chrome.jsx:84` |

⚠️**確認ダイアログが開いていたら無条件で「やめる」を押す**方針にした——
このハーネスの目的は「キャリアを最後まで走らせて数値を測る」ことなので、
⚠️**破壊的操作を一切承認しないのが正しい既定**である。

色で判別できない脱出系（`タイトルに戻る`・`モード選択に戻る`・引退画面の
`監督として新チームを率いる`・`新たな選手でキャリアを始める`）だけ文言で塞ぐ。

シーズン化の検出も⚠️**「あなたのチーム」（シーズンの既定チーム名。マイライフには絶対に
出ない）**へ変更した。旧版は「昇格まで…pt」で判定していたが、
⚠️**`chrome.jsx:174`でマイライフのヘッダも同じ文言を出しており誤検出し得た。**

## ⚠️未解明のまま残したこと

⚠️**第87弾の2回目の実行がシーズン化した経路は特定できていない。**
1回目は当時ブロックリストに`監督として新チームを率いる`が無かったことで説明が付くが、
2回目は追加済みだった。クリック履歴を記録する診断版を回したが、
⚠️**打ち切りまでの間に再現しなかった**（＝毎回起きるわけではない）。

作り直したハーネスにはクリック履歴の記録を残してあるので、
⚠️**再発したらそのログで経路が判明する**。再発しなければ、上記の
「ラストレースで引退」経路が原因だったと考えるのが自然（ただし確証ではない）。

## 実測結果：ハーネスは直った。⚠️**しかし第87弾の是正は2つとも目標未達だった**

作り直したハーネスは⚠️**4000ステップ・48年目まで完走し、season化もエラーも0件**。
ハーネス側の問題は解消した。以下はその実測値（`scratchpad/play90/log.txt`）。

| 年目 | 人気度(4月) | 資金 | 年俸 |
|---|---|---|---|
| 1 | 16.0 | 0 | 280 |
| 5 | 57.0 | 1,353 | 458 |
| 10 | **90.0** | **7,507** | 1,840 |
| 20 | 90.0 | 33,148 | 3,300 |
| 46 | 90.0 | 約108,000 | 約4,000 |

### ⚠️①-a 年俸：長期は5倍改善したが、10年目の目標は未達

- 46年目の資金：**559,409万円 →約108,000万円（約5.2倍の改善）**。上限は効いている。
- ⚠️**しかし10年目は6,525→7,507で改善していない**（別乱数の実行なので厳密な比較では
  ないが、目標「10年目で最高額の買い物900万円の数倍」に対し**8.3倍**で未達）。
- 理由：10年目の年俸は1,840万で、⚠️**クラス別上限（B1:1200/A:3000/PRO:8000）がまだ
  効き始めていない**。上限が効くのは20年目以降で、狙った10年の地平では素通りする。

### ⚠️②人気度：直っていない。毎年100へ飽和している

4月のスナップショットが90.0で揃っていたのは⚠️**年度末減衰（×0.9）の直後を見ていただけ**
だった。月次で追うと：

```
11年目4月 90.0 → 9月 92.1 → 11月 99.4 → 1月 100.0 → 3月 100.0（4ヶ月間 張り付き）
12年目4月 90.0 → 7月 99.9 → 9月 100.0 → 3月 100.0（7ヶ月間 張り付き）
```

⚠️**毎年4〜6ヶ月で上限に到達し、年の半分以上を100で過ごす。** 目標「10年目で70〜85に
落ち着き、100に張り付かない」は**未達**。

**原因：逓減を1箇所にしか入れていなかった。** `applyPopGain`を通らない
⚠️**直接書き込みが4箇所**ある：

| 場所 | 内容 |
|---|---|
| `controllers/mylife/event.js:30` | イベントの`popularityDelta`（スポンサーの仕事+2〜4、ライバル会話+3） |
| `controllers/mylife/event.js:157` | 弟子等のイベント効果 |
| `controllers/mylife/result.js:191` | アシスト成功の`assistPop`（+0.5〜3） |
| `domain/mylife/ambition.js:31` | アンビション報酬の`reward.pop`（⚠️**最大+25**） |

⚠️**第83弾・第85弾で「同じ値が複数箇所にあり片方だけ直すと取りこぼす」類型を
2回記録した本人が、3回目を踏んだ。** 第84弾で`applyPopGain`を切り出したとき
「通常レースとチームTTの唯一の合流点」と書いたが、⚠️**それは"レース由来の"人気度に
限った話で、イベント・アンビション由来の経路を見ていなかった。**

## ⚠️発見：移籍時の年俸がクラス上限を無視する

`controllers/mylife/career.js:39`：

```js
const salary = Math.round(s.salary * offer.salaryMul);   // ⚠️上限の再適用が無い
```

第87弾で年度末の改定にはクラス別上限を入れたが、⚠️**移籍の年俸倍率（1.05〜1.6）には
入れていなかった。** 実測で**クラス0（B1・上限1,200万）なのに年俸3,300万**という
状態が繰り返し観測される（3,000＝A級の上限×1.1）。翌年度末には再クランプされるが、
⚠️**移籍を挟むたびに上限を超えた年俸で1年間過ごす。**

## ⚠️この実測で分かった限界

# 第18弾：僚友と絆（スピリット接続）

**状態：設計合意済み・実装待ち**。8番 Phase 3（マイライフに自チームの僚友システムを新設し、
新ステータス「スピリット」を接続）に着手する。

## 着手時の実測

### 僚友の「実体」は既にあり、「関係性」だけが無い

- `ml.teammates`は`worldRosters[自チーム]`の上位11名（`mlTeammatesFromRoster`・第11弾で
  実在ロースター化済み）。毎年`ageWorldRosters()`で加齢・成長・引退・新人補充が回り、
  レースにも一緒に出走し（`buildMyLifeSim`のisMyTeam分岐）、`riderStats`に戦績も積まれ、
  チーム名鑑画面（`mylife_teamroster`・`screens/mylife/career.jsx:228`）もある。
- しかし**何年一緒に走っても何も変わらない**。絆・信頼・結束にあたる状態が一切なく、
  「同じジャージを着た他人」のまま。
- **マイライフのレースsimにはケミストリーが無い**：シーズンは`teamChemistryTier`（在籍年数
  ベース）の`chemMul`（0.92〜1.0・ドラフト時の消耗軽減）が効くが、マイライフの自チームには
  相当物が未配線。`sim/ticks.js:564`は既に`en.chemMul || 1`を消費しているため、
  **エントラントにchemMulを付けるだけで動く**（sim本体の改修不要）。

### スピリットの受け皿も既にある

- `genSubStats`（`core/core.js:179`）は突破力・安定感の前例あり（生まれつき固定・
  脚質差ゆるやか44〜58・クランプ20〜95）。
- `RiderRadarChart`（`components/RadarChart.jsx:87`）のaxes配列は軸数可変で、実装コメントに
  「将来のスピリット追加時に7角形へ拡張しても改修不要」と既に書いてある。

## 確定仕様（ユーザー合意済み・2026-08）

1. **個別の絆＋平均が結束**：僚友ごとに絆があり、共闘・勝利で育つ。絆の平均＝チームの結束
   としてレースに効く。
2. **スピリット＝生まれつき固定のサブステ**：突破力・安定感と同じ前例（genSubStatsで生成時
   固定・脚質差ゆるやか・レーダー7角形化）。高いほど絆が早く育ち、結束の上限が高い。
3. **「僚友の育ちやすさ」は実際の成長に効く**：絆の高い僚友は年次のbaseline成長が良くなる
   （自チームのみ・移籍すると失う。世界の対称性を少し崩すことは合意済み）。
4. **弟子（プロテジェ）も絆に含める**：既存の指導イベント・育成はそのまま、絆の数値だけ
   共通化。チームの結束にも寄与する。

## 詳細設計

### A. スピリット（新サブステ）

**A-1. 生成**（`core/core.js`の`genSubStats`へ追加）：
```js
// スピリット：仲間と走る力。ルーラー（献身の脚質）がやや高め、独走屋（一人で走る）がやや低め
const spiritBase = { RUL: 56, PUN: 52, CLM: 50, SPR: 48, TT: 44 }[type] ?? 50;
// breakthrough/stabilityと同じくjitter＋クランプ20〜95、性格補正なし・逸材補正なし
```
突破力・安定感と同じ狭い幅（44〜56）に留める。**全選手が持つ**（シーズン選手にも生成される。
機能的に使うのは当面マイライフのみ＝運の前例と同じ扱い）。

**A-2. 表示**：`RiderRadarChart`のaxes配列に`{ label: "スピリット", value: r.spirit ?? 50, max: 100 }`
を追加（6角形→7角形）。旧セーブ・既存選手は`?? 50`で描画（補完コード不要）。

### B. 絆（bonds）

**B-1. 保存形**：`ml.bonds = { [riderId]: number }`（0〜上限）。`initMyLife()`に`bonds: {}`、
`ML_SAVE_FIELDS`に`"bonds"`を追加。旧セーブは`loadMyLifeGame()`で
`if (!merged.bonds || typeof merged.bonds !== "object") merged.bonds = {};`。

**B-2. 育ち方**（`controllers/mylife/result.js`のレース確定処理に追加）：
- 共闘した僚友＝`sim.ranked`のうち`id`が`s.teammates`／`s.protege`のidに一致する者。
- 1レース共闘ごとに `gain = 2 × spiritMul`。プレイヤーが3位以内なら`+1`、
  作戦が`assist`（アシスト）だったレースは`×2`（献身が絆を深める）。
- `spiritMul = 0.7 + (player.spirit ?? 50) / 100 × 0.6`（スピリット50=1.0、20=0.82、95=1.27）。
- 上限：`bondCap = min(100, round(55 + (player.spirit ?? 50) × 0.5))`
  （スピリット50=80、20=65、90=100）。
- 減衰なし。年度末に現メンバー（`nextTeammates`＋弟子）以外のidを刈り取る（移籍・引退で
  自然に関係が消える。移籍時も同様に新チームでは0から）。

**B-3. 絆の段階呼称**（表示用・純関数`bondTier(v)`）：
| 値 | 呼称 |
|---|---|
| 0〜19 | 顔見知り |
| 20〜44 | 仲間 |
| 45〜69 | 信頼 |
| 70〜89 | 相棒 |
| 90〜100 | 無二の親友 |

### C. 結束（チームケミストリー）

- `buildMyLifeSim`のisMyTeam分岐で、**実際に出走する僚友（＋弟子）の絆の平均**から
  `chemMul = 1 - (avgBond / 100) × 0.08`を算出（絆0=1.0＝効果なし、絆100=0.92＝
  シーズンの最良ティアと同値）。自チームの全エントラント（プレイヤー本人を含む）に付与。
- `sim/ticks.js`は無改修（既存の`en.chemMul || 1`がそのまま消費する）。
- `buildMyLifeSim`のシグネチャに`bonds`を追加（末尾引数・省略時は効果なし＝旧経路無影響）。

### D. 僚友の育ちやすさ（年次成長ボーナス）

- `controllers/mylife/month.js`の年度末ブロックで、`ageWorldRosters()`の**戻り値に対する
  後処理**として適用（`ageWorldRosters`自体は無改修＝シーズンに影響しない。第16弾の
  `ageRival`と同じ手筋）：
```js
// 絆の高い僚友は練習の質が上がり、実際の成長（baseline）が良くなる。生き残った現メンバーのみ対象
aged.worldRosters[s.team] = aged.worldRosters[s.team].map(r => {
  const bond = (s.bonds || {})[r.id] || 0;
  const boost = bond >= 85 ? 2 : bond >= 60 ? 1 : 0;
  return boost ? { ...r, baseline: Math.min(14, (r.baseline || 0) + boost) } : r;
});
```
- クランプ14は`ageWorldRosters`内部の上限と同値（自チームだけ上限を超えないため）。
- ログは出さない（§7の抑制。効果は名鑑の成長と結束の数字で見える）。
- 適用後にbaseline降順の再ソートを行う（`ageWorldRosters`の不変条件を保つ）。

### E. UI

**E-1. チーム名鑑（`mylife_teamroster`）**：各僚友の行に絆（段階呼称＋ゲージ）を追加し、
画面上部に「結束」のサマリ（平均絆→段階表示）を置く。**実装前にCLAUDE.md §8の手順で
実データのモックを2〜3案提示して選んでもらう**（第17弾Bと同じ運用）。
弟子が名鑑に載っていない場合は載せ方も候補に含める。

**E-2. レーダー7角形化**：A-2のとおり（マイライフ・シーズン両方の選手カードに自動反映）。

**E-3. ヘルプ**：マイライフのヘルプに「僚友と絆」節を追記（§6方針）。

### F. 波及範囲の切り分け

- A（スピリット生成）は全選手に入るが、機能配線（B〜D）はマイライフ専用。
  シーズンの挙動は不変（`teamChemistryTier`は従来どおり在籍年数ベースのまま）。
- `ageWorldRosters`・`sim/ticks.js`は無改修。
- 旧セーブ互換：①`bonds`未保存→`{}`②`player.spirit`欠落→全読み取り点で`?? 50`
  ③絆0の状態は結束ボーナスなし＝現行と同じレース挙動（回帰なし）
  ④シーズンの既存選手（spirit欠落）はレーダーが50で描画されるのみ。

## 検証

- 各ステップでNode単体テスト（scratchpad）＋ビルド。UI変更はPlaywrightのスクリーンショットで
  目視確認（CLAUDE.md §7の点検を含む）。
- 回帰：`bonds`が空（旧セーブ・新規開始直後）のときレース結果・年次成長が改修前と
  完全一致することをNodeで確認。シーズンモードのロースター成長が一切変わらないことを確認。
- 較正：結束の効果量（0.92下限）はシーズンの実績値をそのまま流用するため、第17弾Dのような
  専用の較正ラウンドは置かない。ただしCの検証で「絆100のフル結束が勝率に与える差」を
  1回実測し、異常（±20pt超のような過大）が出た場合のみ係数を見直す。

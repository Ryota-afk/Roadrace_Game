# 第57弾：勝負所のカードから「不発」を廃止する

**状態**：**設計確定（ユーザー合意済み・2026-08）**。実装はSonnet。

実機を1レース通しで遊んで見つけた問題を直す弾。数値ではなく画面から出発している。

---

## 実機で見えたこと

勝負所のカードで、3択のうち2つが「不発」でグレーアウトし、実質「集団で勝負」の1択に
なっていた（スクリーンショットは`scratchpad/shots/14_decision_card.png`）。

## 実測1：勝負所は3回に1回以上、実質1択になっている

`scratchpad/w57_cards.mjs`（マイライフ・5テンプレート×n=40・主力power74）：

| カード | 選択肢 | 生きている数 | 不発率 | **実質1択の割合** | その時の脚 |
|---|---|---|---|---|---|
| mid（中盤） | 3.00 | 2.85 | 5.2% | **0.0%** | 0.523 |
| **finale（勝負所）** | 3.00 | **2.27** | **24.3%** | **36.5%** | **0.237** |

中盤は健全で、問題は勝負所に集中している。原因は構造的で、勝負所の3択は
`kick`／`send`／`hold`だが、**残脚スケール対象（`LEGS_SCALED_MOVES`）でないのは`hold`だけ**。
脚が減ると必ず`hold`だけが残る。

## 実測2：「不発」は事実に反している

`moveEdge.js`の冒頭コメントは**「sim本体と同じ`legsLeft01`を使い、表示と実際の挙動を
食い違わせない」**と宣言しているが、`不発`ラベルはまさに食い違わせていた。

| 一手 | 脚が空(g=0)でも | 不発の閾値(g=0.15)で |
|---|---|---|
| `kick`（差しにかける） | 最大の**27%** | **38%** |
| `kickBig`（会心の差し） | **29%** | **40%** |
| `sprintWait`（スプリント勝負） | **31%** | **41%** |
| `send`（早駆け・追い込み量） | **23%** | **35%** |

**「今は効かない」と表示しながら、実際は3〜4割効いている。** どの一手も効果に下限
（`KICK_MIN`等）があるため、**効果が0になる状態はそもそも存在しない**。

## 確定仕様（ユーザー合意済み）

### 1. `moveEdge.js`：`不発`を廃止する

```js
// 変更前
export function moveEdge(moveId, energy) {
  const g = legsLeft01({ energy });
  const base = moveTierBase(moveId);
  const dud = LEGS_SCALED_MOVES.has(moveId) && g < DUD_THRESHOLD;
  return { tier: dud ? "dud" : base, g };
}
// 変更後
export function moveEdge(moveId, energy) {
  const g = legsLeft01({ energy });
  return { tier: moveTierBase(moveId), g, legsScaled: LEGS_SCALED_MOVES.has(moveId) };
}
```

- `DUD_THRESHOLD`（0.15）は**削除**する。
- `LEGS_SCALED_MOVES`は**残す**（`legsScaled`の判定に使う）。
- 冒頭コメントのレア度一覧から`不発`の行を削除し、廃止の根拠（上の実測表）を書く。

### 2. `DecisionCard.jsx`：グレーアウトを撤去し、脚依存の一手にだけバーを出す

**撤去するもの**（`CardButton`）：
- `const dud = tier === "dud";`
- `opacity: ... (dud ? 0.45 : 1)` と `filter: dud ? "saturate(.3)" : "none"`
- ラベルの `color: dud ? T.color.sub : T.color.text`（常に`T.color.text`にする）
- `不発`バッジの`<span>`ブロックまるごと
- `CardGlow`の `if (tier === "dud") return null;`（`不発`が無くなるため、虹／金の発光は常に出る）

**足すもの**：`legsScaled`が真の選択肢にだけ、ラベルの下に細いバーを1本置く。

- 値は`g`（`legsLeft01`）。**脚バーと同じ量**なので**同じ色段階**を使う
  （これで「上の脚バーと同じ数字だ」と一目で繋がる）。
- 高さ**3px**（上の脚バーは6px＝主、こちらは従）。幅はボタン内側いっぱい。
- 背景は`T.color.surface`（ボタン地の`surfaceUp`より暗い＝残量が読める）。
- **脚に依存しない一手（`hold`/`conserve`/`hangOn`等）にはバーを出さない。**
  ユーザー確認済み：出さないほうが「この2つは脚次第／これは脚に関係ない」の差が読める。

⚠️色段階は`LegsBar`と**二重管理にしない**（CLAUDE.md §5）。`LegsBar`内のtier判定を
`legsTier(energy)`のような小さなヘルパーへ括り出し、バー側と共用する。

### 3. 文言：「売り切れ」をやめる

ユーザー指摘「脚が売り切れるという言い回しは変」。

| 箇所 | 現状 | 変更後 |
|---|---|---|
| `DecisionCard.jsx` 脚バー最下段 | 売り切れ | **限界** |
| `raceDecisions.js` `react`副題 | 脚が**売り切れかけている**——粘るか、立て直すか | 脚が**尽きかけている**——粘るか、立て直すか |

段階は `十分 → やや消耗 → 苦しい → 限界`（境界は現行のまま raw 40／0／−60）。

内部コメントの「売り切れ」も併せて直す（`ticks.js`の`LEGS_EMPTY`付近と`send`の説明、
`moveEdge.js`、`raceDecisions.js`の`buildDecisions`内）。⚠️特に`ticks.js`の
「売り切れた脚での早駆けは**不発に終わる**」は**事実として誤り**（実測23%）なので、
表現を実態（効果が下限まで落ちる）に合わせる。

# 【保留】仲間が乗る（プレイヤーの`attack`を集団にする）

⚠️**この設計は合意済みだが着手を見送った。** 実機を見たところ、**そもそも勝負所で
`attack`系の一手が「不発」で選べない**状態だったため、順序として先に上の弾を行う。
診断と実測は有効なので、再提案しないためではなく**次に使うため**に残す。
（ユーザー合意は取れているので、この弾の後に着手できる。）

## 前提：第56弾の凍結バグ修正で状況が変わった

**第52〜55弾の逃げの実測はすべて凍結バグがある状態で測ったもの**だった
（全テンプレートの13〜43%のレースで発生していた）。逃げ集団は小さい（平均2.4〜4.1人）ため
**エースだけの集団になりやすく、凍結して死んでいた**。

修正後に測り直すと、**AIの逃げは既に成立するようになっていた**（`w55_breaktype.mjs`・n=40）：

| テンプレート | 集団逃げ 旧→新 | 単独逃げ 旧→新 |
|---|---|---|
| クリテリウム（平坦） | 5.0% → **20.0%** | 0% → 0% |
| サーキット | 2.5% → **10.0%** | 0% → 0% |
| 丘陵ロード | 2.5% → 5.0% | 0% → 0% |
| 山岳ロード | 0% → 0% | 2.5% → 0% |
| ヒルクライム | 0% → **30.0%** | 0% → **15.0%** |

**第52〜55弾の4回が追っていた「逃げが成立しない」の相当部分は、あの凍結バグの症状だった。**

## 残った問題と、その構造的な原因

残るのは**プレイヤーの`attack`カードだけが機能しない**こと
（`w55_sweep_one.mjs`：`hold` 12.00 vs `attack` 25.03 ＝ **+13.03着悪化**）。

原因は実測で完全に特定できた（`scratchpad/w57_solo.mjs`・n=30）：

| | 飛び出す人数 | tick30時点で形成される集団 | 単独のまま |
|---|---|---|---|
| **AIの逃げ** | tick0に**7.9人が一斉** | 平均**5.1人の集団** | 1.1人 |
| **プレイヤーの`attack`** | **1人だけ** | **単独** | — |

そして**平坦・丘陵では単独逃げの勝率は0.0%**（上表）。
**`attack`カードは、その地形で勝率0%の形にプレイヤーを送り込んでいた。**
AIの逃げロールは`ticks.js`の`fromTick===0`枝で
`en.attackLeft = (en.role === "breakaway" ? BREAKAWAY_ATTACK_TICKS : 0)`により
**全員が同時に飛び出すため最初から集団になる**。この機会がプレイヤーにだけ無い。

**なお`brk`はこの問題を解けない。** `brk`は`committedBreak && (mode==="solo"||"attack")`＝
**単独の時しか掛からない**ので、成功している集団逃げには最初から1ミリも効いていない。
`brk`を下げる案は実測で棄却した（下記「やらないこと」）。

## 確定仕様（ユーザー合意済み）

### 1. `RACE_MOVES.attack`に「同乗」を足す

`src/sim/ticks.js`の現行：

```js
  attack: (r) => {
    const g = legsLeft01(r);
    r.attackLeft = Math.round(ATTACK_MIN_TICKS + (BREAKAWAY_ATTACK_TICKS - ATTACK_MIN_TICKS) * g);
    r.committedBreak = true; r.conserveLeft = 0; r.holdOn = 0; r.energy -= 9;
  },
```

第2引数`riders`は既に`finish.js`の`RACE_MOVES[moveId](focus, riders)`で渡されている
（`teamShelter`/`teamChase`/`assistLaunch`が既に使用）。シグネチャを`(r, riders)`へ変える。

**同乗者の条件**——**新しい判定基準を発明せず、既存の自発アタック抽選のフィルタをそのまま使う**
（`ticks.js`の`if (en.isPlayerChar || en.isAce || ...)`の行。同じ母集団＝「集団ゴールで
勝ち目が薄く、飛び出す動機がある選手」を指す）：

- `en === r` を除外（本人）
- `en.isAce` を除外
- `en.attackLeft > 0` / `en.committedBreak` を除外（既に逃げている）
- `en.mode === "solo"` を除外（既に千切れている）
- `en.energy < 42` を除外
- `sprintGap = max(flat, climb, sprint, stamina, solo) - sprint` が **8未満**を除外
- **`en.groupId === r.groupId`**（プレイヤーと同じ集団にいる選手のみ）
- `en.finished` を除外

**人数と選び方**：
- **最大2人**（`BRIDGE_MAX = 2`。プレイヤーと合わせて3人＝実測で勝っている集団逃げの規模）
- **`sprintGap`の降順**で選ぶ（集団ゴールで最も勝ち目が薄い＝最も乗る動機がある選手）。
  **同値は`id`の昇順**で決定論的に割る（`Math.random()`は使わない）
- ⚠️**確率は使わない。条件を満たす候補が居れば必ず乗る。** 理由：プレイヤーには既に
  「逃げが残るか」という大きな不確実性があり、そこに同乗のコイン投げを重ねるとカードが
  読めなくなる。候補数はレース状況で自然に0〜2人へ変動する。

**同乗者に与える値**（プレイヤーと揃える）：
- `attackLeft` = **`r.attackLeft`と同じ値**（バラけると置いていかれる）
- `committedBreak = true` / `conserveLeft = 0` / `holdOn = 0`
- `energy -= 9`（プレイヤーと同じ代償。ノーコストで乗せない）
- 難易度スケール用に**`en.bridgedFrom = r.id`のマーカーを立てる**（下記2で使う）

### 2. `finish.js`の難易度スケールを同乗者にも掛ける

`applyMove`の現行のスケール処理は`focus`にしか掛かっていない。このままだと難易度によって
**プレイヤーと同乗者の持続がズレて逃げが分解する**。既存の
`riders.forEach(en => { if (en !== focus && en.finaleSend) en.finaleSend *= eff; })`
と同じ形で1行足す：

```js
      riders.forEach(en => { if (en !== focus && en.bridgedFrom === focus.id && en.attackLeft > 0) en.attackLeft = Math.max(6, Math.round(en.attackLeft * eff)); });
```

`bridgedFrom`は使い終わったら消すか、次の一手で上書きされる前提にすること
（レース跨ぎで残らないよう`fromTick===0`の初期化ブロックでも`null`にする）。

### 3. 空の状態（empty state）

条件を満たす候補が1人も居ない場合（全員エース／脚が42未満／スプリンター揃い／
プレイヤーが既に単独）は、**現状どおり単独で飛び出す**。カードは撃てるが決まりにくい、
という今の挙動をそのまま残す。**エラーにも不発表示にもしない。**

### 4. UIは変更しない

この弾では判断カードの文言・表示を変えない。「何人乗ったか」を見せるかどうかは
実測で効果を確認してから、CLAUDE.md §8の手順（候補提示→合意→実装）で別途決める。

## やらないこと

- ⚠️**`brk`は変更しない。** 修正後のsimで実測したところ、`attack−hold`を狙って`brk=0.25`に
  すると**平坦の逃げが20.0%→27.5%・丘陵が5.0%→22.5%**と第55弾で決めた目標
  （平坦10〜15%／丘陵8〜12%）の約2倍になり、`hold`も12.00→13.04（+1.04着）動く。
  **プレイヤーのカードとAIの逃げが同じレバーを共有しているため、カードを狙って調整すると
  レースの形が壊れる。** 参考値：

  | brk | terrain/hold | terrain: attack−hold | mid: attack−hold |
  |---|---|---|---|
  | 現行`{mtn:0.4…sprint:0.85}` | 12.00 | +13.03 | +5.85 |
  | 0.30 | 12.67 | +7.46 | +1.35 |
  | 0.27 | 12.02 | +5.82 | +1.40 |
  | 0.25 | 13.04 | +2.83 | +0.11 |
  | 0.22 | 13.28 | ⚠️**−0.61** | ⚠️**−0.79** |

- ⚠️**速度には一切触らない**（第52〜55弾で軸そのものが行き止まりと確定済み。
  `ARCHITECTURE.md`のレースsim節）。
- ⚠️**AIの自発アタック抽選には同乗を適用しない。** AI逃げ屋は既にtick0で7.9人が一斉に
  飛び出して5.1人の集団を作っており、**集団を作る機会が無いのはプレイヤーだけ**だから
  （優遇ではなく**是正**）。AIにも広げると発火頻度が数倍になり、いま正しく収まっている

- `send`（早駆け）は`committedBreak = false`の別物なので対象外。
- **山岳ロードの逃げ0%**は扱わない。⚠️`brk`をどう変えても0%のままで、
  「最終登坂で本隊が逃げを捕まえる山岳ロードレース」として筋が通っており、
  バグと断定できない（`mtn: 0.4`という全地形で最強の割引が既に効いた上での0%）。

## 予測と撤退基準（実装前に明示）

**狙う値**：`attack−hold`を現在の**+13.03から+1〜+3**へ。
⚠️**`hold`とレースの形は動かさないこと。**

**撤退基準（1つでも該当したら同乗の仕組みを撤回する）**：

1. **`hold`の平均着順が12.00から2着を超えて悪化**（＝プレイヤーの基準点を壊した）。
2. **逃げが決まるレースの割合が平坦で30%を超える**（現在20.0%。レースの形を壊した）。
3. **`attack−hold`がマイナスになる**（＝「常に仕掛けるのが正解」になり、§35で潰した
   「早駆けが常時最適解」の裏返しを再生産する）。

## 検証項目

1. **同乗の選出が決定論的**であること（同一シード・同一状況で2回呼んで同じ顔ぶれ）。
2. **同乗者が仕様どおりの条件で選ばれること**：エース・スプリンター（`sprintGap<8`）・
   `energy<42`・別集団の選手が**選ばれない**ことを合成データで直接確認する。
3. **最大2人**を超えないこと。候補0人なら単独（従来どおり）で例外を投げないこと。
4. **同乗者の`attackLeft`がプレイヤーと一致**すること（難易度easy/normal/oniの3つで確認
   ＝`finish.js`のスケール漏れが無いこと）。
5. **同乗者の`energy`が9減っている**こと。
6. `attack`以外の一手（`send`/`hold`/`conserve`等）では**同乗が起きない**こと。
7. 第46〜52弾の既存検証スクリプトが全て通ること。
8. `npx vite build`成功・Playwrightで`pageerror`ゼロ。

## Phase 2（実装後・Opus担当）

`w55_sweep_one.mjs`（`attack−hold`と`hold`）・`w55_breaktype.mjs`（レースの形）・
`w55_shape.mjs`（決着規模）で撤退基準3つと狙う値を判定する。

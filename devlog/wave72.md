## ⚠️訂正：古典由来のバッジは脚質で閉ざされていない

上の「発見1」で「SPRとTTは`pave_sp`等の取得経路から構造的に外れている」と書いたが、
⚠️**これは誤りだった**。`ACQUIRE_REQS`の`pave_sp`/`ardennes_sp`/`autumn_sp`に`gate`は無く、
全脚質が取得できる。しかもモニュメント月は候補1本なので、スプリンターでも必ず
石畳クラシックに出走する（地形的に不利ではあるが締め出されてはいない）。

正確な穴は次のとおり：

| 脚質 | 実際の状態 |
|---|---|
| **RUL** | ⚠️**専用コースが1つも無い＝機能的に壊れている** |
| SPR / TT | 古典が無いのは**味付けの非対称**。機能的な締め出しではない |

## ⚠️発見3：`segMixOf`が距離として誤った列を読んでいる

`segs`の要素は`[type, base, dist]`（`sim/course.js:19`の分解で確定）だが、
`domain/shared/segMix.js`は`s[1]`（＝`base`）を距離として使っている。実距離は`s[2]`。
`segMixOf`・`segMixOfRace`の両方に同じ誤り。

⚠️**なお`base`（`s[1]`）はsim側でどこからも読まれていない死んだ値**である
（`course.js`が`{type, base, dist}`として保持するが参照箇所なし。コース全長`LEN`も
`300 + rng*120`の乱数で、segsの数値とは無関係）。`dist`は区間の比率としてのみ効く。

## ⚠️発見4：地形分類されないコースがある

`terrainOfMix`（`core/core.js`）は閾値方式で、⚠️**flatだけ0.6・他は0.5**。
どれにも届かないと`null`を返し、そのレースは**どの地形バッジにも数えられない**。

- **グラベルレース**：flat 42.3% / hill 30.8% / climb 19.2% / sprint 7.7% → `null`

`core.js`のコメントは「実測で**全6テンプレート**が例外なく分類されることを確認済み」と
書いているが、⚠️**当時6種だったTEMPLATESの外（`UNLOCK_TEMPLATES`）は検証対象外**だった。
第70弾でそれらを常駐化したことで、未分類のコースが本編の抽選プールに入った。

## 確定した設計（ユーザー合意済み・2026-08）

ユーザー承認：「1→2→3の優先順で進める」。SPR/TTの古典（味付け）は今回は対象外。

### 1. RULの専用コース「平坦ロード」を新設

`data/course.js`の`TEMPLATES`**末尾**へ追加（⚠️既存の添字参照7箇所を動かさないため）：

```js
{ kind: "平坦ロード", favors: "RUL", squadMin: 1, squadMax: 5,
  segs: [["flat", 520, 30], ["flat", 480, 26], ["tt", 420, 18]] }
```

⚠️**最終区間を`tt`にするのが設計の核**。`sim/finish.js:70`により決着が
`solo*0.6 + flat*0.4`（独走決着）になり、SPR系コースの`sprint`決着
（`finish.js:71` = 純スプリント力）と明確に差別化される＝「平坦を高速で押し切る」
というルーラーの定義（`data/abilities.js`の`TYPES.RUL.tagline`）がそのまま形になる。
`tt`区間が集団レースで正常に動くことは確認済み（`sim/ticks.js:302`が終盤アタックの
対象区間に`tt`を明示的に含む／`sim/effects.js:155`が通常のsegTypeとして処理）。

地形分類：flat = (30+26)/74 = **75.7% ≥ 0.6** → `"flat"`（実測確認済み）。

### 2. `FAVORS_TO_DISCIPLINE`に`RUL: "flat"`を追加

`data/progression.js`。現在`{ SPR, CLM, PUN, TT }`の4つしか無くRULが欠落している。
これにより連動して直るもの：
- 第70弾の出走計画（シーズン・マイライフとも）が`"flat"`で機能するようになる
- `screens/mylife/create.jsx`の`focusOptions`（`TEMPLATES`に該当地形があるものだけを
  選択肢にする）に「平坦中心」が現れる
- `state/seasonState.js`の`seasonRaceFocus`がRUL主体ロースターで効くようになる

### 3. ラストレースのコース割り当てを`favors`検索方式へ

`controllers/mylife/raceStart.js:24`の`tmplByType`は`TEMPLATES[0]/[3]/[2]/[2]/[5]`の
ハードコード添字で、⚠️**RULとPUNが同じ`TEMPLATES[2]`（丘陵ロード）を共有**している。
つまり**ルーラーの引退記念レースがパンチャーのコースで行われる**。

```js
const tmplByType = Object.fromEntries(
  Object.keys(TYPES).map(t => [t, TEMPLATES.find(x => x.favors === t) || TEMPLATES[2]])
);
```

⚠️**実測で4脚質（SPR/CLM/PUN/TT）の割り当ては現行と完全に同一**、RULだけが
丘陵ロード→平坦ロードへ変わることを確認済み。添字ハードコードが今回の問題の元凶
なので、今後コースを足しても自動追従する形にする。

### 4. `terrainOfMix`に最大シェアのフォールバックを追加

`core/core.js`。閾値で決まらない場合、最大シェアの地形へ寄せる（`sprint`は`flat`へ畳む）。
既存の閾値判定を先に通すため、⚠️**現在分類できているコースの結果は一切変わらない**。

### 5. `segMixOf`のindex修正（4と同時に入れること）

`domain/shared/segMix.js`の`s[1]`→`s[2]`（`segMixOf`・`segMixOfRace`の両方）。

⚠️**4と5は必ず同時に入れる**——5を単独で入れると山岳クラシックが
`climb`46.0%・`flat`34.9%となり閾値を満たさず`null`に落ちる（＝退行）。
4のフォールバックがあれば`climb`のまま維持される（実測確認済み）。

### 既存セーブへの影響

⚠️`raceLog`に記録済みの`segMix`は作り直せないため、**過去のレースは古い（`base`由来の）
値のまま**残る。ただし上表のとおり12コース中11コースは新旧どちらの計算でも同じ地形に

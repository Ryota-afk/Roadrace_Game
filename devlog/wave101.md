# 第101弾：手触りの実地計測（観戦の196秒に何が起きているか）

## この弾の発端

第100弾で特定した2層のうち、**入口**は第100弾で手当てした（作品名・絵・選手作成・第一戦）。
残るもう1層が**手触り＝操作していて気持ちよくない**で、第100弾の観察3・5・6・7が該当する。
ここは設計に入る前に実測が要る（CLAUDE.md §10）。

## 方法

第100弾の実装を`npm run build`したものをローカルに立て、Playwrightで430×860の実機を
起動し、**デビュー戦を×1のまま最後まで走らせて**時間・判断回数・画面の中身を測った。
スクリプトは使い捨て（`scratchpad/race_timeline.mjs`・`race_camera.mjs`）。

## 実測1：デビュー戦は196秒かかる

第100弾で既定になった**日光グラベルレース**（1年目4月）を×1で完走させた実測：

| 項目 | 実測 |
|---|---|
| レース開始〜結果画面 | **196.6秒（3分16秒）** |
| 判断カード | **3回** |
| 中盤の判断 | 51.1秒（残り52%） |
| 逃げの選択（react） | 55.1秒（残り50%） |
| 勝負所の判断 | 72.2秒（残り38%） |
| **最後の判断からゴールまで** | **124秒（全体の63%）・判断ゼロ** |

⚠️**第100弾の「×1で約94秒」は誤りだったので訂正する。** あれは最初の15秒で
「残り84%」だったことからの外挿で、**実測の半分**しかない。外挿が外れた理由は下記。

## 実測2：時間の63%が終盤に集中している理由

`RaceView.jsx:307-311`。カメラが寄る（`span`が小さい）ほど再生を遅くする演出が入っている。

```
zoomT    = (0.20 - spanNow) / (0.20 - SPRINT_MIN_VIEW_FRAC)
zoomSlow = 1 - 0.76 * zoomT        // 最大 0.24倍速
clock   += dt * speed * slowFactor
```

最終区間では`span`が`SPRINT_MIN_VIEW_FRAC = 0.018`まで絞られるため、
⚠️**終盤は最大0.24倍速＝4.2倍の時間をかけて再生される**。
コース進捗で見ると、

| 区間 | コースの割合 | 実時間 |
|---|---|---|
| 序盤〜中盤 | 0→48% | 51秒 |
| 中盤 | 48→62% | 21秒 |
| **終盤** | **62→100%** | **124秒** |

⚠️**このゲームが最も長く・最も丁寧に見せている124秒は、判断が1つも無い区間である。**

## 実測3：走っている間、自分が何位かは画面に出ない

`RaceView.jsx:554`——HUDの順位表は`sorted.slice(0, 5)`＝⚠️**上位5名のみ**。
デビュー戦の着順は**35位／41人中**なので、⚠️**196秒のあいだ一度も順位表に載らない。**
画面の他のどこにも「あなたは何位」に相当する数字は無い（左の箱は地形・時計・残り%・
逃げとのギャップ、右の箱はTOP5）。

自分の居場所を知る手段は、俯瞰マップ上の水色のマーカー（`circle stroke="#27d3ff"`）を
40個近い重なったドットの中から目で探すことだけ。

## 実測4：既定カメラは「先頭集団」＝自分ではない

`RaceView.jsx:415-420`。既定の`camMode`は`"lead"`で、

```
leadGroup = framing.filter(r => leadF - r.frac <= LEAD_GROUP_FRAC)   // 0.06
```

⚠️**先頭から6%以内の選手だけを枠に収める。** さらに最終区間では`leadGid`の集団だけに
絞り込む（`RaceView.jsx:422-426`）。チップ行で自分に切り替えることは**できる**
（`playerRoster`に自分が入っている）が、⚠️**既定では選ばれておらず、初見はその存在を知らない。**

### 実測（`race_camera.mjs`）：⚠️終盤、プレイヤーは画面から消える

俯瞰マップ（viewBox `0 0 660 280`・実表示幅426px）の中に水色マーカー
（`circle[stroke="#27d3ff"]`＝「あなた」）が入っているかを約5秒間隔でサンプリングした
**別の走行（以下ラン B。ラン Aとは選手もレースも別の乱数）**の結果：

| 経過 | 残り | 自分が画面内か | 見えている選手ドット |
|---|---|---|---|
| 5.1〜71.6秒 | 94%→31% | ⚠️**17サンプルすべて true** | 42 |
| 76.7〜112.1秒 | 27%→3% | ⚠️**8サンプルすべて false** | 42 |
| 117.2秒〜 | 0% | 俯瞰マップ自体が消える（シネマティックへ） | 0 |

⚠️**コースの残り27%に入った時点で、プレイヤーは俯瞰マップの枠外へ出る。**
最終区間でカメラが`leadGid`だけに絞り込まれるためで、仕様どおりの挙動である。

⚠️**さらに、そのあとの最終直線シネマティックにも入らない。**
`RaceView.jsx:513`——シネマティックの母集団`contenders`は`cameraFramingRef`
（＝直前までカメラが映していた集団）から作られる。既に枠外にいる選手は母集団に入らない。

**実測（`race_cinematic.mjs`・ラン C）**：プレイヤー名を控えたうえでシネマティックに
到達し、パネル内の全テキストを照合した。

- プレイヤー＝**銀河 航平**
- シネマティック中のパネル表示＝「**単独ゴール — 最終直線**」「★高田」
  「単独ゴール — スロー再生」、順位表は「**1. 高田 皓 TOP**」の1行のみ
- ⚠️**`playerNameInPanel: false`＝プレイヤーの名前はどこにも出ない**

このランは逃げ切り（単独ゴール）だったため、⚠️**スロー再生で映されるのは他人1名**で、
しかも撮影した瞬間のパネルは通過後でほぼ真っ黒だった（`x101_cine1.png`）。

なお、42人が幅426pxのパネルに描かれ、集団の塊の横幅は実測137〜326px。
⚠️**1人あたり10px前後**で、名前タグが重なる（第100弾の観察6と一致）。

## 実測5：結果画面の「0と0」は第100弾のあとも残っている

第100弾で第一戦がチームTT→ロードレースに変わったが、⚠️**結果画面の構造は変わっていない**。

実測（日光グラベルレース・35位/41人中）：

- 見出しは**「フィニッシュ」**（無感情な語）
- **「この一戦の成果」の先頭2行が「獲得ポイント +0pt」「賞金 +0万円」**
- 3行目＝「事前予想41番手／実際は35位——**予想を上回る快走**」（good色）
- 6行目＝「世界ランキング21位／**初めてランキングに載った**」

⚠️**3分16秒かけて見せた末に最初に出る数字が、0と0。**
良い知らせは2つとも存在するのに、0の行より下に置かれている。

## まとめ：手触りの問題は「長さ」ではなく「誰の話か」

| 層 | 実測 |
|---|---|
| 時間 | 1戦196秒。最後の判断からゴールまで124秒（63%）は判断ゼロ |
| 主体 | 残り27%で俯瞰マップの枠外へ出る。順位表は上位5名のみ。最終直線シネマティックにも名前が出ない |
| 報酬 | 196秒の対価として最初に出る2行が「+0pt」「+0万円」 |

⚠️**デビュー戦の時系列（ラン A・B・Cの合成）**

```
0s ─────────────── 47〜72s ──────── 77s ─────── 117s ──────────── 196s
 │                 判断3回          │            │                 │
 │                                  │            │                 └ 結果「+0pt +0万円」
 │                                  │            └ シネマティック（他人の単独ゴール・スロー）
 │                                  └ 自分が俯瞰マップの枠外へ
 └ レース開始
```

⚠️**「レースが長い」のではなく、「長い時間をかけて、自分が出ていない他人のレースを
見せている」**というのが実測から見える形である。速度切替（×0.5〜×8）とスキップが
用意されていることは、第100弾で書いたとおり設計側の自認だが、⚠️**スキップすると
判断カードも発火しない**（`RaceView.jsx:343`の`!skipRef.current`）ため、
プレイヤーの選択肢は「196秒見る」か「唯一の対話要素を捨てる」の二択になっている。

## 副産物1：⚠️第100弾の「約180レース」は計測値ではない

第100弾に「キャリア15年＝約180レース」と書いたが、これは12ヶ月×15年をそのまま
レース数と見なした上限であって実測ではない。月次の選択は
「レースに出る／練習／休養／ピーキング」の4択なので、実際の出走数はこれより少ない。
なお`tools/_shared.mjs`の実測メモでは、⚠️生成される**候補**は新人1年目/B1で年28レース
（TT除く）。⚠️**キャリア総時間（「4.5時間」「約10時間」等）は現時点では断定しないこと。**
必要なら`tools/simcareer.mjs`で出走数を測ってから書く（本弾では600秒の上限に達し未取得）。

## 副産物2：⚠️レース画面に絵文字が残っている（§8の取りこぼし）

`components/race/FinalSprintCinematic.jsx:52-54`の`riderTagIcon()`が
**🚴（自分）／🔥（ライバル）／🏛（殿堂選手）／★（自チームエース）**を返しており、
`RiderNameTag`経由で⚠️**シネマティックだけでなく俯瞰マップ・側面マップのタグにも出ている**
（実測したHUDテキストに`🚴朔`・`★岡`が含まれる）。

第13弾で653個の絵文字を撤去した際の取りこぼし。⚠️しかも**「自分」の識別をよりによって
絵文字に依存している**——CLAUDE.md §8が名指しする「絵柄で区別・強調するのは、レイアウト・
級数・余白・整列で階層を作る仕事の放棄」そのものの形になっている。
第101弾で「自分を主役にする」に着手するなら、ここは同じ弾の中で扱うのが筋。

# 方向A「自分を主役にする」— 候補提示（§8 手順1）

方向Aは独立した3つの変更からなる。

| # | 変更 | 性質 |
|---|---|---|
| A-1 | 既定カメラを「先頭集団」から**自分**にする | 挙動（`camMode`の初期値） |
| A-2 | **走行中に自分の順位を出す** | ⚠️新しいUI要素＝§8の候補提示が要る |
| A-3 | シネマティックの母集団に自分を必ず含める | 挙動（`contenders`の作り方） |
| A-4 | 選手タグの絵文字（🚴🔥🏛）を撤去する | §8違反の是正（副産物2） |

A-1・A-3・A-4は「新しい見せ方を選ぶ」話ではないので候補提示は不要。
A-2だけがUIの新設なので候補を作った（`scratchpad/build_mock101.mjs`→`mock101.html`）。

## A-2 の候補4案

実データは1年目4月・日光グラベルレース・残り54%の実測そのまま
（プレイヤー＝朔 迅、出走42名、TOP5と着差、集団構成、実況文）。

| 案 | 置き場所 | 長所 | 短所 |
|---|---|---|---|
| 1 | 順位表の下に「あなた」行 | 新しい要素をゼロ個しか増やさない。最も安い | 上位5名と同じ級数＝探せば分かる程度 |
| 2 | 左の箱に28pxで大きく | 画面内で最大の数字が自分の順位になる＝主役が変わる | 左の箱が縦に伸び、マップが下がる |
| 3 | マップ直上に専用の帯 | **居場所（どの集団にいるか）まで言葉で出せる**のはこの案だけ | 要素が1つ増える |
| 4 | 順位表を自分中心に組み替え | 「誰を抜けば1つ上がるか」が分かる | TOP5が3名に減る |

⚠️**順位の値そのものは現行コードが算出していない。** 実装では
`sorted`（fracの降順）の`index + 1`と、TOP5と同じ`paceFracPerSec`換算の秒差で出す。
モックの「22位／+0:31」は、実測の集団構成（独走1・追走2・ペロトン36）と整合する
位置に取った例示値。

## 決定（ユーザー選択）：**案3 ＝ マップ直上に自分専用の帯**

# 実装仕様（合意済み・Sonnetが実行する）

## 実装1 A-1：既定カメラを自分にする — `RaceView.jsx:62-65`

```js
const [camMode, setCamMode] = useState("lead");
const camModeRef = useRef("lead");
```

を、`isPlayerChar`を持つ選手が居るときだけその選手のidで初期化する形に変える
（遅延初期化）。**`camModeRef`の初期値を`useState`と必ず揃えること**——片方だけ
`"lead"`のまま残すと、最初のtickでカメラだけ先頭集団を映す不整合が出る。

- シーズンモードは`isPlayerChar`を持たないため自動的に`"lead"`のまま＝⚠️**挙動は変わらない**。
- `sim`が変わったとき（次のレース）も初期化し直す。再マウント前提に依存しないこと。

**この1箇所で副次的に直るもの（新しいコードを足さずに直る）**

1. 最終区間の`leadGid`絞り込み（`RaceView.jsx:422`）は`camMode === "lead"`のときだけ
   発動するため、⚠️**残り27%で画面外に出る問題が消える**。
2. シネマティックの母集団は`cameraFramingRef`（直前のカメラ枠）から作られるため、
   ⚠️**プレイヤーの集団が映るようになる**。

## 実装2 A-2：「あなた」の帯（案3）

### 2-a 集団ラベルを純関数へ抽出（§5：重複定義を作らない）

集団ラベル（独走／逃げ集団／追走集団／ペロトン／遅れた集団）は現在
`RaceView.jsx:761-780`のJSXの中で算出されている。帯からも同じラベルが要るので、
**先に純関数へ出す**。新規`src/domain/shared/raceGroups.js`（JSXをimportしない＝
Node単体テスト可能）。

- ラベル規則は現行と**完全に同一**にする（`pelotonN`＝最大人数、`i===0`かつ`n===1`は独走、…）。
- `RaceView.jsx`の該当JSXはこの関数を呼ぶ形に置き換える。⚠️**表示は1ピクセルも変えない**。

### 2-b 帯に出す値（すべて同じtick内の既存の値から作る）

| 値 | 作り方 |
|---|---|
| `myRank` | `sorted.findIndex(r => isAvatar(r.e)) + 1`（`sorted`は`RaceView.jsx:548`のfrac降順） |
| `myGap` | `(leadFracNow - 自分のfrac) / Math.max(1e-6, paceFracPerSec)`（TOP5と同じ換算） |
| `myField` | `riders.length` |
| `myGroup` | `raceGroups(riders)`から自分の`gid`の集団のラベル |
| `myDone` | `rt >= 自分のfinishTime` |

### 2-c 見た目

配置は**ChipRowの直後・マップ（`{cinematic ? ... : (...)}`）の直前**に1本。
地は`T.color.surface`、padding `T.space.sm` × `T.space.md`、`marginTop: T.space.sm`。

| 位置 | 内容 | トークン |
|---|---|---|
| 左 | `あなた` | `T.size.caption` / `T.color.sub` |
| 左 | `22位` | `T.size.head` / `T.color.accent` |
| 左 | `/ 42人` | `T.size.caption` / `T.color.sub` |
| 右 | `先頭と +0:31　ペロトン内` | `T.size.caption` / `T.color.sub` |

- 秒差は既存の`fmtGap()`をそのまま使う（新しい書式を作らない）。
- 「〜内」の付け方：⚠️**`独走`のときだけ`独走中`**（「独走内」は日本語として誤り）。
  他は`ペロトン内`・`逃げ集団内`・`追走集団内`・`遅れた集団内`。

**空状態（1件ずつ確定させる）**

| 条件 | 帯の表示 |
|---|---|
| `!hasAvatar`（シーズンモード） | ⚠️**帯そのものを出さない** |
| 集団が1つしか無い（`groups.length < 2`） | 右側は`先頭と +0:31`のみ（居場所を書かない） |
| 自分が先頭（`myRank === 1`） | 右側は`先頭　ペロトン内`（`+0:00`とは書かない） |
| 自分がゴール済み（`myDone`） | `あなた　35位　/ 42人`＋右側は`ゴール`のみ |

# 実装（Sonnet・進行中）

`src/domain/shared/raceGroups.js`（新設）に集団ラベル算出を抽出し、`RaceView.jsx`の
俯瞰マップと新設の「あなた」帯の両方がこれを共有する形にした（§5：重複定義を作らない）。

- **A-1（既定カメラ）**：実装・検証済み。`camModeRef`/`camMode`の初期値を、
  `isPlayerChar`を持つ選手が居ればそのidに変更。実測（`race_camera.mjs`再実行）で
  残り95%〜2%まで29サンプル連続で「画面内」——第101弾で確認した「残り27%で画面外に
  出る」不具合が完全に解消したことを確認した。
- **A-2（案3の帯）**：実装済み。順位表と同じ300ms周期の`sorted`/`paceFracPerSec`から
  `myRank`/`myGap`/`myField`/`myDone`/`myGroupLabel`を算出し`hud`state経由で描画。
  空状態（シーズンモード非表示・集団1つなら居場所を書かない・先頭なら「+0:00」と
  書かない・ゴール済みなら「ゴール」のみ）を実装。実機で「あなた 12位 / 40人 先頭と

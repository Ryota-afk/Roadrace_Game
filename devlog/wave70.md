# 第70弾：クリアポイント(CP)経済の全体診断

**状態**：**診断完了・設計方針の合意待ち（2026-08）。実装未着手。**

DEVLOG TODO #15（クリアポイント解禁の再設計）に着手。当初はコース解禁だけを直す想定だったが、
ユーザー判断で**CP経済全体を先に見直す**方針になった。以下はその実測結果。

## CPの4つのチャンネル

| チャンネル | 件数 | 方式 | 判定 | 最終段 |
|---|---|---|---|---|
| コース解禁（`UNLOCK_TEMPLATES`） | 3 | 自動 | `totalEarnedCP` | 45 CP |
| シーズン開幕（`CP_MILESTONES`） | 16 | 自動 | `totalEarnedCP` | 400 CP |
| マイライフ特典（`ML_CP_MILESTONES`） | 9 | 自動 | `totalEarnedCP` | 330 CP |
| CPショップ（`CP_SHOP`） | 18 | **購入** | 残高 | 全買い 1,070 CP |

⚠️自動系は`totalEarnedCP`（累計獲得）で判定するため**買っても減らない**。残高を消費するのは
ショップだけ。この二重構造自体は妥当だが、後述のとおり中身が重複している。

## ⚠️発見1：モード間でCP獲得が最大8倍違う

```
シーズン1周   : 14〜42 CP   （computeClearPoints = 5 + 速度ボーナス最大15 + 難易度最大22）
マイライフ1周 : 12〜350 CP  （computeMyLifeClearPoints）
```

| マイライフのキャリア内容 | 獲得CP |
|---|---|
| ほぼ未達（数勝のみ） | 12 |
| そこそこ（中堅で終える） | 38 |
| 成功（世界トップ10） | 87 |
| 完全制覇（世界1位・normal） | 159 |
| **完全制覇・oni** | **350** |

⚠️**oni完全制覇のマイライフ1回 ＝ oni2年クリアのシーズン8.3回分。**
共有通貨でありながら、⚠️**シーズンでCPを貯めるのは実質的に成立していない**。
ショップ全買い1,070CPをシーズンだけで賄うと、oni2年クリアを**26周**必要とする。

## ⚠️発見2：貯めきるとシーズンモードが始まった時点で終わる

累計400CP（自動系の最終段）＋ショップ全買いで、シーズン開幕時に乗る総量：

| | 初期値 | CP適用後 |
|---|---|---|
| ロースター能力 | 平均 **58.4**（min34/max82） | ⚠️**全員94**（+62されクランプ上限に張り付く） |
| 開幕資金 | 300万円 | **4,700万円**（15.7倍） |
| ロースター人数 | 6名 | **12名**（逸材6名追加＝B1上限`ROSTER_MAX_BY_CLASS[0]=12`にちょうど到達） |
| 設備Lv | 0 | 3（上限） |

⚠️**初期平均58.4の選手が全員94で開幕する**＝育成の余地も経営判断も消える。
CPを貯めるほどシーズンモードが成立しなくなる構造になっている。

## ⚠️発見3：与えているのに黙って捨てている（設備Lv）

CP側は設備Lvを合計 **+14** 与えるが、`bumpEquipLv`は`Math.min(3, ...)`でクランプする
（B1の`equipMax = 3 + classIdx = 3`）。⚠️**11段ぶんが無言で捨てられる。**

対象は`CP_MILESTONES`の4件（Lv1/Lv2/Lv2/Lv3）と`CP_SHOP`の2件
（`s_equip` 55CP／`s_equip2` 95CP＝**計150CPぶんの購入がほぼ無効**）。
⚠️**プレイヤーは150CPを払って何も得ていない可能性がある。**

## ⚠️発見4：チャンネル間で効果が重複している

ショップ18件のうち、ミルストーンと**同じ効果を買い直しているだけ**のものが多い。

| 効果 | ミルストーン | ショップ | 実質 |
|---|---|---|---|
| 開幕資金 | 5件 | 2件 | 同じ |
| 能力底上げ | 4件 | 2件 | 同じ |
| 設備Lv | 4件 | 2件 | 同じ（しかも上限で死ぬ） |
| 逸材新人 | 5件 | 2件 | 同じ |
| デビュー特能運 | 2件 | 2件 | 同じ |

⚠️**ショップ18件のうち、ミルストーンに無い"新しい軸"は4件だけ**：
`s_staffmax`（スタッフ枠+1）・`s_rostermax`（所属枠+2）・`m_partlvmax`（パーツ上限+2）・
`s_salarydiscount`（年俸-10%）。いずれも第12弾で後から足されたもの。

## ⚠️発見5：43件中39件が「開幕ブースト」＝受動的

CP由来の要素は全43件（自動25＋購入18）。このうち**プレイ中の判断に関わるのは
上記の恒久上限拡張4件だけ**で、残り39件はすべて「開始時点で強くなる」。

⚠️**ユーザーの「受動的」という指摘は、コース解禁だけでなくCP全体に当てはまる。**
CPは「次の周をどう始めるか」しか変えず、「今の周をどう戦うか」を一切変えない。

## ⚠️発見6：コース解禁（当初の対象・第70弾着手時の測定）

| | プール | 特定コースが1枠に出る確率 |
|---|---|---|
| 解禁前 | 6種 | 16.7% |
| 全解禁後 | 9種 | **11.1%** |

⚠️**解禁するほど狙ったコースが出にくくなる**（報酬が罰として働いている）。
さらに3種のうち2種は既存コースと脚質が重複する：

| 解禁コース | favors | 重複相手 |
|---|---|---|
| ナイトクリテリウム | SPR | クリテリウム・サーキットレース |
| グラベルレース | PUN | 丘陵ロード |
| チームTT | TT | ⚠️これだけ別物（`squadMin:4`＝層の厚さを要求・専用エンジン） |

CP45で枯れるため、normalなら**2周で全解禁**され、以後この経路は永久に死ぬ。

## 設計上の着眼点（バッジとの接続）

`ACQUIRE_REQS`には**地形依存のバッジが8種**ある
（`rouleur`平坦10回／`allclimber`登坂10回／`grinder`丘陵10回／`diesel`独走3回／
`sponge`全地形3回ずつ／`climbengine`／`kicker`／`allrounder_sp`）。

つまり⚠️**「どの地形を走れるか」がバッジ獲得＝個性づくりを直接左右する**のに、
カレンダーはRNGである。

- マイライフ：`raceFocus`（出走計画）で3候補のうち1本を宣言地形に寄せられる（第43弾）
- シーズン：⚠️**介入手段が一切ない**（毎月3〜5本を完全ランダム抽選・出走可能は2〜4本）

「バッジで個性を出す」という方向転換（DEVLOG）と、CPが持つべき役割はここで接続できる。

## 確定した設計（ユーザー合意済み・2026-08）

ユーザー判断：**CPの役割を「今の周の選択肢」へ移す**／**開幕ブーストは難易度で切り替える**。

### 中核の原則：CPを「強さ」と「選択肢」に分ける

| 種別 | 中身 | 難易度による変化 |
|---|---|---|
| **強さ** | 開幕資金・能力底上げ・逸材新人・アイテム・設備Lv | ⚠️**難易度で効き方が変わる** |
| **選択肢** | 出走計画・恒常上限の拡張・情報の解禁 | ⚠️**難易度に関わらず常に効く** |

```
CP_BOOST_DIFF_MUL = { easy: 1.0, normal: 1.0, hard: 0.5, oni: 0 }
```

⚠️**既存の獲得側`MLCP_DIFF_MUL = { easy:0.7, normal:1.0, hard:1.5, oni:2.2 }`と対になる。**

- **easy**：稼ぎ0.7倍・ブースト1.0倍 → 楽に周回したい人の道
- **oni**：稼ぎ2.2倍・ブースト**0倍** → 実力で挑み、稼いだCPは「選択肢」に注ぐ

⚠️これにより**「鬼で稼いだCPは、鬼を楽にするためではなく、選択肢を増やすために使う」**という筋が通る。
現行の「貯めるほどシーズンが始まった時点で終わる」構造（発見2）が、高難易度側から順に解消される。

### 新設する項目（選択肢・難易度不問）

| id | モード | 効果 | 実装フック |
|---|---|---|---|
| `s_plan1` | シーズン | 毎月、出走可能なレース1本が宣言地形になる | `genMonthRaces()`に`focus`引数を追加 |
| `s_plan2` | シーズン | 上記が2本になる | 同上 |
| `m_plan2` | マイライフ | 3候補中の宣言地形枠が1→2本 | `mlGenRaceCandidates`のfocus適用枠 |
| `m_growthreveal` | マイライフ | 成長力が1年目から判明（現行3年目） | `mlGrowthPowRevealed()`（`year>=3`を返すだけの関数） |

⚠️**両モードで正当化の理由が異なる（設計判断として明記）**：
- **マイライフ**＝地形依存バッジ8種の取得がRNG任せなのを選択に変える（「バッジで個性を出す」に直結）
- **シーズン**＝バッジは自動習得のまま据え置き（第39弾の決定）なので、
  **ロースターの脚質に合わせてレースを引き寄せる経営判断**が理由

⚠️**バッジ枠+1は入れない**——DEVLOG「バッジ所持上限の撤廃はやらない（上限こそが個性の源）」に抵触する。

### 廃止・整理

| 対象 | 措置 |
|---|---|
| コース解禁3件 | ⚠️**廃止**。3種を`TEMPLATES`へ統合して常駐化＝希釈（発見6）と脚質重複が同時に消える |
| `s_equip`(55)・`s_equip2`(95) | ⚠️**削除**。`bumpEquipLv`のクランプで死んでいる（発見3）。購入者へ**150CP返金** |
| `CP_MILESTONES`の設備Lv 4段 | 同上の理由で削除または別効果へ差し替え |

### 移行（マイグレーション）

⚠️`cpUnlocks`はlocalStorageに残る。削除する項目のcostを`cpSpent`から差し引いて**返金**する
移行処理を1度だけ走らせる（既存の`resetCpProgress`とは別系統）。

### 残るリスク

⚠️**出走計画は地形バッジの取得速度を上げる。** これは狙いどおりだが、
**どの程度速くなるかは実測しないと分からない**。実装後にバッジ取得までの平均月数を計測すること。

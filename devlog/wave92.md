**状態**：**設計。実装は未着手**（§2によりSonnetへ引き継ぐ）。

## 背景：3つの症状は1つの構造から出ている

第89〜91弾で表面化した問題を並べると、いずれも同じ原因に行き着く。

| 症状 | 実際に起きたこと |
|---|---|
| 計測に30分かかる | 自動プレイ1本＝4,000ステップ×0.45秒。第90・91弾で2回流して約1時間 |
| ⚠️**計測が誤った結論を出す** | 第89弾は「資金が余る」と結論→第90弾で撤回。シンクを使わない1本だけを見ていた |
| ⚠️**同じ形のバグが3回再発** | 第83・85・90弾：同じ値が複数箇所にあり片方だけ直す。⚠️**そのたびDEVLOGへ教訓を書いて3回とも再発** |

原因は**バランスの計測をUI経由でしか行えないこと**である。ゲームのロジックは純粋関数として
`src/`に分離済みなのに、数値の計測をChromiumのクリック操作で代用している。その結果、
計測が高価（30分）になり、高価だから1本しか回さず（n=1）、UIの都合で壊れ、そして
⚠️**CLAUDE.md §10「機能追加のたびに測れ」が守れなくなっている**（第70・87弾で実際に飛ばされた）。

⚠️**ルールを増やしても直らない。守ろうとしている対象が道具の都合で守れない構造になっている。**

## 設計

### 全体像

`tools/simcareer.mjs` を新設する。reducerを直接呼んでキャリアを回し、統計を出す。

```sh
node tools/simcareer.mjs --careers 100 --seed 1 --policy spender --out /tmp/sim
```

⚠️**既存の`tools/autoplay.mjs`は消さない。** 役割を分ける：

| | 対象 | 所要 |
|---|---|---|
| `tools/simcareer.mjs`（新） | ⚠️**数値・バランス**（人気度・資金・年俸・成長） | 100キャリアで約3分 |
| `tools/autoplay.mjs`（既存） | ⚠️**UIが壊れていないか**（画面遷移・pageerror） | 1本30分 |

### 1. 画面ディスパッチ表（中核）

ゲームは`state = reducer(state, args)`の形に揃っている（`hooks/useMyLifeGame.js`は
`setMl(s => reducer(s, ...))`の薄いラッパーでしかない）。よって`state.screen`を見て
対応するreducerを呼ぶ表を作れば、UIなしでキャリアが進む。

`src/`をgrepして確定した遷移先の画面は以下（`mylife_`接頭辞は省略）：

| screen | 呼ぶもの | 備考 |
|---|---|---|
| `create` | `mlCreateChar(s, type, bg, master, partner, cpMeta)` | `domain/mylife/createChar.js` |
| `scout` | 確認して`main`へ | `createChar.js:308`が遷移先 |
| `badge_goals` | `mlConfirmBadgeGoals` / `mlSetRaceFocus` | 目標バッジと注力レースの選択 |
| `main` | ⚠️**方策が決める**（下記2） | 月の行動 or レース出走 |
| `startlist` | `race`へ進む | 出走表の確認だけ |
| `race` | `mlRaceFinish` | ⚠️**simは構築済み・演出は不要** |
| `result` / `event_result` / `newspaper` | `main`へ戻す | 表示のみ |
| `event` | `mlApplyEventEffects(s, choiceIdx)` | `controllers/mylife/event.js` |
| `protege_event` | `mlResolveProtegeEvent(s, choiceIdx)` | |
| `contract` | `mlChooseTeam(s, offer)` | 移籍先の選択 |
| `retire_advice` | `mlRetireAdviceContinue` / `ReduceRole` / `Accept` | ⚠️方策で分岐 |
| `offseason` | `mlResolveOffseason(s, choiceIdx)` | |
| `offseason_result` | `mlContinueAfterOffseason` | |
| `crossroads` | `mlResolveCrossroads(s, choiceIdx)` | |
| `crossroads_result` | `mlContinueAfterCrossroads` | |
| `retired` | 終了 | キャリア終了 |

⚠️**表に無いscreenが来たら黙って読み飛ばさず、その場で異常終了させること。**
第89弾のハーネスは「押せるボタンが無ければ待つ」という寛容な作りだったため、
⚠️**シーズンモードへ迷い込んだまま計測を続けた**。⚠️**寛容さは誤った計測を生む。**

⚠️**実測で判明済みの関門**：`mlAdvanceMonth`を60回連続で呼んでも1年目12ヶ月で止まる。
年度末は`pendingOffseason`／`pendingAdvice`を積んで`screen`を切り替えるため、
⚠️**オフシーズン系のreducerを通さないと2年目に進まない**（`month.js:417-419`）。
月送りだけのループでは1年しか測れない。

### 2. 方策（policy）＝仮想プレイヤーの行動方針

⚠️**第89弾の誤りは「方策を1つしか用意しなかったこと」だった。** シンクを使わない
プレイヤーだけを測り、その結果を全体の結論として書いた。⚠️**方策は差し替え可能にし、
最低2つを常に両方回して両方報告する。**

| 方策 | 内容 | 何を代表するか |
|---|---|---|
| `frugal` | 資金を一切使わない。月の行動は練習のみ | 資金の**上振れ**側＝溜め込むプレイヤー |
| `spender` | 押せる中で常に最大額を使う（ワンオフ機材・科学トレーニング） | 資金の**下振れ**側＝使い切るプレイヤー |

⚠️**両者の差がそのまま「プレイヤーの選択の幅」であり、それが無ければシンクは
機能していない**（第90弾で確認した「7,507万 vs 55万」がまさにこれ）。
将来`balanced`（中庸）を足す余地は残すが、初版は2つでよい。

方策のインタフェースは1つだけ：

```js
// state を受け取り、「今どのreducerをどの引数で呼ぶか」を返す
policy.decide(state) -> { action: "advanceMonth", args: ["train_flat"] }
```

### 4. 不変条件アサーション（再発防止の本体）

⚠️**これが「散文の教訓」を「機械の検査」に置き換える部分**である。
毎月、以下を検査し、破れたら**その場でキャリアを止めて年月と値を報告する**。

| # | 不変条件 | 破れていた実績 |
|---|---|---|
| A1 | `salary <= ML_SALARY_CAP[classIdx]` | ⚠️**在籍月の51.4%で破れていた**（第90弾③） |
| A2 | `0 <= popularity <= 100` かつ⚠️**100に張り付いた月が全体の5%未満** | ⚠️**45.7%だった**（第90弾①） |
| A3 | `money` が負のまま12ヶ月以上続かない | 第90弾で「破産経路が成立しないか要確認」として持ち越した項目 |
| A4 | 成長キャップ超過（`overall`が`mlGrowthCapFor`を超えない） | 第33・36弾の「早期カンスト」系 |

⚠️**A2のような「statistical な不変条件」を混ぜるのが要点。** 単なる範囲チェック
（0〜100に収まっているか）では第90弾のバグは検出できなかった——⚠️**値は常に
正当な範囲内で、ただ100に張り付いていただけ**だからである。

### 5. 出力

`--out`ディレクトリへ2つ書く。

- `summary.md`：方策×年次の表（人気度・資金・年俸・クラス・世界ランクの中央値と四分位）。
  ⚠️**DEVLOGへそのまま貼れる体裁にする**（毎回手で表を組み直しているのが地味に高い）
- `violations.txt`：アサーション違反の一覧（キャリアID・年月・値）。⚠️**0件ならその旨を明記**
  （§10「動かなかったことも書く」）

**空状態**：違反0件・キャリア0本完走などの場合も、⚠️**空ファイルではなく「0件」と
明示的に書く**。ファイルが無い／空なのは「実行されなかった」と区別がつかない。

# 第23弾：拠点マップの重なり順・導線の総点検＋散歩先拡充＋セリフ大量追加

**背景**：2026-08にユーザーから12項目の不具合・要望の一括報告。調査の結果、見た目の症状は
バラバラだが根本原因は3系統に集約されることが分かった。

- **A. 描画順（painter's sort）が「1点のy座標」しか見ていない**：大きな設置物（建物・ジム・
  チームカー・ラック）は画面上で広がりを持つのに、ソートキーはアンカー1点のy。アンカーより
  手前/奥にいる選手との前後関係が壊れる。
- **B. 屋外ルートが建物footprintと交差しても検証されていなかった**：第21弾の検証器は
  「小物との点クリアランス」「コース横断回数」だけを見ており、**建物の矩形との交差**を
  見ていなかった。前庭ベンチへのルート(w=5.1)は建物(w:5〜14)の内側を通っている。
- **C. データの表現力不足**：ベンチの「座る向き」を屋内椅子用の反転規則(`!chairFlip`)で
  流用している／木の影が汎用の自動オフセット式で幹とずれる／セリフが第21弾から未拡充。

## 2. 前面帯ルールの実装

`BaseView.jsx`のdrawOrder構築で：
```js
const FRONT_L = BASE_VIEW_CLUBHOUSE.l - BASE_VIEW_CLUBHOUSE.hl; // -4.5
const FRONT_W = BASE_VIEW_CLUBHOUSE.w + BASE_VIEW_CLUBHOUSE.hw; // 14
const inFront = (w, l) => l < FRONT_L - 0.05 || w > FRONT_W + 0.05;
sortY = inFront(item.w, item.l) ? CLUBHOUSE_SORT_Y + 1 + rawY * 1e-3 : rawY;
```
- `propItems`の各要素にw/lを持たせる（現在はsortY+nodeのみ）。選手は`act.w/act.l`。
- 変換は単調（前面帯内の相互順序はそのまま）。前面帯の要素より南に「建物の奥側」要素は
  存在し得ない（敷地はw≤16でy最大736<840.5）ので破綻しない。
- 建物の裏（w<5・l>5.5）の要素は従来どおり素のyで建物より先＝奥に描かれる。

# 第51弾（設計確定）: バッジ段階で「判断の機会」が変わる

## 発端：能力値をいくら盛っても効かないことが実測で判明した

第49〜50弾の実測で、レースの構造がこうなっていると分かった。

- プレイヤーは**99.0〜99.1%のtickで集団に残る**（千切れ閾値までratio中央値1.20の余裕）
- `ticks.js:290`で**プレイヤーは自発的アタックの対象から明示的に除外**されている
- 集団にいる間は`dist = groupDist`＝**全員同速。自分の能力は完全に捨てられる**
- 能力が効くのは最終区間と、第50弾で直した決着の並べ替えだけ
- 決着への合流は`FINISH_BADGE_K=2`で**飽和**（K=2/3/4が1桁まで同一値）

⚠️つまり**倍率をどこまで上げても頭打ち**で、「バッジで個性を出す」を数値で達成する道は塞がっている。
ユーザーの提案**「バッジ持ちは判断場面が追加されるとかさ」**を受け、
**強さではなく“選べる回数”をバッジの報酬にする**方向へ切り替える。

## 確定仕様

### 1. 基本の判断回数を減らす（⚠️バッジ無しは今より減る）

現在の基本スロットは`mid`／`finale`／`react`（状況発火）／`sprint`の4枚で、**全員一律**。
これを減らし、増える分をバッジ由来にする。

| | 判断回数 |
|---|---|
| 現状（全員一律） | 3〜4回 |
| **改定：バッジ無し** | **2回**（`mid`＋`finale`。`react`は従来どおり状況発火のみ） |
| 地形バッジ 銅〜金 | 3回 |
| 地形バッジ 虹 | 4回 |

- `sprint`スロットは基本から外し、**スプリント系バッジ保持者だけ**に出す
  （`sprinter_sp`／`kicker`／`finisher`／`closer`のいずれかを所持）。
- ⚠️**バッジ無しのプレイヤーは判断機会が3〜4回→2回に減る**。体験の後退だが、
  「バッジを育てると走りの選択肢が増える」という育成の実感と引き換えに**意図的に受け入れる**
  （ユーザー合意済み）。

### 2. 得意地形の専用カードを新設する

自分のバッジが効く地形の区間に入った瞬間に発火する。

| 地形 | 対象バッジ | カードの見出し |
|---|---|---|
| climb / mtn | 山の申し子・岳人・山の吸血鬼 | 「登りに入った」 |
| hill | 丘陵ハンター・岳人 | 「丘に入った」 |
| flat | 平坦の職人・鉄脚の巡航機関 | 「平坦に入った」 |
| tt | 独走の求道者 | 「独走区間に入った」 |

- 補足文はいずれも「自分の得意地形——ここでどう動く？」。
- **回数の上限**：所持している地形バッジのうち**最も高い段階**で決まる。
  銅・銀・金＝**1回**／虹＝**2回**。複数の地形バッジを持っていても合計はこの上限まで。
- 発火する区間は、コースの先頭から見て条件に合う区間のうち上限数まで。
- ⚠️**シーズンモード（監督視点＝`ctx.manager`）では出さない**。監督は選手本人ではないため。
- カードのidは区間インデックス込みで一意にする（`terrain-<segIdx>`）。`firedRef`が
  id単位で1回しか発火させないため、同じ区間で二重に出ることはない。

### 3. 専用カードだけの新しい一手「ふるいにかける」

⚠️`RACE_MOVES`のコメントには**「専用ムーブを増やさず必勝ボタン化を避ける」**という既存の
設計方針が明記されている。これと衝突しないよう、**自分が速くなる一手ではなく、
集団を小さくする一手**にする。

第49弾の実測で「誰も千切れないため決着が常に大集団」と分かっており、この一手はその
構造に直接効く。集団が小さくなれば、第50弾で決着に合流させたバッジのボーナスが効く場面が生まれる。

```
tempo（表示名「ふるいにかける」）
  効果：発動中、同じ集団の他の選手の「ついていく判定」(keepThresh)を厳しくする
  代償：自分が大きく脚を使う（発動時に energy を消費）
  持続：残脚に比例（脚が売り切れていれば短く、moveEdge上は「不発」表示になる）
```

- 実装位置：`ticks.js`の集団ループで、`members`の中に`tempoLeft > 0`の選手がいて
  かつ現在の区間がその選手の地形バッジの対象なら、**その選手以外**のkeepThreshに
  `TEMPO_KEEP_TIGHTEN`を上乗せする。`course.selective`（既存の`selectiveTight = 0.035`）が
  同種の仕組みを持っているのでそれに倣う。
- `moveEdge`分類：`STEADY_MOVES`（金＝手堅い）に追加し、`LEGS_SCALED_MOVES`にも追加する
  （脚が無ければ不発表示。既存の「脚が無ければ一手は決まらない」原則に揃える）。

**初期値（⚠️すべて実装後に実測して確定する仮置き）**

| 定数 | 仮置き | 根拠 |
|---|---|---|
| `TEMPO_KEEP_TIGHTEN` | 0.06 | `selectiveTight`0.035と`grinder`の緩和0.04〜0.06の間 |
| `TEMPO_ENERGY_COST` | 14 | `attack`の9と`send`の17の中間 |
| `TEMPO_MIN_TICKS` / `TEMPO_MAX_TICKS` | 40 / 110 | `attack`の持続レンジに準拠 |

### 4. 専用カードの選択肢（3択）

| 表示 | move | 説明文 |
|---|---|---|
| ふるいにかける | `tempo`（新設） | ペースを上げて後続を千切る。脚を大きく使う |
| 仕掛ける | `attack` | 単独で飛び出す。決まれば独走、脚を使い切れば失速も |
| 流れに任せる | `hold` | 展開に乗って様子を見る |

⚠️虹は同じカードが2回出る。選択肢は同じだが、**2回目は脚が減っている**ため
「どちらの区間で脚を使うか」という配分の判断になる（モック`wave51_mock.html`で確認済み）。

## ⚠️バランス上の危険（実装後に必ず実測する）

集団を削ると決着クラスタが小さくなり、**第50弾の決着ボーナスと二重に効く**。
強くなりすぎる可能性が実在するため、実装後に以下を測る。

1. `tempo`使用時／不使用時の勝率差（同一シード・3点固定＝`Math.random`／`Date.now`／
   `ridState.value`。`devlog/wave49.md`参照——固定しないと数字はすべて無意味になる）
2. `tempo`1回で実際に何人が千切れるか（削れすぎていないか）
3. `TEMPO_KEEP_TIGHTEN`を0.03/0.06/0.10で振って応答曲線を出す
4. 脚の消費が「使ったら決着で不利」として機能しているか（使用後の着順分布）

## 検証項目

1. バッジ無しの選手で判断カードが**2回**（`mid`＋`finale`）になること。`react`は従来どおり
   状況発火すること。
2. スプリント系バッジ非保持者に`sprint`カードが**出ない**こと、保持者には出ること。
3. 地形バッジ銅／銀／金で専用カードが**1回**、虹で**2回**出ること。
4. 複数の地形バッジを持っていても合計が上限を超えないこと。
5. シーズンモード（監督視点）で専用カードが**出ない**こと。
6. `tempo`を選ぶと同じ集団の他選手のkeepThreshが厳しくなり、実際に千切れる人数が増えること
   （発動前後の集団人数を数える）。
7. 脚が売り切れた状態で`tempo`が「不発」表示になること。
8. `pageerror`ゼロ・ビルド成功・第45〜50弾の既存検証スクリプトが全て通ること。

## 実装結果（2026-08・Sonnet）

**`src/core/core.js`**
- `TERRAIN_ABILITIES`（segType→地形バッジID配列）と`hasTerrainBadge(r, segType)`を新設。
  判断カードの専用枠判定（raceDecisions.js）と`tempo`の発動条件判定（ticks.js）の両方が
  この1箇所を参照する（計算の二重管理を避ける）。

**`src/domain/shared/raceDecisions.js`**
- `buildDecisions(course, focusEnt, manager)`に第3引数`manager`を追加。基本スロットを
  `mid`/`finale`/`react`の3件（うち`react`は従来どおり状況発火のみ）に削減。`sprint`は
  `SPRINT_BADGES`（sprinter_sp/kicker/finisher/closer）のいずれかを保持する選手にのみ追加。
  `manager`が偽のとき、保持する地形バッジの最高段階（`bestTerrainTier`→
  `terrainCardCap`：銅・銀・金=1／虹=2／無し=0）まで、コース先頭から見て条件に合う区間
  （最終区間を除く）に`terrain-<segIdx>`カードを追加する。
- `composeCard`に`kind==="terrain"`の分岐を追加。地形ごとの見出し（登り/丘/平坦/独走に
  入った）と、共通の選択肢「ふるいにかける(`tempo`)／仕掛ける(`attack`)／流れに任せる(`hold`)」
  を返す。

**`src/sim/ticks.js`**
- `TEMPO_KEEP_TIGHTEN`(0.06)・`TEMPO_ENERGY_COST`(14)・`TEMPO_MIN/MAX_TICKS`(40/110)を
  新設（すべて仮置き・`export const`で外部から差し替えて実測できる形）。
- `RACE_MOVES.tempo`を追加：残脚(`legsLeft01`)に比例した持続tickを`tempoLeft`にセットし、
  `energy -= TEMPO_ENERGY_COST`。他の一手同様、attackLeft/committedBreak/conserveLeft/
  holdOnをリセットする。
- 集団の`keepThresh`計算に`tempoTighten`項を追加：同じ集団の**自分以外**の誰かが
  `tempoLeft > 0`かつ`hasTerrainBadge(その選手, 現在のsegType)`なら`TEMPO_KEEP_TIGHTEN`を
  上乗せする（発動者自身の得意地形の区間にいる間だけ効く。発動者自身は対象外）。
- `tempoLeft`の初期化（レース開始時0）・毎tickの消化（`conserveLeft`/`holdOn`と同じ並びで
  `--`）を追加。

**`src/sim/finish.js`**
- `resumeSim`の全選手一括リセットに`en.tempoLeft = 0`を追加（`attackLeft`と同様、選び直した
  一手のたびに作り直す）。
- `FINISH_BADGE_K`を**1→2**に変更（第50弾で実測確定済み・§80。K=2で飽和し3以上は完全に
  同一値だったため、頭打ちになる最小値を確定値として適用）。

**`src/domain/shared/moveEdge.js`**
- `tempo`を`STEADY_MOVES`（金＝手堅い。自分は速くならない性質）と`LEGS_SCALED_MOVES`
  （残脚依存＝脚が売り切れれば不発）の両方に追加。

**`src/components/RaceView.jsx`**
- `buildDecisions`呼び出しに`!hasAvatar`（シーズン＝監督視点かどうか）を渡すよう変更。
- 判断の実況ラインに`tempo`用の1文を追加（「〜がペースを上げた！集団を絞り込みにかかる」）。

**検証**（Node・Playwright実機。`w51_verify.mjs`をscratchpadに作成）
1. バッジ無しの選手で判断定義が`mid`/`finale`/`react`の3件のみ（`sprint`/`terrain-*`が
   無い）ことを確認。
2. スプリント系バッジの有無で`sprint`カードの出現が切り替わることを確認。
3・4. `mount`銅／金でterrainカードが1件、`mount`+`allclimber`虹（climb・hill両方所持）で
   2件（上限を超えない）になることを確認。
5. `manager=true`でterrainカードが出ないこと（`manager=false`では出ることも対照確認）。
6. **`tempo`が実際に集団を削ること**を、`resumeSim`を使った実機同等の手順（tick0→150まで
   助走→そこから`hold`と`tempo`をそれぞれ分岐実行）で確認。能力差だけでは千切れない
   境界値（同一シード・`Math.random`固定）で、`hold`は弱組6名中0名千切れ、`tempo`は
   6名中6名千切れることを確認（後述のteamKeepRelief・エネルギー履歴欠落の2点に注意が
   必要だった。詳細はテスト実装時の調査メモとしてscratchpadに残す）。
7. 満タンでは不発でない・残脚-90では`tempo`が「不発」表示になることを確認。
8. 第45〜50弾の既存検証スクリプト（w45_verify1/2/3・w46_verify・w47_verify・w48_verify・
   w50_verify）を全て再実行し回帰なし。`npx vite build`成功。Playwright実機：マイライフで
   デビュー→目指すバッジ3つ選択→山岳ロード出走→観戦中に実際にterrainカード
   「ふるいにかける／仕掛ける／流れに任せる」が発火→選択→結果画面（24位/41人中）まで
   到達、`pageerror`ゼロ。

**やらなかったこと（設計どおり）**：`TEMPO_KEEP_TIGHTEN`等3定数の実測確定はOpus担当
（devlog/wave49.mdの3点固定＝`Math.random`/`Date.now`/`ridState.value`が必須）。専用の
相乗テーブルは作っていない。

# 第38弾: 能力をカンストさせない成長カーブへ（旧「早期カンストの再発疑い」）

2026-08 設計。DEVLOG「次のアクション」17番。**★育成の方向転換**（能力値で個性を出すのをやめ、
バッジで出す）の第1歩＝バッジ（13番）が乗る土台を作る弾。

## まず訂正 — 第36弾に記録した数字は誤りだった

第36弾の副次観察として「熱心なプレイなら3〜4年目、成長力Sなら2年目にfocus能力がカンストする」
と記録し、DEVLOG 17番もこれを根拠にしていた。**この数字は誤りである。**

原因：測定スクリプトが`careerWins: 0`固定だった。`mlGrowthCap`は実績（`mlAchievementBonus`＝
路線の踏破段数×4＋タイトル×5＋通算勝利/4）で大きく動くため、勝たない選手と勝つ選手では
上限がまるで違う。**「熱心なプレイ」と称しながら、実際は「一度も勝たない選手」を測っていた。**

| 実績 | 1年目 | 5年目 | 12年目 |
|---|---|---|---|
| 無勝利 | 90 | 94 | 98 |
| 通算8勝 | 100 | 104 | 108 |
| 通算20勝 | 111 | 115 | 119 |
| 通算20勝＋2タイトル | 121 | 125 | 129 |
| 通算40勝＋4タイトル | 140（ハードキャップ） | 140 | 140 |

## 診断（実コードをimportした月次シミュレーション）

`addAb`/`growthFactor`/`growthPhase`/`mlGrowthCapFor`を実際にimportし、
`controllers/mylife/month.js`のtrain枝・race枝・衰え枝と同じ順序・同じ係数で15年回した。
「カンスト」の操作的定義は**年間の伸びが1.0点を割った年**（＝プレイヤーが「もう伸びない」と
感じる年）とした。第36弾が使った「capとの差が0.05未満」は初期条件でぶれて再現性が無い。

| シナリオ | 伸びが1.0を割る年 | 12年目の能力/上限 |
|---|---|---|
| ①勝てない（年7練習・無勝利） | 9年目 | 107.3 / 108（残0.7） |
| ②平均（年2勝） | 9年目 | 122.2 / 129（**残6.8**） |
| ③熱心（機材あり・成長力A・年4勝） | 10年目 | 136.1 / 139（**残2.9**） |
| ④最強（成長力S・年6勝＋年1タイトル） | 9年目 | 154 / 150 |

**カンストは3〜4年目ではなく、全シナリオ一律で9〜10年目。** そして原因は成長上限ではない：

```
年1〜2  成長期(22-23歳)  +14〜38/年   ← キャリアの伸びの大半がここで終わる
年3〜8  全盛期(24-29歳)  +2.5〜10/年
年9〜   衰え期(30歳〜)   ほぼ0か減少
```

**決定的な証拠は②③で上限が余っていること**（残6.8点・残2.9点）。伸びしろがあるのに伸びない。
壁の正体は`growthPhase()`が返す係数が**成長期1.0 / 全盛期0.5 / 衰え期0.1**で、30歳で
10分の1に落ちること。したがって**`mlGrowthCap`を上げても②③④はほとんど改善しない。**
上限が実際に効いているのは①（勝てない選手）と④（ハードキャップ140に当たる）だけ。

副次的な問題として**初動が激しすぎる**：1年目の伸びは+18.4/+20/+34.2/+38.4。
④は58→96.4を1年で駆け上がる。「気づいたら終わっていた」の体感の正体はこれ。

## 影響範囲（重要）

`growthPhase`が実際に適用される対象を確認した：

- **マイライフ**：プレイヤー本人のみ（対戦相手は`aiPowerFor()`が文脈から都度生成し、
  月次成長はしない）
- **シーズン**：自チーム`state.roster`の6名のみ（AIチームは`worldRosters`＋`ageRival`の別経路）

**つまり相手は据え置きで自分だけが動く。** したがって「総量を変えず配り直す」は好みではなく
**バランス上の必須条件**——総量が増えれば両モードとも難易度が下がる。

（補足：衰え適用はシーズンが`ph2.dec`をそのまま、マイライフが`ML_AGE_DECLINE_MUL=0.2`を
掛けている＝シーズンの方が5倍速い。この非対称は第38弾では触らない。）

## 設計案（ユーザー方針＝(b)全盛期を延ばす＋(c)初動を平坦にして配り直す）

### 変更する定数（2ファイル・3行）

**1. `src/domain/shared/growth.js` の `growthPhase()`**

| 係数 | 現行 | 新 |
|---|---|---|
| 成長期 | `1.0 * mul` | **`0.55 * mul`** |
| 全盛期 | `0.5 * mul` | **`0.30 * mul`** |
| 衰え期 | `0.1 * mul` | **`0.28 * mul`** |

**2. `src/data/abilities.js` の `GROWTH` — peakの終端を全タイプ+4歳**

| タイプ | 現行 | 新 |
|---|---|---|
| 超早熟 | `[18,21]` | `[18,25]` |
| 早熟 | `[21,25]` | `[21,29]` |
| 普通 | `[24,29]` | `[24,33]` |
| 晩成 | `[28,33]` | `[28,37]` |
| 超晩成 | `[32,38]` | `[32,42]` |

`gainMul`（早熟↔晩成のトレードオフ）は**触らない**。ハードキャップ140も**触らない**（後述）。

### 実測結果（この案での15年シミュレーション）

| シナリオ | 現行 8年/15年/頭打ち | 新案 8年/15年/頭打ち |
|---|---|---|
| ①勝てない | 108.5 / 104.7 / 9年 | 100.4 / 108.8 / **13年** |
| ②平均 | 121.3 / 121.7 / 9年 | 110.0 / 127.8 / **—（15年間ずっと伸びる）** |
| ③熱心 | 133.2 / 137.0 / 10年 | 129.7 / 143.9 / **14年** |
| ④最強 | 155.7 / 151.4 / 9年 | 152.0 / 156.2 / **11年** |

②平均の年次トレース（新案）：1年目+11.5 → 5年目+5.0 → 10年目+3.2 → 15年目+1.0。
**初動が20→11.5に収まり、伸びが15年間途切れない。**

### 意図的に受け入れるトレードオフ

- **中盤（8年目）が現行より5〜11点低くなる。** これが「配り直す」の裏側で、相手は
  据え置きなので**中盤のレースは今より難しくなる**。総量は15年目でほぼ回収される。
- **15年目は+4〜6点のインフレが残る。** 完全にゼロにするには全盛期係数を0.24以下まで
  下げる必要があるが、そこまで下げると中盤の落ち込みが大きくなりすぎる。この幅なら許容と判断。
- **④最強は11年目で頭打ちのまま。** 原因は`mlGrowthCap`の`Math.min(140, …)`。
  170へ上げる案も測ったが、④が15年目**184.5**（現行151.4から+33）まで暴れたため却下した。
  「年6勝＋毎年タイトル」を続けた選手に天井があるのは設計として妥当と判断し、
  **「ほぼ絶対カンストしない」は通常プレイ（①②③）に対する約束とする。**
- **31〜32歳の早期引退勧告がほぼ発火しなくなる。** `month.js:376`の
  `declining = phase === "衰え期" && overall < joinOvr`が、普通タイプで34歳まで偽になるため。
  33歳以上の引退勧告（`age >= 33`）は無条件なので引退動線自体は壊れない。

## 検証（第38弾の完了条件）

1. `npm run build` 通過・`pageerror`ゼロ。
2. **上表の数値をNodeスクリプトで再現**し、実装後の値が設計値と一致することを確認する
   （`careerWins`をシナリオごとに増やすフィードバック込みで測ること。固定にすると第36弾と
   同じ誤りを繰り返す）。
3. **早熟↔晩成のトレードオフが生きていること**を5タイプで確認（5年目は早熟が先行し、
   15年目は晩成が上回る、という関係が保たれているか）。
4. **シーズンモードの自チーム選手**でも成長が破綻しないことを実プレイで確認する
   （`controllers/season/month.js`は`ph2.dec`に0.2を掛けないため衰えが5倍速い）。
5. 引退動線が壊れていないこと（33歳で引退勧告が出る／31〜32歳の早期勧告が消えても
   ゲームが詰まらない）。
6. 選手画面の成長フェーズ表示（`growthPhase().tag`）が新しいpeakと整合していること。

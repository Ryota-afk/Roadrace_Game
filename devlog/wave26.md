# 第26弾：拠点画面ズームボタンの補間（22b）

**背景**：`hooks/useIsoCamera.js`の`zoomBy`はボタン1タップで倍率を一段階いきなり
適用しており補間が無かった（2026-08発見・「次のアクション」22b）。設計をテキストで
提示しユーザー承認（AskUserQuestion）：**160ms・easeOutCubic・連打は目標積み上げ・
リセットも補間・手動操作開始で即中断**。

## 実装（`hooks/useIsoCamera.js`のみ・呼び出し側は無変更）

- `startZoomAnim(toK)`：現在kから目標kへrAFで補間。毎フレーム「現在k→次フレームk」の
  **画面中央アンカー`zoomAbout`を積む**方式（中央固定ズームの合成は中央固定のままなので、
  既存の`clampCam`・限界値処理がそのまま効く）。
- `zoomBy(mul)`：目標は`アニメ中なら現在の目標toK、でなければ現在k`に`mul`を掛けて
  min/maxへクランプ→`startZoomAnim`。連打すると目標が積み上がり滑らかに再目標化。
- `startResetAnim()`：倍率とカメラ位置の両方を同じ160msでlerp（毎フレーム`clampCam`）。
- 中断：`onPointerDown`（ドラッグ・ピンチ）と`onWheel`の先頭で`cancelAnim()`。
  ホイール・ピンチ自体は従来どおり即時（連続入力に補間を挟むと遅延に感じるため）。
- アンマウント時もcancelAnim（rAFリーク防止）。最新k/camはkRef/camRefの鏡で参照。

## 検証（Playwright・シーンgのscale値をrAFでサンプリング）

| 項目 | 結果 |
|---|---|
| 1タップ | 中間5フレームを経て最終比1.350（=ボタンのmulと厳密一致） |
| 素早く2タップ | 最終比1.822（期待1.35²=1.8225と一致＝目標積み上げが機能） |
| リセット | 中間7フレームで初期倍率へ |
| 補間中にドラッグ | 比1.199で停止（<1.35＝中断が機能） |

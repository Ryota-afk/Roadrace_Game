# 第48弾: 第45弾の実装バグ修正——エントラントに銀・虹の段階が伝わっていなかった

## 発端

第45弾積み残しの「AIへの段階配布」に着手する前に、Opusが「配らないと何が壊れるか」を
先に実測しようとしたところ、**プレイヤー側の段階を銅→虹まで上げても勝率が一切動かない**
という結果になった（中堅24.0%→22.9%、全盛14.6%→12.0%）。効果が小さいのではなく、
そもそも効いていない挙動だった。

## 原因

`src/sim/effects.js`の`effAbilities()`が、レース用エントラント（`e`）を選手データ（`r`）
から組み立てる際、**`goldAbilities`しかコピーしていなかった**（108行目付近）。

```js
e.type = r.type; e.abilities = r.abilities; e.goldAbilities = r.goldAbilities;
```

`badgeTier(entity, id)`は`entity.silverAbilities`・`entity.rainbowAbilities`を見て段階を
判定するが、エントラント上ではこの2つが常に`undefined`＝空配列扱いになるため、
**銀は銅に、虹は金に潰れる**。実測で数値が完全一致することを確認：

| 段階（選手データ上） | エントラント上のbadgeTier | climb区間の能力(mount) |
|---|---|---|
| 銅 | bronze | 69.00 |
| 銀 | **bronze** | **69.00**（銅と一致） |
| 金 | gold | 73.00 |
| 虹 | **gold** | **73.00**（金と一致） |

## 影響範囲

第45弾で4段階化した19種のうち、**エントラント上で`badgeTier(e/en, id)`を呼ぶ16種**が対象
（`effects.js`の区間補正7種＋`ticks.js`の9種）。残る3種（大舞台の申し子・オールラウンダー・
吸収の天才）は選手オブジェクト`r`を直接見る実装だったため無事だった。

第45弾の検証（`w45_verify1/2/3.mjs`）は`badgeTier`・`tierValue`を選手オブジェクト単体で
確認しただけで、**`effAbilities()`で組み立てた後のエントラントで確かめていなかった**ことが
見落としの直接原因。

## 修正

`effAbilities()`に2行追加するだけ（`sim/`は`effAbilities`を唯一の入口として全エントラント
を生成しているため、他に直す箇所は無い——マイライフ・シーズン・ライバル・レジェンド全経路
が同じ関数を通る）。

```js
e.silverAbilities = r.silverAbilities; e.rainbowAbilities = r.rainbowAbilities;
```

## 検証（2026-08・Sonnet）

1. 16種すべてで銅<銀<金<虹の順に効果が単調増加することをNode検証で確認
   （例：mount climb区間 69.0→71.0→73.0→76.0）。
2. `w45_verify1/2/3.mjs`・`w46_verify.mjs`・`w47_verify.mjs`・`w47_createchar.mjs`
   （既存の全波の検証スクリプト）を再実行し、回帰が無いことを確認。
3. `npx vite build`成功。
4. Playwright実機で新規キャラ作成→素質診断→ホーム画面までの導線に`pageerror`が
   出ないことを確認（配合なし・生成のみのケース）。

## 保留（この弾ではやらない）

- **段階の効きの再測定**：バグが直った状態で改めて銅→虹の勝率差を測り直す必要がある
  （Opus・実測タスク）。
- **AIへの段階配布の要否判断**：上の再測定の結果を見てから決める（第45弾から積み残し）。
- **`sponge`の金1.35の見直し**：これも段階が正しく効くようになってから測るべきなので
  上記の再測定に合流させる。

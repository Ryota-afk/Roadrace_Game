# 第30弾: 能力レーダーの正規化とラベル配置の是正（設計合意済み・実装待ち）

2026-08。DEVLOG §61の詳細記録。ユーザーの指摘「レーダーチャートの仕様やっぱり変えられないかな？」から。

## 診断（実測）

第29弾で「外周＝その能力の上限」にしたが、**判断③のメカニクスと表示仕様が逆方向に働いていた**。

判断③は「脚質ごとに能力のシルエットを際立たせる」ための仕組み。ところが頂点の位置を
「値÷その能力の上限」にすると、**得意能力ほど分母（上限）も大きい**ため、作ったはずの
主武器の突出が図の上で打ち消される。5脚質×各120体を実際の成長式で育て切って実測：

| 脚質 | 主武器の実際の突出 | 図での突出 | 圧縮率 |
|---|---|---|---|
| SPR | 26.8% | 18.6% | 70% |
| CLM | 33.5% | 24.4% | 73% |
| RUL | 27.8% | 17.5% | **63%** |
| PUN | 23.1% | 17.7% | 77% |
| TT | 29.6% | 18.9% | **64%** |

（突出＝主武器が2位の能力をどれだけ上回るか）

さらに値が上限から遠い序盤は順位そのものが入れ替わる。4,000ケース（5脚質×200体×1/3/5/8年目）
のうち **5.8%（230件）** で「一番強い能力」と「図で一番外に出る能力」が食い違った。
実例：スプリンター1年目、実際の最強はスプリント59だが、図では登坂48（上限82）が最外に出る
＝**クライマーがクライマーに見えない**。

あわせて、第29弾とは無関係の既存不具合として、140pxでは下2軸のラベルが接触して
「スタミナスプリント」と繋がって読める状態だった。

## 決定（ユーザー合意）

### 決定1：外周の正規化＝案B（案C＋上限を点線で重ねる）

- **外周（frac=1.0）＝その選手の能力別上限の最大値**（`maxCap`）。全軸で同じ分母を使う。
- **実線多角形＝各能力値 ÷ maxCap**。分母が共通なので図の形が能力の形と一致する（歪まない）。
- **点線多角形＝各能力の上限 ÷ maxCap**。「この脚質が到達できる上限のかたち」。
  得意軸の上限は外周にちょうど接し、苦手軸は内側へ凹む。
- 実線と点線の隙間＝そのまま伸びしろ。**判断③の効果が点線の形として直接見える**ので、
  メカニクスと表示の向きが揃う。

**却下した案とその理由（すべて実際に描いて判断）**：
- 案A（外周＝基準の上限・第29弾より前へ完全復帰）：形は素直だが、得意能力は基準を超えて
  育つため上限近くで外周に張り付き、頭打ちに見える。
- 案C（外周＝maxCapのみ・点線なし）：形は直るが能力別上限が図に出ず、判断③が数値の
  伸び方だけの体感になる。
- 案D（レーダーをやめて横棒＋上限の目盛り）：読み取りは最も正確でラベル問題も消えるが、
  ひと目で脚質が分かる「かたち」と、隣の素質7角形との対比を失う。

### 決定2：ラベル配置＝甲（下2軸を外へ逃がす＋「上限」を左下へ）

- 下側の軸（`sin(angle) > 0.3`）だけ外周1.5倍の位置へ出す。他の軸は従来どおり1.3倍。
- 下側の軸は中央揃えをやめ、**右の軸は左揃え・左の軸は右揃え**にして外へ寄せる（dx=∓8）。
- 図の右下にあった「上限」の数字を**左下へ移す**（スプリントのラベルとの接触を避ける）。

**却下した案とその理由（すべて実際に描いて140pxで確認）**：
- 案2（ラベルと数値を1行化）：1行化で横幅が増え、12年目の値では「48タミナ」と衝突。破綻。
- 案3（数値を図の内側へ）：数値が中央に集まって団子になる。破綻。
- 乙（五角形を回して頂点を下へ）：下の衝突が上へ移動しただけで「スプリントスタミナ」と繋がる。破綻。
- 丙（甲から「上限」の数字を消す）：最もすっきりするが、天井の具体的な数値が画面から
  読めなくなるため不採用（あと何点伸びるかを知りたい場面がある）。

## 実装仕様（そのまま実装できる粒度）

### `src/components/RadarChart.jsx`

**`RadarChart` に新propを1つ追加**
- `capRing`: `number[] | null`（各軸のfrac 0..1、軸の順序はaxesと同じ）。既定 `null`。
- `capRing` があるとき、**データ多角形を描く直前**（＝下のレイヤー）に点線多角形を1枚描く：
  - `points` = 各軸 `pointFor(i, capRing[i])`
  - `fill="none"` / `stroke={color}` / `strokeWidth={1.2}` / `strokeDasharray="3 3"` / `opacity={0.55}`

**軸ラベルの配置を変更**（`axes.map` のラベル描画部）
```
const [ux, uy] = [Math.cos(angleFor(i)), Math.sin(angleFor(i))];
const bottom  = uy > 0.3;                                  // 下側にある軸
const [lx, ly] = pointFor(i, bottom ? 1.5 : 1.3);
const anchor  = bottom ? (ux > 0 ? "start" : "end") : "middle";
const dx      = bottom ? (ux > 0 ? -8 : 8) : 0;
```
- ラベル：`x={lx + dx}` `y={showValues ? ly - 6 : ly}` `textAnchor={anchor}`
- 数値　：`x={lx + dx}` `y={ly + 7}` `textAnchor={anchor}`
- `showValues=false` のときは従来どおりラベル1行のみ（yのずらしなし）。

**cornerの位置を右下から左下へ**
- 変更前：`x={size} y={size-9}` / `x={size} y={size+4}`（ともに `textAnchor="end"`）
- 変更後：`<text x={-6} y={size+16} textAnchor="start">{corner.label}</text>`
  　　　　`<text x={28} y={size+16} textAnchor="start">{corner.value}</text>`
- svgは `overflow:"visible"` なので枠外へ出て良いが、**親側の下余白が足りているか要確認**
  （`AbilitySoshitsuRadarPair` のラッパー、および `Section` の padding）。

**`AbilityRadarChart` の軸生成を変更**
```
const caps   = capFor ? AB_KEYS.map(k => capFor(k)) : null;
const maxCap = caps ? Math.max(...caps) : cap;
const axes   = AB_KEYS.map(k => ({ label: AB_LABEL[k], value: r[k] ?? 0, max: maxCap }));
const ring   = caps ? caps.map(c => c / maxCap) : null;
```
- `<RadarChart ... capRing={ring} corner={capLabel ? { label: "上限", value: Math.round(maxCap) } : null} />`
- **cornerの数字は基準値ではなく `maxCap`（＝外周の値）にする。** 図と数字を一致させるため
  （第29弾では基準値を出していたが、外周が基準値でなくなるので合わなくなる）。
- `capFor` を渡さない呼び出し（シーズン側）は `maxCap === cap`・`ring === null` となり、
  点線なし・従来の見え方のまま。

### 影響範囲（呼び出し側の変更は不要）

- `src/screens/mylife/rider.jsx`：既に `capFor` を渡しているので自動的に案Bになる。
- `src/screens/season/hub/riders/list.jsx:85`：`cap` のみ渡す＝点線なし。ラベル配置の
  改善だけ共通で効く。
- `RiderRadarChart`（素質7軸）：`capRing` なし。**ただしラベル配置の変更は7角形にも効く**ので、
  7角形で下側の軸が3本になるケースの重なりを実機で必ず確認すること（モックは5角形のみ）。

## 検証項目（実装後に必ず実施）

1. `npm run build` が通る。
2. Playwright：マイライフ選手画面で、実線多角形の各頂点の半径比が `値 / maxCap` と全軸一致。
3. Playwright：点線多角形の各頂点の半径比が `capFor(k) / maxCap` と一致（得意軸が1.0）。
4. Playwright：5角形・7角形とも、隣り合うラベルのテキストbboxが交差しないこと（機械判定）。
5. Playwright：シーズン選手一覧のレーダーが従来どおり（点線なし・頂点比＝値/cap）。
6. pageerror ゼロ。左下の「上限」が親要素にクリップされていないこと（スクショ目視）。

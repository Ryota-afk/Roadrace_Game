# 第43弾（設計確定）: 出走計画 — レース選択の操作量を増やす

2026-08 設計。第42弾で退行モデルを撤回した際、**根本原因は「プレイヤーがレースの地形を
ほとんど選べないこと」**だと判明した（`devlog/wave42.md`末尾）。この弾はそこを直す。

## 背景：なぜ操作量が足りないのか

| 事実 | 値 |
|---|---|
| コーステンプレの総数 | **6種**（クリテリウム／サーキットレース／丘陵ロード／山岳ロード／ヒルクライム／個人TT） |
| うち山岳を含むもの | **2種**のみ（山岳ロード0.76／ヒルクライム1.00） |
| 候補が1本しか出ない月 | クラス0で4/12、**クラス2以降で6/12**（1月石畳古典・4月丘陵古典・6月山岳古典・5月世界選手権・3月五輪・11月年度末） |
| `favors`が`flat`のテンプレ | **0種**（平坦区間はスプリント系コースから供給されている） |

狙って選んでも、**年の半分は選択肢が無い**。結果、山岳狙いのプレイヤーの露出率は0.496、
無頓着は0.222で、8戦窓のばらつきに埋もれる（第42弾の計測1〜3）。

## 計測：どの方式が効くか

12年×3クラス、24年分の候補生成をシミュレートして比較した。

| 案 | 無頓着 | 山岳宣言 | 差 | 8戦窓の分離 |
|---|---|---|---|---|
| 現状 | 0.222 | 0.496 | 0.274 | −0.049 |
| 通常月を5候補に | 0.222 | 0.622 | 0.400 | +0.076 |
| 全月3候補（看板月にも選択肢） | 0.222 | 0.695 | 0.473 | +0.140 |
| 重み w=2 | 0.222 | 0.564 | 0.342 | +0.030 |
| 重み w=3 | 0.222 | 0.599 | 0.377 | +0.061 |
| **★必ず1本含める（採用）** | 0.222 | **0.597** | 0.375 | +0.061 |

**「必ず1本含める」を採用。** 効果は重みw=3と同等（0.597対0.599）でありながら、
確率ではなく確定仕様なので**一文で正確に説明でき、値がぶれない**。

⚠️「全月3候補」は効果最大だが、`race.js`冒頭の第41弾の決定（看板レースは選択肢を出すと
格が下がる）を覆すため不採用。「5候補」は6種中5種を毎月見せることになり、狙った地形が
ほぼ必ず手に入る＝毎月の迷いが消えるため不採用。

### 年間本数（この弾の実効果・⚠️プレイヤーには出さない）

| 宣言 | 宣言なし | 宣言あり |
|---|---|---|
| 山岳 | 年3.4本 | 年8.1本 |
| 丘陵 | 年3.1本 | 年8.8本 |
| スプリント | 年3.3本 | 年8.0本 |
| 独走（TT） | **年1.2本** | 年7.0本 |

⚠️**独走の行が重要。現状のTT型は年1.2本しかTTを走れていない。** 第41弾で`soloist`が
「狙っても0.33止まり」だったのはこれが原因で、TT型のビルドは事実上成立していなかった。

### 却下した案：`badgeGoals`を宣言に流用する

各脚質の目標バッジ母集団10種のうち**地形に紐づくのは常に1種だけ**（しかも自分の脚質に
gateされたもの）。これでは「クライマーが意図して平坦を走り込み`flatlander`を獲る」が
できず、残り9種を選ぶと偏りがゼロになる。**成立しないため却下**（設計途中で一度
「`badgeGoals`に意味が生まれる」と述べたが誤りだった）。

## 確定仕様

### データ

| 項目 | 内容 |
|---|---|
| 保存先 | `ml.raceFocus`（新規・`null`＝未指定）。`ML_SAVE_FIELDS`（`state/mylifeState.js`）に追加 |
| 取りうる値 | `"climb"` / `"hill"` / `"sprint"` / `"solo"` / `null` |
| 選択肢の導出 | `DISCIPLINE_KEYS`のうち、`TEMPLATES`のいずれかが`FAVORS_TO_DISCIPLINE[t.favors]`で該当するもの。**`flat`は該当テンプレが0種のため選択肢に出さない** |
| 表示名 | `DISCIPLINES[k].label + "中心"`（山岳中心／丘陵中心／スプリント中心／独走（TT）中心）。`null`は「特に決めない」。**新語彙を作らない** |
| 初期値 | `initMyLife()`・`domain/mylife/createChar.js`とも`null` |

### 生成ロジック

`mlGenRaceCandidates(year, month, classIdx, focus)` に**第4引数を追加**する。

- `focus`が`null`／未指定なら**現状と完全に同一の出力**（RNGの消費順を1回も変えない）
- 効くのは**通常月（候補3本の月）のみ**。看板レース月（古典3種・世界選手権・五輪・
  11月年度末）は分岐の手前で`return`するため**一切変更しない**
- 通常月では、`FAVORS_TO_DISCIPLINE[t.favors] === focus` を満たすTEMPLATEから**1本を先に
  引き**、残り2本を従来どおり残りのプールから重複なしで引く
- `mlGenRace(year, month, classIdx)`は**シグネチャ据え置き**（他クラスの世界ランク用に
  偏りのない生成が必要なため。下表参照）

### 呼び出し6箇所の扱い

| 箇所 | 用途 | 対応 |
|---|---|---|
| `domain/mylife/createChar.js:252` | キャリア開始時の初月 | そのまま（この時点ではまだ出走計画を選んでいない）。下記「初月の扱い」参照 |
| `controllers/mylife/career.js:43` | クラス変動時の再生成 | `s.raceFocus`を渡す |
| `controllers/mylife/month.js:457` | 年跨ぎ | `s.raceFocus`を渡す |
| `controllers/mylife/month.js:468` | 年跨ぎ | `s.raceFocus`を渡す |
| `controllers/mylife/month.js:522` | 翌月へ | `s.raceFocus`を渡す |
| `controllers/mylife/month.js:492` | **他クラスの世界ランク用**（`mlGenRace`） | ⚠️**無変更**。他クラスの選手はプレイヤーの計画と無関係 |

**初月の扱い**：`mlConfirmBadgeGoals`（出走計画の確定もここで行う）で、`raceFocus`が
`null`以外なら`races`を`mlGenRaceCandidates(year, month, classIdx, raceFocus)`で
**再生成する**。まだ1戦も走っていないため安全であり、これをしないと「計画を立てた直後の
初月だけ計画が無視される」ことになる。

**変更の反映タイミング**：`ml.races`は生成済みのため、ホームで計画を変えても
**今見ている候補は入れ替わらず、翌月の候補から効く**（変更による鞍替えを防ぐ）。

### UI（§8の手順どおりモック提示→合意済み。案A採用）

**キャラ作成（`mylife_badge_goals`画面）**——順序は**目指すバッジ→出走計画**。
出走計画は手段の選択なので、目的（バッジ）を決めた直後に置く。

```
目指す選手像                        ← 画面タイトル
  目指すバッジ            3 / 3 選択  ← セクション
  クライマーが目指せるバッジから3つ選ぶ。あとから変えられる
  [既存の10種リスト]
  出走計画                          ← セクション（新規）
  山岳中心                     選択中
  丘陵中心 / スプリント中心 / 独走（TT）中心 / 特に決めない
  毎月の候補に山岳のレースが必ず1本入る   ← 選択中のものだけ1行
[この内容でキャリアを始める →]
```

⚠️**併せて既存の見出し重複を解消する**（ユーザー合意済み）。現行の`create.jsx`は
296行目の画面タイトルと308行目のセクション見出しが**どちらも「目指す選手像」**。
タイトル＝「目指す選手像」、セクション＝「目指すバッジ」「出走計画」に整理する。

**ホーム**——既存の「レース作戦」PressRowの直後に「出走計画」PressRowを追加。
アコーディオンの構造は`ML_TACTICS`のものをそのまま流用し、作成画面と同一の見え方にする。
開いた状態の末尾の一文は「毎月の候補に山岳のレースが必ず1本入る。変更は翌月の候補から効く」。

**⚠️数字は一切出さない**（ユーザー明示）。上の「年3.4本→年8.1本」は開発用の実測値であり
画面には出さない。効果は「毎月の候補に◯◯のレースが必ず1本入る」という確定仕様の一文で
伝える——平均ではないのでぶれず、数字より正確。

# 第55弾（設計確定）: テンポを撤去し、逃げの「消耗」を再較正して成立させる

## 発端

⚠️**「逃げを成立させる」試みは3回失敗した**（第52弾＝定数調整／第53弾＝集団ごとのテンポ／
第54弾＝レース全体のテンポ）。3回とも**集団の速度に手を入れる**方向で、3回とも
**基準点（`hold`）を犠牲にする**か**フィールドを融合させる**かで失敗した。

⭐しかし第54弾の判定作業中の決定実験で、**真の障壁が特定できた**（全表は`devlog/wave54.md`末尾）。

- `TEMPO_BASE=0.85`（逃げに**17.6%**の速度優位）でも`attack`は`hold`より**5.84着悪い**。
  ⚠️**現実的にあり得ない速度差を与えても逃げは成立しない＝速度は障壁ではない。**
- テンポをOFFにし、`energyDrain`の`brk`（`committedBreak`かつ`solo`/`attack`の選手に掛かる
  消耗割引）**だけ**を下げると、⭐**基準点を一切犠牲にせずに`attack`が成立した**。

| brk | terrain/hold | terrain: attack−hold | mid: attack−hold | グループ数 | 逃げ切り勝ち |
|---|---|---|---|---|---|
| 現行`{mtn:0.4 … sprint:0.85}` | 12.93 | +12.25 | +4.59 | 6.86 | 3.1% |
| 0.25 | 12.66 | +4.87 | +2.26 | 6.60 | 11.5% |
| ⭐**0.22** | ⭐**12.93** | ⭐**+1.43** | ⭐**+1.91** | ⭐**6.74** | ⭐**10.4%** |
| 0.18 | 13.00 | **−3.74** | +0.63 | 6.71 | 13.5% |
| 0.15 | 12.98 | −5.17 | +0.44 | 6.73 | 15.6% |

**なぜこれが効くのか**：集団に一切触らないため**基準点が動かず**、速度差を作らないため
**誰が千切れるかの選抜も壊れない**。テンポが3回とも壊したのは、まさにこの2つだった。

⚠️**brk=0.18以下は行き過ぎ**（`attack`が`hold`より明確に良くなり、今度は「常に仕掛けるのが
正解」になる。§35で潰した「早駆けが常時最適解」の裏返し）。

## 確定仕様

### 1. テンポ（第53・54弾）をコードごと撤去する

実測で成立しないと確定したため、使わない仕組みを残さない。

- `src/sim/ticks.js`から`TEMPO_BASE`／`CHASE_FULL_GAP`／`TEMPO_END_PROG`／
  `TEMPO_DRAIN_EXP`の4定数と、その定義コメントブロックを削除する。
- tickループ先頭の`racePaceMul`/`raceDrainMul`の計算ブロックを削除する。
- モード決定後の`active.forEach`（`groupPaceMul`/`groupDrainMul`を配る処理）を削除する。
- 移動パスの`dist *= en.groupPaceMul`と`* (en.groupDrainMul ?? 1)`を削除する。
- ドラフト勢の`drain`計算から`tempoDrainMul`の項を削除する。
- ⚠️**`TEMPO_KEEP_TIGHTEN`／`TEMPO_ENERGY_COST`／`TEMPO_MIN_TICKS`／`TEMPO_MAX_TICKS`は
  削除しない。** これらは第51弾の判断カードの一手`tempo`（「ふるいにかける」）のもので、
  名前が似ているだけの別物。⚠️**混同して消さないこと。**
- 撤去後の挙動は第52弾完了時点（`TEMPO_BASE=1.0`相当）と**完全に一致するはず**。

### 2. `brk`（逃げの消耗割引）を再較正する

`src/sim/ticks.js`の`energyDrain`内：

```js
const brk = en.committedBreak && (mode === "solo" || mode === "attack")
  ? ({ mtn: 0.4, climb: 0.45, hill: 0.55, flat: 0.75, sprint: 0.85, tt: 0.75 }[segType] ?? 1) : 1;
```

**実測の最適値は全地形一律0.22**。ただし現行テーブルは「登坂ほど逃げが決まりやすい」という
v35の設計意図を持っており、これは残す価値がある。**平均が0.22前後になるよう、現行の形を
保ったまま圧縮する**：

```js
{ mtn: 0.18, climb: 0.19, hill: 0.21, flat: 0.25, sprint: 0.27, tt: 0.25 }
```

（現行の相対的な大小関係はそのまま・平均0.2250。⚠️これは**実測値ではなく設計値**なので、
実装後に「一律0.22」と同等の結果になるかを確認する＝下記の検証項目3）

### 3. ⚠️平坦系コースでの確認測定を必ず行う

⚠️**上記の実測はすべて山岳系レース（`mlGenRaceCandidates(..., "climb")`）でしか行っていない。**
現行の`flat: 0.75`／`sprint: 0.85`という高い値は今回ほとんど動かされておらず、
**平坦系コースで逃げが強くなりすぎる／弱いままである可能性がどちらもある**。
実装後に`"flat"`／`"sprint"`のレース選択で同じ格子を測り直すこと（Opus担当）。

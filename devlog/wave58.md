# 第58弾：仕掛けに仲間が乗る（プレイヤーの`attack`を集団にする）

**状態**：**設計確定（ユーザー合意済み・2026-08）**。実装はSonnet。

第57弾の着手時に保留していた設計を起こしたもの。順序を入れ替えた理由は、
**そもそも勝負所で`attack`が「不発」表示で選びにくい状態だった**ため
（第57弾でその表示を廃止し、`attack`が普通に選べるようになった）。

⚠️**第57弾はUIのみでsimの計算式・定数に一切触れていない**（`ticks.js`の実質的な変更は
`LEGS_EMPTY`のコメント1行だけで値は同一）。よって下記の基準値はそのまま有効：
**`hold` 12.00 ／ `attack−hold` +13.03 ／ 平坦の逃げ 20.0%**。

⚠️**第57弾で`attack`が選びやすくなった分、この罠は以前より露出する。**
プレイヤーが「仕掛ける」を選ぶ機会が増えたのに、平坦・丘陵では単独逃げの勝率が0.0%
のままなので、この弾の優先度は上がっている。

**エースだけの集団になりやすく、凍結して死んでいた**。

|---|---|---|
| クリテリウム（平坦） | 5.0% → **20.0%** | 0% → 0% |
| サーキット | 2.5% → **10.0%** | 0% → 0% |

## 残った問題と、その構造的な原因

残るのは**プレイヤーの`attack`カードだけが機能しない**こと
（`w55_sweep_one.mjs`：`hold` 12.00 vs `attack` 25.03 ＝ **+13.03着悪化**）。

原因は実測で完全に特定できた（`scratchpad/w57_solo.mjs`・n=30）：

| | 飛び出す人数 | tick30時点で形成される集団 | 単独のまま |
|---|---|---|---|
| **AIの逃げ** | tick0に**7.9人が一斉** | 平均**5.1人の集団** | 1.1人 |
| **プレイヤーの`attack`** | **1人だけ** | **単独** | — |

そして**平坦・丘陵では単独逃げの勝率は0.0%**（上表）。
**`attack`カードは、その地形で勝率0%の形にプレイヤーを送り込んでいた。**
AIの逃げロールは`ticks.js`の`fromTick===0`枝で
`en.attackLeft = (en.role === "breakaway" ? BREAKAWAY_ATTACK_TICKS : 0)`により
**全員が同時に飛び出すため最初から集団になる**。この機会がプレイヤーにだけ無い。

**なお`brk`はこの問題を解けない。** `brk`は`committedBreak && (mode==="solo"||"attack")`＝
**単独の時しか掛からない**ので、成功している集団逃げには最初から1ミリも効いていない。
`brk`を下げる案は実測で棄却した（下記「やらないこと」）。

## 確定仕様（ユーザー合意済み）

### 1. `RACE_MOVES.attack`に「同乗」を足す

`src/sim/ticks.js`の現行：

```js
  attack: (r) => {
    const g = legsLeft01(r);
    r.attackLeft = Math.round(ATTACK_MIN_TICKS + (BREAKAWAY_ATTACK_TICKS - ATTACK_MIN_TICKS) * g);
    r.committedBreak = true; r.conserveLeft = 0; r.holdOn = 0; r.energy -= 9;
  },
```

第2引数`riders`は既に`finish.js`の`RACE_MOVES[moveId](focus, riders)`で渡されている
（`teamShelter`/`teamChase`/`assistLaunch`が既に使用）。シグネチャを`(r, riders)`へ変える。

**同乗者の条件**——**新しい判定基準を発明せず、既存の自発アタック抽選のフィルタをそのまま使う**
（`ticks.js`の`if (en.isPlayerChar || en.isAce || ...)`の行。同じ母集団＝「集団ゴールで
勝ち目が薄く、飛び出す動機がある選手」を指す）：

- `en === r` を除外（本人）
- `en.isAce` を除外
- `en.attackLeft > 0` / `en.committedBreak` を除外（既に逃げている）
- `en.mode === "solo"` を除外（既に千切れている）
- `en.energy < 42` を除外
- `sprintGap = max(flat, climb, sprint, stamina, solo) - sprint` が **8未満**を除外
- **`en.groupId === r.groupId`**（プレイヤーと同じ集団にいる選手のみ）
- `en.finished` を除外

**人数と選び方**：
- **最大2人**（`BRIDGE_MAX = 2`。プレイヤーと合わせて3人＝実測で勝っている集団逃げの規模）
- **`sprintGap`の降順**で選ぶ（集団ゴールで最も勝ち目が薄い＝最も乗る動機がある選手）。
  **同値は`id`の昇順**で決定論的に割る（`Math.random()`は使わない）
- ⚠️**確率は使わない。条件を満たす候補が居れば必ず乗る。** 理由：プレイヤーには既に
  「逃げが残るか」という大きな不確実性があり、そこに同乗のコイン投げを重ねるとカードが
  読めなくなる。候補数はレース状況で自然に0〜2人へ変動する。

**同乗者に与える値**（プレイヤーと揃える）：
- `attackLeft` = **`r.attackLeft`と同じ値**（バラけると置いていかれる）
- `committedBreak = true` / `conserveLeft = 0` / `holdOn = 0`
- `energy -= 9`（プレイヤーと同じ代償。ノーコストで乗せない）
- 難易度スケール用に**`en.bridgedFrom = r.id`のマーカーを立てる**（下記2で使う）

### 2. `finish.js`の難易度スケールを同乗者にも掛ける

`applyMove`の現行のスケール処理は`focus`にしか掛かっていない。このままだと難易度によって
**プレイヤーと同乗者の持続がズレて逃げが分解する**。既存の
`riders.forEach(en => { if (en !== focus && en.finaleSend) en.finaleSend *= eff; })`
と同じ形で1行足す：

```js
      riders.forEach(en => { if (en !== focus && en.bridgedFrom === focus.id && en.attackLeft > 0) en.attackLeft = Math.max(6, Math.round(en.attackLeft * eff)); });
```

`bridgedFrom`は使い終わったら消すか、次の一手で上書きされる前提にすること
（レース跨ぎで残らないよう`fromTick===0`の初期化ブロックでも`null`にする）。

### 3. 空の状態（empty state）

条件を満たす候補が1人も居ない場合（全員エース／脚が42未満／スプリンター揃い／
プレイヤーが既に単独）は、**現状どおり単独で飛び出す**。カードは撃てるが決まりにくい、
という今の挙動をそのまま残す。**エラーにも不発表示にもしない。**

### 4. UIは変更しない

この弾では判断カードの文言・表示を変えない。「何人乗ったか」を見せるかどうかは
実測で効果を確認してから、CLAUDE.md §8の手順（候補提示→合意→実装）で別途決める。

## 実装結果（Sonnet・2026-08）＝⚠️機構は動くが効果が出ない

`RACE_MOVES.attack`のシグネチャを`(r, riders)`へ変え、既存の自発アタック抽選と同一の
フィルタ（エース・スプリンター・`energy<42`・別集団を除外）で候補を抽出し、`sprintGap`
降順で最大2人を同乗させる実装を行った。`en.groupId`は前回のtickループ終了時点（レース
終了直前）の値のまま残っており、`fromTick`時点の実際の隊列を反映していないことを実測で
確認したため、`attack`内で現在の`pos`を基準にグループを作り直す処理を追加した
（`_bridgeGroup`）。`finish.js`の難易度スケールも`bridgedFrom`マーカー経由で同乗者へ掛かる
ようにした。

**検証項目1〜8はすべて通過**（新規`w58_verify.mjs`・第46〜52弾＋`w57_verify.mjs`・
`vite build`）。同乗の選出・条件・上限・難易度スケール・空の状態は仕様どおりに動く。

### ⚠️ しかし実測で`attack−hold`はほぼ動かなかった（+13.03→+12.87）

`w55_sweep_one.mjs`で再測定したところ、同乗が82.3%のレースで実際に発生している
（`scratchpad/w58_debug.mjs`・n=96）にもかかわらず、`attack−hold`は+13.03→+12.87と
**誤差の範囲でしか改善しなかった**。狙っていた+1〜+3には遠く届いていない。

### 原因：同乗者は35tick以内に92.4%の確率でプレイヤーと別集団に分裂する

`scratchpad/w58_spread.mjs`（同乗ありn=79）で、`attackLeft`が尽きる頃（約35tick後）の
`groupHist`を突き合わせたところ：

| | 件数 |
|---|---|
| 同乗者全員がプレイヤーと同じ集団を維持 | **6件（7.6%）** |
| いずれかの同乗者が別集団に分裂 | **73件（92.4%）** |

原因は`ticks.js`のモード決定ループにある：**`attackLeft > 0`の選手は集団の人数に関わらず
必ず`mode = "attack"`になる**（多人数グループの分岐内でも`if (en.attackLeft > 0) { en.mode
= "attack"; ...; return; }`が`pull`/`draft`の判定より先に来る）。`attack`モードは**個人が
自分の能力だけで進む独立走行**で、`groupDist`による位置の同期が一切かからない。

つまり同乗した2〜3人は、飛び出した瞬間から**それぞれ自分の脚力で勝手に進み**、能力差が
そのまま位置の差になって開いていく。実例（seed=1000）：プレイヤー11.02に対し同乗者は
9.03と9.90——たった35tickで1〜2ユニットも開き、`GROUP_GAP_DIST`(0.22)を大きく超えて
別集団になる。「仲間を同時に飛び出させる」ことはできても、**その後1つの集団として機能
する前に、能力差で勝手にバラバラになっている**。

⚠️AIの`role: "breakaway"`も同じ`attack`モードで動いているが、Wave55の実測では集団逃げが
20〜30%成立している。地形適性で選ばれる逃げ要員同士は登坂力が近く、30tickでは目立った
差にならない可能性がある一方、この弾の同乗選出は「`sprintGap`が大きい選手」という基準
だけで選んでおり、⚠️**プレイヤーとの能力の近さを一切考慮していなかった**。

### 判断が必要な点（この弾では決めていない）

考えられる方向は複数あり、いずれもsimの動きに触れる可能性があるため設計判断が要る：

- 同乗中だけ仲間の位置をプレイヤーに同期させる（`pull`モードの「エースに合わせる」処理
  `if (ace) dist = Math.min(dist, tickDistance(ace, ...))`と同型の仕組みを`attack`にも足す）。
- 候補選出に「プレイヤーとの能力（特に該当地形の適性値）の近さ」を条件に加える
  （simには触れない・候補フィルタのみの変更で済む可能性がある）。
- 別の方式を検討する。

⚠️**コードは実装済み・全検証項目は通過しているが、狙った効果が出ていないためユーザー
判断待ち。** 撤退基準には抵触していない（`hold`は12.00で不変）が、目的（`attack−hold`
+1〜+3）も達成していない中間状態。

# 第58弾 Phase 2：逃げている間だけ足並みを揃える（設計確定・ユーザー合意済み）

## 原因の特定（Opus実測・`scratchpad/w58_why.mjs`）

分裂の実体は⚠️**プレイヤーが同乗者より12〜32%速いこと**だった。

| seed | 区間 | プレイヤーの1tick | 同乗者の1tick | 速度差 |
|---|---|---|---|---|
| 1000 | climb | 0.2302 | 0.1744 / 0.1957 | **+18〜32%** |
| 1001 | hill | 0.2683 | 0.2400 / 0.2387 | +12% |
| 1003 | climb | 0.2327 | 0.2082 / 0.2027 | +12〜15% |
| 2005 | hill | 0.2819 | 0.2466 / 0.2439 | +14〜16% |

35tickで8前後進む中での12%差は約1.0の開きになり、`GROUP_GAP_DIST`(0.22)を大きく超える。

⚠️**能力を揃えるだけでは解決しない**：seed=1003の同乗者1は登坂87でプレイヤー90とほぼ同等
なのに、バッジ（虹のmount/allclimber）の区間ボーナスで実速度は12%差が付く。

## 中核の気づき

⭐**`attackLeft`が切れて集団になれば、その後は集団の仕組み（牽引ローテとドラフト）が働く。**
壊れているのは**その前の10〜30tickで散ってしまうこと**だけである。したがって
**逃げている間だけ足並みを揃えれば足りる**。

## 確定仕様

### 1. `RACE_MOVES.attack`：リーダーにも自己参照のマーカーを立てる

現状、同乗者には`en.bridgedFrom = r.id`が立つが**リーダー（プレイヤー本人）には立たない**。
コホートを1回の`filter`で取れるよう、`attack`の中で`r.bridgedFrom = r.id`（自己参照）も立てる。

⚠️`finish.js`の難易度スケールは`if (en !== focus && en.bridgedFrom === focus.id ...)`と
`en !== focus`で本人を除いているため、自己参照を足しても**そのまま正しく動く**（確認済み）。

### 2. `ticks.js`の移動パス：コホートの上限を1tickにつき1回だけ計算する

⚠️`tickDistance`は`Math.random()`のtickジッターを含むため、**同じ選手に2回呼ぶと値が
食い違う**（`ownCapable`のコメントに前例あり）。したがって移動パスの`active.forEach`の
**直前**にコホートごとの上限を1回だけ算出してMapに持つ。

```js
    // 第58弾Phase2(devlog/wave58.md): 同じ逃げに乗った仲間は足並みを揃える。
    // attackモードは個人の独立走行でgroupDistによる同期がかからないため、能力差が
    // そのまま位置の差になり、attackLeftが切れて集団になる前に散ってしまう（実測で
    // 同乗者の92.4%が35tick以内に別集団へ分裂）。pullモードの「エースを置き去りに
    // しない」処理と同じ型で、コホート内の最も遅い選手の速度を上限にする。
    // ⚠️tickDistanceはtickジッターを含むので、1tickにつき1回だけ計算して使い回す。
    const bridgeCap = new Map(); // leaderId -> そのtickでの上限距離
    if (!noGroup) {
      const byLeader = new Map();
      active.forEach(en => {
        if (en.mode !== "attack" || en.bridgedFrom == null) return;
        if (!byLeader.has(en.bridgedFrom)) byLeader.set(en.bridgedFrom, []);
        byLeader.get(en.bridgedFrom).push(en);
      });
      byLeader.forEach((cohort, leaderId) => {
        if (cohort.length < 2) return; // 単独なら上限なし＝従来どおり
        // ⚠️千切れた同乗者に引きずられないよう、先頭からGROUP_GAP_DIST以内の仲間だけを対象にする
        const lead = Math.max(...cohort.map(en => en.pos));
        const together = cohort.filter(en => lead - en.pos <= GROUP_GAP_DIST);
        if (together.length < 2) return;
        bridgeCap.set(leaderId, Math.min(...together.map(en =>
          tickDistance(en, course.segTypeAt(en.pos).type, "attack", course.steepness))));
      });
    }
```

移動パス内、既存の`if (en.mode === "pull") { ...エースに合わせる... }`の**直後**に：

```js
      if (en.mode === "attack" && en.bridgedFrom != null && bridgeCap.has(en.bridgedFrom)) {
        dist = Math.min(dist, bridgeCap.get(en.bridgedFrom));
      }
```

### 3. クリアは追加不要

`mode === "attack"`を条件にしているため、`attackLeft`が尽きればコホートは自動的に解散する。
`bridgedFrom`自体は既に`fromTick===0`の初期化と`resumeSim`の冒頭でクリアしており、
⚠️`resumeSim`は「全員クリア →（`applyMove`で）`attack`が再設定」の順なので順序も正しい。

## やらないこと

- ⚠️**同乗者の選出条件は変えない**（「その区間を走れるか」を足したい誘惑があるが、
  2つ同時に入れると効果の切り分けができない——第53〜55弾で繰り返した失敗）。
  足並み合わせだけを入れて測り、足りなければ次の一手にする。
- `brk`・速度・AIの自発アタックには触れない（第58弾の「やらないこと」を継承）。

## 予測と撤退基準（据え置き）

**狙う値**：`attack−hold`を**+12.87 → +1〜+3**へ。

**撤退基準**：①`hold`が12.00から2着超悪化 ②平坦の逃げが30%超 ③`attack−hold`がマイナス。

⚠️**トレードオフを受け入れる**（ユーザー合意済み）：足並みを揃える＝プレイヤーは
`attackLeft`の間だけ遅くなる。その代わり3人で回してドラフトし合える。実測で平坦の
集団逃げは20%勝つのに**単独逃げは0%**なので、遅くなっても集団になるほうが有利なはず。

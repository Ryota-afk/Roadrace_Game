# 第39弾: バッジシステム（DEVLOG「次のアクション」13番）

2026-08 設計。**★育成の方向転換**の主役——能力値ではなくバッジで個性を出す。
第38弾で「能力がほぼカンストしない」土台ができたので、その上に乗せる弾。

## 調査結果：この仕組みは既に存在する（が、強く絞られている）

「レース経験でカテゴリ別pt→解放・強化」は**新機能ではない**。すでに実装済みで、
機能しないほど絞り込まれているだけだった。第36弾（生活費のクランプ）と同じ構図である。

**既にあるもの**

| 要素 | 現状 | 場所 |
|---|---|---|
| バッジ本体 | **48種・8カテゴリ** | `ABILITIES`（`data/abilities.js`） |
| カテゴリ | 地形適性10／展開・役割9／メンタル3／フィジカル13／成長5／配合限定3／血脈レシピ5 | 同上 |
| 経験による解放 | **15種**に条件あり | `ACQUIRE_CONDITIONS`（`domain/mylife/cp.js`） |
| 経験による強化 | **14種**に金特条件あり（効果はおよそ倍：`+4→+8`／`1.05→1.09`） | `GOLD_CONDITIONS`（`core/core.js`） |
| レースへの反映 | **47箇所** | `sim/effects.js`・`sim/ticks.js`・`raceDecisions.js`ほか |
| 判定材料 | `raceLog[]`＝`{year, month, name, rank, role, monument?}` | `controllers/*/result.js` |

解放条件の実例（既存）：
```
mount:      脚質CLM かつ 優勝2回        → 金特は優勝5回
escape:     逃げ役での出走3回            → 金特は5回
domestique: アシスト役での出走5回        → 金特は8回
iron:       通算出走15回                 → 金特(engine)は30回
pave_sp:    石畳の古典で表彰台           → 金特は同レース優勝
```

**足りないもの（＝第39弾でやること）**

1. **48種のうち33種に解放経路が無い**（配合・イベント専用のまま死蔵）
2. **習得が月15%の抽選**（`acquireNewAbility`）＝プレイヤーに主体性が無い
3. **所持上限が3個固定**（`if (abilities.length >= 3) return r;`）
4. **進捗が一切見えない**（「あと2回逃げれば逃げ屋」が分からない）
5. **段階が2つだけ**（通常／金）。ユーザー要望は「〜S」
6. 条件が**閾値の真偽判定**であってpt蓄積ではない

## ⚠️ 発見した balance の罠（第38弾と同じ構図）

**AI選手は金特を一切持てない。** `rollAbilities()`（`core/core.js:9`）はAIに通常特能を
0〜3個ランダムに配るだけで、`goldAbilities`を設定する経路が無い（配合由来の
`controllers/season/roster.js`は自チーム新人専用）。

つまり**強化段階は現時点で実質プレイヤー専用の非対称**であり、段階を2→5へ増やすことは
そのままプレイヤー側だけの強化になる。第38弾で「相手が据え置きなので総量保存が必須条件」と
判明したのと同じ罠。**段階を増やすなら、AI側にも段階を持たせるか、5段階の最大効果を
現行の金特（＝2段階目）と同等に留めるかの、どちらかを必ず選ぶ必要がある。**

## NBA 2Kのバッジ仕様調査（2026-08・ユーザー指示で実施）

**重要：2Kのバッジは世代ごとに全く別の仕組みで、3つの世代がある。** どれを参考にするかで
設計が根本的に変わるため、3つとも記録する。

### 第1世代（〜2K23）＝バッジポイントの予算配分制

- ゲームプレイでバッジポイントを獲得し、**限られたポイントを使ってバッジを装備**する
- カテゴリごとに16バッジ（Tier1が8個・Tier2が4個・Tier3が4個）
- **段階ごとに費用が違う**：Tier1は Bronze1／Silver2／Gold3／HOF4 pt、Tier2は 3/4/5/6、
  Tier3は 5/6/7/8
- **Tier3を取るにはTier1・2に最低10pt投資済みであることが条件**（積み上げの強制）
- 「コアバッジ」に指定するとポイントが返ってきて配分し直せる
- ⇒ **個性＝限られた予算をどう配るか**

### 第2世代（2K24）＝使用量による成長と退行

- 属性要件を満たすと**ブロンズで自動装備**される
- **上位段階は「実際にそのバッジを試合で使う」ことで上がる**
- **使わない／効果的に使えていないバッジは段階が下がる**（ただし**ブロンズが下限**で、
  それ以下には落ちない。落ちた分は初回より早く取り戻せる）
- 「フロアセッター」を適用すると、そのバッジが指定段階未満に落ちなくなる（永続）
- 2K公式の設計意図は **「バッジが常にプレイヤーの現在のプレースタイルを反映するように」**
- ⇒ **個性＝実際にどう遊んでいるか**

### 第3世代（2K25〜2K26）＝属性しきい値によるゲート制

- バッジは5段階（Bronze／Silver／Gold／Hall of Fame／**Legend**）
- **各段階に個別の属性требования**がある。例：Deadeyeはブロンズでミドル73／3P73、
  レジェンドで99／99。Legendは概ね属性95〜99が必要
- 「Build via Badges」＝欲しいバッジと段階を先に選ぶと、必要な属性が自動で確保される
- ⇒ **個性＝限られた属性ポイントをどう振ったか**

### ⚠️ この調査で判明した、本プロジェクトにとって決定的な事実

**第3世代（最新の2K26）のモデルは、属性にハードキャップがあることを前提に成立している。**
2Kのマイプレイヤーは属性の合計に厳しい予算があり（身長・ポジションでも制限が変わる）、
**全属性を99にはできない**。だからこそ「どのバッジをLegendにできるか」が個性になる。

**本プロジェクトは第38弾で、その前提（能力の頭打ち）を意図的に外したばかりである。**
能力がカンストしない世界で属性ゲート制を採ると、**時間さえかければ全員が全バッジを
最高段階にできてしまい、「極めると全員同じ万能型」がそのまま再来する。**

したがって**第3世代モデルは本プロジェクトには使えない。** 使えるのは第1世代（予算配分）か
第2世代（使用量と退行）で、どちらも能力の頭打ちに依存しない。

### 第2世代（2K24）が本プロジェクトに極めて良く合う理由

1. **ユーザーが最初に述べた要望そのもの**——「レース経験でカテゴリ別バッジpt→解放・強化」
2. **退行が、人工的な上限なしで均質化を防ぐ**。48種すべてを同時に使うことは物理的に
   できないため、使わないバッジは自然に落ちる。**装備枠のような枠制を別途設けなくてよい**
3. **自転車競技と相性が良い**：山岳を走り続ければ登坂系バッジが育ち、スプリンターに
   転向すれば登坂系が落ちてスプリント系が育つ。**キャリアの軌跡がそのまま選手の個性になる**
4. **ブロンズが下限**なので、一度取ったものが完全に失われる不快感が無い
5. 第38弾の「能力はカンストしない」と**矛盾しない**（むしろ補完する）

**実装上の要件（第2世代を採る場合）**：現状のsimはバッジを47箇所で適用しているが、
**「どのバッジが実際に効いたか」を記録していない**。使用量ベースにするには、
`sim/effects.js`等で発火したバッジIDをレース結果に集計して返す計装が要る。
これは新しい保存フィールド（例：`player.badgeUse`）を伴う。

## 設計案（NBA 2K調査を踏まえて改訂。ユーザー合意待ち）

### D1. 既存の特殊能力との関係 → **統合（既存を解放する）を推奨**

バッジ＝特殊能力そのものとして扱い、絞りを外す。新しい概念を足さない。

- 48種という「種類は豊富に」の要望は**既に満たされている**
- sim側の適用点47箇所を**そのまま使える**（並立・置換なら全て作り直し）
- 配合の金特クロス・血脈レシピ・配合限定特能が全て特殊能力に依存しているため、
  **置換は育成/配合システム全体の作り直しになる**
- 並立は「レース経験で強くなる仕組み」が2つ並ぶことになり、CLAUDE.md §5（肥大化防止）に真っ向から反する

### D2. 「全員同じ万能型」への歯止め → **2K24式の「使用量による成長＋退行」を推奨（改訂）**

⚠️ **当初は「装備枠制」を推奨していたが、2K調査を経て改訂した。**

- 条件を満たしたバッジは**最低段階（C）で自動的に有効**になる
- **上位段階は、そのバッジが実際にレースで効いた回数で上がる**
- **長く使われないバッジは段階が下がる**（ただし**Cが下限**。一度取ったものは失われない）
- 枠を人工的に設けなくても、**48種すべてを同時に使うことは物理的に不可能**なため、
  均質化が構造的に起きない

**装備枠制より優れている点**：枠制は「レース前に付け替える」という管理作業を毎回強いるが、
使用量制は**遊んでいるだけで勝手に選手の個性が形になる**。山岳ばかり走れば登坂系が育ち、
スプリンターに転向すれば登坂系が落ちてスプリント系が育つ——**キャリアの軌跡が
そのまま個性になる**のは、一人の選手の人生を追うマイライフモードと極めて相性が良い。

**退行の速さは慎重に決めること。** 2Kは「落ちた分は初回より早く取り戻せる」設計にしている。
本作は1か月＝1レース程度と試合数が桁違いに少ないため、2Kと同じ感覚で退行させると
**ほぼ全部がCに張り付く**。年単位で緩やかに落ちる調整が要る（実測で較正すること）。

### D3. 範囲 → **両モード**（`ACQUIRE_CONDITIONS`は既にシーズンでも動いている：`controllers/season/month.js:162`）

### D4. 主体性 → **条件を満たしたものは一覧から自分で選んで習得・強化**（月15%抽選は廃止）

## 段階（グレード）の設計

ゲーム内の既存語彙に合わせ **C → B → A → S** の4段階とする
（`growthPow`がS/A/B/C、適性グレードがS〜Gで、この語彙は既に定着している）。

⚠️ 効果の幅は上記「balance の罠」の結論待ち。**現行の通常=+4／金=+8 を、
C=+4 / B=+6 / A=+8 / S=+10 と素直に伸ばすと、AIが2段階目相当すら持たないため
プレイヤーだけが+10まで伸びる。** 採用するなら同時にAI側へ段階を配る必要がある。

## 段階実装（この順で進める）

1. **可視化だけ先に入れる**（機能変更なし）。現在の`ACQUIRE_CONDITIONS`/`GOLD_CONDITIONS`の
   進捗を選手画面に出す。「あと2回逃げれば逃げ屋」が見えるだけで体験が変わるか確認する。
2. **抽選を廃止し、選んで習得へ**（D4）。所持上限3個は据え置き。
3. **バッジ発火の計装**。`sim/effects.js`等で実際に効いたバッジIDを集計し、レース結果に
   載せる（`player.badgeUse`）。**この時点ではまだ効果に反映せず、数字を眺めるだけ**にして、
   1レースあたり各バッジが何回効くのかを実測する。退行速度の較正はこの実測に基づく。
4. **使用量による成長＋退行へ移行**（D2）。所持上限3個を撤廃。
5. **解放経路を33種へ拡張**（D1の本体）。
6. **段階をC〜Sへ拡張**（AI側の段階と同時に）。

**1→2 の時点で一度プレイして確かめること。**「見えるようになった」「選べるようになった」
だけで方針転換の狙い（育成の手応え）が達成される可能性があり、その場合3以降は縮小できる。
**3（計装して実測）を4（挙動変更）より先に置くのは意図的**——第36弾・第38弾とも、
実測せずに数値を決めて後から誤りが判明している。

## 判断が要る点（ユーザー確認事項）

- D1（統合）・D3（両モード）・D4（自分で選ぶ）の推奨で良いか
- **D2を「装備枠制」から「使用量による成長＋退行（2K24式）」へ改訂した**が、これで良いか。
  ⚠️退行＝**しばらく使わないバッジは段階が下がる**（下限Cで、完全には失われない）という
  挙動を受け入れられるか。ここが最も好みが分かれる点。
- 段階拡張（C〜S）に伴うAI側の対応：**AIにも段階を配る**か、**S段階の効果を現行の金特と
  同等に抑える**か
- ⚠️**属性ゲート制（最新2K26式）は採らない**方針で良いか。理由は上記「決定的な事実」の
  とおりで、第38弾で能力の頭打ちを外した本作とは前提が噛み合わない。

## 周回（ディナスティ）バランス実測（2026-08・ユーザーの「毎年勝ち続けるバランスでは？」への回答）

グランファイナル（PRO・2日制のday1）をbuildSimで直接回して実測（各50回・normal）。
自チームは調子3固定・作戦/役割/パーツなし・エースのみ指定の素の勝負。

| 自チーム | 周回0 | 周回2 | 周回4 |
|---|---|---|---|
| 全能力94（理論上限）×5・28歳 | 優勝28%・3位内70% | 優勝14% | 優勝12%・3位内30% |
| 現実的な強豪（平均OVR91） | 優勝16% | 優勝0% | 優勝0% |
| 全能力94の4年後（32歳・衰え式適用→OVR85） | 優勝0% | — | 優勝0% |
| **全能力94＋機材Lv5（PRO上限）** | **優勝92%** | — | **優勝80%**（hardでも80%） |

読み取り：
1. **素の選手力どうしは健全**。理論上限ロースターでも優勝28%止まりで、周回で12%まで落ちる。
   衰え（ピーク後は毎月-0.25×超過年数）で黄金世代の窓は実質3〜4年しかなく、
   「1ループが長い＝勝ち続ける」はむしろ逆で、選手側の入れ替え圧力は機能している。
2. **周回ボーナスは早期に頭打ち**。AI実効能力はnormalで周回0→2→4が86.6→92.1→93.9と、
   2周目以降ほぼ飽和（`abilCap=94`のクランプに吸われる）。hardは周回0で既に93.8＝
   周回ボーナスが最初から無意味。「他チームがさらに強化されます」は3周目以降は看板倒れ。
3. **崩壊ポイントは機材（equip）**。フレーム/ホイールLv5＝平坦×1.30・登坂×1.30は
   プレイヤー専用（AIに対応物なし）の恒久・全員適用の乗算で、これだけで優勝率が
   92%（周回0）／80%（周回4・hardでも80%）に跳ね、周回スケーリングを無効化する。
   パーツ・決戦アイテム（+15%）・調子管理・作戦を積む実プレイではさらに上振れする。

結論：**「機材まで積めば毎年勝ち続けられる」が現状の実態**。原因は(a)AI側に機材相当の
軸が無いこと、(b)周回ボーナスが「クランプ前の加算」でabilCapに吸われること。
是正案（未実装・ユーザー判断待ち）：周回ボーナスをクランプ後の乗算にする／AIにも
クラス・周回連動の機材倍率を持たせる／abilCapを周回で引き上げる、など。
計測スクリプト：scratchpad/measure_dynasty.mjs（equipを`{frame:0,wheels:0}`で渡すこと。
`{}`だとNaN→50丸めの計測バグになる——effAbilitiesの非有限ガードによる）。

## 成長速度の実測（2026-08・「自チームもAIも育ちやすすぎない？」への回答）

month.jsの練習式を実関数（addAb/growthPhase/persMul）で忠実再現し、18歳ユース
（OVR60前後開始・毎月最弱能力をfocus・レース出走なしの純練習）を10年回した
（scratchpad/measure_growth.mjs）。normal（cap94）。

| 環境 | 成長力B | 成長力A |
|---|---|---|
| 素朴（設備0・トレーナー0） | 21歳82→23歳89→26歳92 | 21歳88→22歳92 |
| 中間（設備2・トレーナー1） | 21歳88→23歳93 | 21歳90→22歳94 |
| フル（設備5・トレーナー3・キャンプ年4回） | **19歳93**→21歳98→23歳100 | **19歳93** |

AI側はageWorldRostersを12年実走：baseline平均は1.7→3.5（6年目ピーク）→1.6（12年目）と
世代交代で往復するだけ。GF実効は常にcap94に張り付き。

**結論：自チームは育ちやすすぎる（確定）。AIは育ちすぎではない（むしろ固定の壁）。**
1. 投資ゼロでも5年でPRO級（23歳OVR89）。フル投資なら**1年でほぼカンスト**（19歳93）。
   キャンプ×2・設備+75%・トレーナー+36%・冬+30%がすべて乗算で重なるのが原因。
   「キャリアが長い」のに**育成はループ前半の3〜5年で終わり、残り10年は維持するだけ**になる。
2. **ソフトキャップが漏れる**：addAbのcap超過減衰（exp逓減）は完全には止めないため、
   フル環境の巨大gainだとcap94のはずがOVR100前後まで滲む。
3. これは前項（機材で常勝）と同根：選手が皆cap付近に張り付きやすいから、
   選手力の差が消えて機材倍率だけが勝敗を決める構図になる。
是正のノブ（未実装・設計から要検討）：環境倍率の乗算→逓減化／キャンプ×2の見直し／
cap超過減衰の強化（ハードクランプ寄りへ）／基礎gain 1.5の引き下げ。クリア想定年数・
難易度曲線の全体設計に響くため、独立したバランス弾として扱う。

## バランス是正 実装仕様（2026-08確定・Sonnet向け）

前2節の実測を受けた是正。**ユーザー合意済み**：成長は案B／機材は据え置き／衰えは同時に緩和。

### 設計原則（この弾で確立）

**「能力のピークが成長タイプのピーク年齢と一致する」**。現状は成長タイプに関わらず全員が
19〜23歳で頭打ちになり、`GROWTH[].peak`（早熟21-25／普通24-29／晩成28-33）が意味を失って
いた。是正後は 早熟25歳／普通29歳／晩成33歳 でそれぞれ最高値を迎える（実測）。

**根本原因は成長カーブであり、機材は症状だった**。成長を是正するだけで機材Lv0→Lv5の
優勝率差は +62pt → +20pt に縮み、周回ボーナスも効き始める（選手が上限に張り付かなく
なるため）。よって機材（Lv毎+6%）・周回ボーナス（min(20, dyn*5)）は**変更しない**。

### 1. シーズンの月次練習（`src/controllers/season/month.js:65-71`）

環境倍率の**乗算を加算へ合流**させ、基礎係数を 1.5 → 0.8 に下げる。
現行はフル投資時に `1.75(設備) × 1.36(トレーナー) × 2.0(キャンプ) × 1.3(冬) = 6.19倍` と
積み上がるのが原因だった。

```js
// 是正後（環境ボーナスは加算で合流。特能・主将の倍率は個体差なので乗算のまま残す）
const envBonus = 1 + state.equip.facility * 0.05 + (state.staff?.trainer || 0) * 0.08
  + (state.camp ? 0.3 : 0) + (winter ? 0.1 : 0);
const gain = 0.8 * ph.gain * POW[n.growthPow].mul * envBonus
  * (hasAbility(n, "trainer") ? 1.2 : hasAbility(n, "lazy_sp") ? 0.8 : 1)
  * (hasAbility(n, "lateblow_sp") && n.age >= 28 ? 1.15 : 1)
  * captainMentorMul(n);
```

**マイライフ側（`controllers/mylife/month.js:110`）の 1.5 は変更しない**——別ファイルに
個別記載されており、環境倍率の構造も違う（装備・特能ベースで積み上がりが穏やか）うえ、
`mlGrowthCap`込みで第43弾に較正済みのため。

### 2. 衰えの緩和（`src/domain/shared/growth.js:80`）

```js
// 現行: dec: Math.min(1.2, 0.25 * (r.age - pe)) * decayMul
   是正: dec: Math.min(0.6, 0.12 * (r.age - pe)) * decayMul
```

**この関数はシーズンとマイライフの共有**なので両モードのベテランが長持ちする（同じ改善で
あり意図どおり）。`ageWorldRosters`（AI側）は別式なので影響なし。

### 旧セーブへの影響（破壊的変更なし）

数値式のみの変更でセーブ構造は不変。既存セーブの選手は現行式で育った能力値をそのまま保持し、
**以後の伸びが緩やかになる**だけ（能力は下がらない）。衰え緩和により既存ベテランはむしろ
長持ちする。ただし遊び込んだセーブでは「急に伸びなくなった」と感じる可能性があり、
そこは仕様変更として受け入れる。

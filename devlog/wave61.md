# 第61弾：メリハリと視線誘導の土台（設計前の実測）

**状態**：**実測のみ完了・設計はこれから**。⚠️§8に従い、着手前に画面モックを複数提示すること。

## 背景

ユーザーから繰り返し「メリハリがない」「視線誘導が意識できていない」と指摘され続けていたが、
毎回感覚で受け止めて終わっていた。§8の背景表（絵文字653個・角丸315枚等）と同じやり方で、
実際に数えた（`scratchpad/measure_hierarchy.mjs`・ホーム画面をDOMから計測）。

## 実測（ホーム画面・1年目4月・テキストノード73個／背景付きの面16個）

| 症状 | 実測値 |
|---|---|
| ⚠️**太字が1つも無い** | 「目立つ文字」14個が**全部`font-weight:400`**。`src`全体で`fontWeight`の指定は**8箇所のみ・実質3箇所(700)**。⚠️**`data/theme.js`にウェイトのトークンが存在しない** |
| 画面の2/3が最小級数 | 73個中**46個(63.0%)が10px** |
| 級数が実質3段 | 38px×**1**／20px×**1**／16px×12／13px×13／10px×46。上位2つは各1個なので実務上は16/13/10の3段、かつ10pxが支配 |
| 画面の6割が沈んだ灰色 | 文字色の**61.6%が`rgb(140,138,130)`（`T.color.sub`）**。白16.4%・アクセント黄15.1% |
| 面の幅が均一 | 16面中**10面(62.5%)がぴったり398px**。幅の差で情報を束ねていない |

## 視線誘導：順序が逆

止まり所（大きい or 太い文字）を上から並べた実測：

```
y= 28  16px  1年目 4月 / 0万円
y=132  20px  春日井 圭介
y=141  38px  62                    ← 画面で最大
y=221  16px  37 / 50 / 100
y=292  16px  富士ヒルクライム
y=338  16px  日光山岳ロード
y=384  16px  瀬戸内丘陵ロード
y=478  16px  このレースに出場する    ← 画面の主役
```

⚠️**画面で一番大きいのは「62」＝総合力＝押せない数字**。⚠️**主ボタンはレース名とも数字
「37」とも同じ16px・同じw400**で、見つかるのは`action`色の面のおかげだけ。
**視線が最初に落ちる所と、行動すべき所が一致していない。**

## 根本原因（設計の起点）

⚠️**強調の道具が「級数を上げる」「黄色にする」の2つしかない。太さの軸が設計システムに無い。**
情報の階層は5段階以上あるのに道具が2つでは足りず、結果として「全部を小さい灰色にして、
たまに黄色」に落ち着く。これが「メリハリがない」の実体。

§9で`accent`＝データ強調／`action`＝操作、と**色の役割分担は既に整理済み**なので、
⚠️**足りないのは色ではなく太さの軸**。色を増やす方向で解こうとしないこと（§9の
「役割のない色はただの装飾に戻る」に抵触する）。

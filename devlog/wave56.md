# 第56弾：レース終盤が「シミュレーションされていない」問題を直す

**状態**：⭐**設計確定（ユーザー合意済み・2026-08「両方直す」）**。実装はSonnet。

第55弾の副産物として持ち越した「`MAX_TICKS`固定値による未完走バグ」を調べたところ、
⚠️**独立した2つの欠陥**が見つかり、しかも**片方は未完走とは無関係に全テンプレートの
レース結果を汚染していた**。

---

## 現状の実態（`scratchpad/w56_scope.mjs`・n=40）

`MAX_TICKS = 2500`で打ち切られた選手は`finished=false`のまま
`finishTime = MAX_TICKS + (remain / lastDist)`という**外挿**で着順が決まる。
⚠️**外挿された区間は「カットオフ時点の速度で固定」**＝消耗も集団の駆け引きも地形も効かず、
決着処理（`finishAbility`）にも乗りにくい。

| テンプレート | 打切率 | 打切時の進捗中央値 | 最悪の残り | ⚠️**勝者も外挿** |
|---|---|---|---|---|
| クリテリウム（平坦） | 2% | 96.1% | 13% | 0% |
| サーキット（平坦+丘） | 4% | 91.3% | 51% | 0% |
| 丘陵ロード | 8% | 93.1% | 20% | 0% |
| 山岳ロード | 21% | 89.8% | 28% | 3% |
| **ヒルクライム** | **65%** | 89.4% | **56%** | ⚠️**55%** |
| **個人TT** | **51%** | 91.7% | 25% | ⚠️**30%** |

⚠️**`finished`はDNF表示には使われていない**（外挿された選手にも順位は付く）。つまり
ユーザーに見えている症状は「未完走」ではなく**「レース終盤の着順が計算ではなく外挿式で
決まっている」**こと。ヒルクライムでは**勝者の55%**がそれで決まっていた。

## ⭐⭐ 欠陥1（真のバグ）：牽引者が居ない集団が完全停止する

⚠️**上限を12000まで上げても終わらないレースがある**と分かり、追跡して特定した。
`mode="draft"`のまま**前進量ちょうど0.0000で永久に凍結**している選手がいた。

原因：移動パス（手順3）は`if (en.mode === "draft") return;`でドラフト勢を除外し、
位置は後段の集団ループで`groupDist`から与えられる。ところが集団ループは
`const puller = members.find(en => en.mode === "pull"); if (!puller) return;`で、
⚠️**牽引者が居ないと何もせずに抜ける＝その集団の全員が1ミリも動かない。**

**牽引者が居なくなる経路は2つある**（`scratchpad/w56_paths.mjs`で切り分け）：

| 経路 | 原因 | 持続 |
|---|---|---|
| **A** | ⭐**集団が全員エース**。`canPull`が`if (en.isAce) return false;`で除外し、⚠️**非常時フォールバックも`members.filter(en => !en.isAce)`でエースを除外**しているため`puller`が永久にnull | **恒久**（レース終了まで） |
| **B** | 選ばれた牽引者が`attackLeft > 0`だとモード割り当てで`"attack"`が優先され`"pull"`が居なくなる（`canPull`は`attackLeft`を見ていない） | 一時（最大約30tick） |

⚠️経路Aの実例は**残脚3.1・4.2と消耗すらしていない**（単にエースだから牽けない）。
「エースだけの小集団」は終盤にフィールドが割れるほど起きやすい。

`if (active.length === 0) break;`で全員ゴール時に早期終了し、`posHist`も実際のtick数までしか
伸びる。⚠️**したがって上限を上げても、2500以内に終わるレースには一切コストがかからない。**
（TODOに書いた「コース長・地形からtick予算を算出する」は過剰設計だった。）

## 確定仕様（ユーザー合意済み）

### 修正1：牽引者が居なければ立てる（欠陥1・両経路をこの1箇所でカバー）

`src/sim/ticks.js`のモード決定ループ内、`members.forEach(en => {...})`でモードを配った
**直後**に置く。

```js
      // 第56弾(devlog/wave56.md): 集団に牽引者が1人も居ないと、ドラフト勢は移動パス
      // (手順3)から除外されたまま後段の集団ループも`if (!puller) return;`で抜けるため、
      // ⚠️【その集団の全員が1ミリも動かない】。2経路ある：
      //   A(恒久) 集団が全員エース … canPullも非常時フォールバックもエースを除外していた
      //   B(一時) 選ばれた牽引者がattackLeft>0で"attack"に転じた
      // どちらも「集団に居るのに前進0」という物理的にあり得ない状態なので、最後の砦として
      // ドラフト勢の中で最も脚が残る選手を牽引に立てる（エースであっても立てる——
      // 全員エースなら誰かが牽くしかない）。⚠️凍結する集団でのみ発火するため、
      // 牽引者が居る正常な集団の挙動は完全に無変更。
      if (!members.some(en => en.mode === "pull")) {
        const pool = members.filter(en => en.mode === "draft");
        if (pool.length) {
          const p = pool.reduce((best, en) => (en.energy > best.energy ? en : best), pool[0]);
          p.mode = "pull"; p.slot = 0;
        }
      }
```

⚠️既存の「非常時フォールバック」（`fallbackPool = members.filter(en => !en.isAce)`）は
**そのまま残す**。あれは「エースに牽かせない」という正しい意図を持っており、
今回の追加はその後段の**最後の砦**として働く（＝通常はフォールバックが先に解決する）。

### 修正2：`MAX_TICKS` を 2500 → 7000

実測の最大必要値5,849に約20%の余裕。⚠️**外挿フォールバックは残す**
（`finishTime = MAX_TICKS + remain/lastDist`）——修正後は発火しないはずだが、
未知の非停止ケースに対する安全網として必要。

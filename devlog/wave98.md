## 4. 実測

### 4.1 仮説「割れなければ判断は効かない」は⚠️**外れた**

各判断地点を「等価」「動いた」に分け、割れ具合を比較（PRO9年目・21レース・脚十分のみ・
各選択肢4回）。

| | n | 判断後のsolo tick | 終盤の集団人数 | 選択肢間のsolo差 |
|---|---|---|---|---|
| **等価** | 459 | 252.9 | 2.4 | 171.9 |
| **動いた** | 811 | 250.9 | 2.3 | 188.0 |

⚠️**3指標すべてほぼ同一＝無相関。** 等価だった地点でも⚠️**選択肢間でsolo tickが平均171.9も
違う**（＝選択は隊列を確実に変えている）のに最終着順が変わらない。
⇒ ⚠️**「集団に埋もれるから判断が効かない」は完全に否定された**（集団関連の仮説は
第97弾§4.13の「集団サイズ」と合わせて⚠️**2回連続で外れ**）。

⚠️**ただしこの結果は機構として不自然だった**——solo tickが171も違えばレース展開は
別物のはずで、それで着順が同じなら⚠️**着順の決まり方そのものか、計測に原因がある。**
第96弾§7.6に従い、⚠️**結論を出す前に「等価」の判定自体を検査した。**

### 4.2 ⚠️⚠️ 原因判明：「不活性36%」は**指標の誤り**だった

#### ①反復回数を変えたときの等価率
| REPEAT | n | 等価率 |
|---|---|---|
| 2 | 653 | 34% |
| 4 | 653 | 37% |
| 8 | 653 | 39% |
| 16 | 653 | ⚠️**40%** |

⚠️**反復を増やすほど等価率が上がる**——ばらつきが減って収束する方向が「等価」である。

#### ②着順で見るか、ゴールタイムで見るか（n=653）
| 判定基準 | 等価率 |
|---|---|
| 着順（差<0.5着） | 40% |
| ⚠️**ゴールタイム（差<1.0秒）** | ⚠️**6%** |
| 両方 | 4% |

⚠️⚠️**判断は94%の場面でゴールタイムを動かしている。動いていなかったのは着順だけ。**

#### ③等価と判定された地点の実値（⚠️8件中7件が「着順1.00」）
```
[2] finale@0.73 flat   send / kick
    着順   : 1.00 / 1.00
    タイム : 1233.7 / 1249.1    ⚠️15.4秒違う
[4] finale@0.80 hill   send / kick
    着順   : 1.00 / 1.00
    タイム : 1671.9 / 1706.3    ⚠️34.4秒違う
[3] mid@0.50 hill      attack / conserve / hold
    着順   : 1.00 / 1.00 / 1.00
    タイム : 1669.6 / 1711.0 / 1710.7   ⚠️41.4秒違う
```

⚠️**能力100/PROの選手は多くのレースで勝ってしまい、1着は1着より上がないので、
どの手を選んでも着順が1.00になる。それを「判断が効いていない」と読んでいた。**

### 4.3 ⚠️結論：#36（旧#32-i）の円熟側は**存在しない問題だった**

⚠️**第97弾§4.11・§4.12・§4.15で繰り返し結論した「健全な場面の34〜36%で判断が結果を
動かさない」を撤回する。** 天井に張り付いていたのは⚠️**判断ではなく測定尺度**だった。

⚠️**§4.12で「乱数ではなく本物」と念入りに確かめたのも的外れだった**——
乱数か設計かを分離しても、⚠️**尺度そのものが飽和していれば意味がない。**
「8回平均でも34%」は「8回とも1着だった」を意味していたにすぎない。

| 記録 | 判定 |
|---|---|
| §4.11「円熟は判定条件が無い」 | ⚠️**無効**（問題自体が無い） |
| §4.12「36%は乱数ではなく本物」 | ⚠️**無効**（尺度の飽和） |
| §4.15「地形別に差がある」 | ⚠️**無効**（平坦46%は「平坦で勝ちやすい」の裏返し） |
| §4.1（本弾）「割れ具合と無相関」 | ⚠️**結果自体は正しいが、比較対象が無意味だった** |

⚠️**新人側（脚が「限界」で選択肢間の着順差が厳密に0.00・頻度43%）は別問題として残る。**
こちらは⚠️**着順もタイムも動かない**（脚が尽きて何もできない）ため、尺度の問題ではない。

### 4.4 ⚠️教訓：3度目の計測の誤り
第96弾§7（`es[0]`＝AI選手を測っていた）、第97弾§4.13（`s.races`＝1年目の2レースを
測っていた）に続き、⚠️**同じ系統の誤りが3度目**。今回は⚠️**「何を成果とみなすか」の
取り違え**だった。

⚠️**共通する構造**：
- ⚠️**それらしい値が返るので誤りに気づけない**（AI選手にも着順はある／2レースでも数字は出る／
  1着も着順である）
- ⚠️**「意外な数字」が出たときだけ気づけた**——今回も「solo tickが171違うのに着順が同じ」
  という⚠️**機構として不自然な結果**が入口だった。

⚠️**今後の原則に追加**：
- ⚠️**成果指標が飽和していないかを最初に確認する**（着順なら「1着の割合」、
  金額なら上限、など）。⚠️**飽和した尺度の上で何を層別しても意味がない。**
- ⚠️**離散量（着順）で差を測るときは、連続量（タイム）でも並べて確認する。**


### 4.5 EV計測ツールに飽和チェックを組み込んだ（3度目の再発防止）

`tools/decisioncard_ev.mjs`に：
- **Δ秒（ゴールタイムの差）を記録・併記**。着順が飽和しても差が見える連続量として必ず並べる。
- ⚠️**無入力基準の勝率が40%以上なら自動警告**（「着順が天井に張り付いており
  Δ着順≒0は判断が効いていない証拠にならない。Δ秒で判定すること」）。
- ヘッダーに経緯と原則を明記。

⚠️**早速、着順だけでは見えなかった事実が出た**（RUL/easy・能力100/PRO）：
| 手 | Δ着順 | ⚠️Δ秒 |
|---|---|---|
| `finale/send` | +0.87（悪い） | ⚠️**-8.6（速い）** |
| `finale/kick` | +0.29 | +2.0 |
| `mid/attack` | -0.60 | ⚠️**-65.1** |

⚠️**`send`は着順で負けタイムで勝つ**——第96弾§7.11「sendは勝率を取りに行く手」と整合する。
`mid/attack`の-65.1秒は⚠️**Δ着順-0.60では到底伝わらない大きさ。**

### 4.6 ⚠️新人側は本物だった（同じ罠ではない）

§4.3で「新人側は尺度の問題ではない」と書いたが、⚠️**タイムは実際には測っていなかった**
（着順差0.00という記録だけ）ので確認した。

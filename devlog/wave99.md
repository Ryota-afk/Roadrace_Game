## ユーザーが決めた2つの分岐（本弾の前提）

### 分岐1：賭けるものは「金と活力の両方」

提示した3案（活力のみ／金のみ／両方）のうち**両方**を選択。

- **金**：31-C の「使い道を足すのではなく競合させる」に乗る。開発・科学トレと同じ財布を取り合う。
- **活力**：`player.vitality`（0〜100）。`vitMul = 0.55 + 0.45*min(1, vit/70)`
  （`controllers/mylife/month.js:36`）で、**70を割ると練習・出走経験の伸びが鈍る**。
  現状の消費はレース1回で `5 + grade*2`（7〜13）、練習3、完全休養+22、オフシーズン+20〜40。
- ⚠️**この組み合わせが持つ自己矛盾が、そのまま緊張になる**——本気度の見返りは成長であり、
  支払うのは「成長の芯」である。育てるために育つ力を削る。

⚠️**第93弾の実測が従来方針の根拠を崩していたことを記録しておく。** TODO 32-d には
「賭けるのは金（#16の恒久シンク不足を埋める）」とあったが、第93弾では
**シンクを使うプレイヤーは吸収力3,100万/年 対 純収入1,600万/年＝常に資金不足**と判明して
いる。つまり「余った金の捨て場」という動機は成立しない。金を賭ける意味は
**「余りを捨てる」ではなく「開発と取り合う」**である。

⚠️**懸念（未解決・UI設計で解く）**：コストが2種類あるとUIが重くなり、CLAUDE.md §7の
引き算原則と衝突する。**「本気度」というつまみ1つに対して結果が2行出る**形にはしない。
候補提示（§8手順1）の段階でここを主要な争点として扱う。

### 分岐2：構造は「賭け型（閾値で払い戻し）」

提示した2案（購入型／賭け型）のうち**賭け型**を選択。

- 出走前に本気度を上げると、**目標**（例「3位以内」）が宣言され、相手が強くなる。
- 達成すれば大きな見返り。**外せば賭けたものは没収され、見返りはゼロ。**
- 購入型（着順に関わらず倍率が付く）を却下した理由：CLAUDE.md §0-1 の
  「分散ゼロの購入は判断ではない」に近づくため。

## 実装レバー（新しいsim機構は不要）

第96弾で「難易度つまみは正しく効く」と確認済みの経路をそのまま使う：

- `buildMyLifeSim(raceMeta, player, team, classIdx, difficultyId, ...)` は
  `DIFFICULTIES.find(d => d.id === difficultyId)` から `aiMul` と `abilCap` を引くだけ
  （`sim/buildMyLifeSim.js:28`）。**本気度は「そのレースだけ aiMul を上乗せする」で表現できる。**
- 賭け金の年次スケールは既存の `mlPrivateCampCost`（`120 + (year-1)*40 + classIdx*60`）と
  同じ形が使える。y1/B1で120万、y9/PROで560万、y20/PROで1,000万。
- ⚠️**`abilCap`は動かさない**方針で計測している（`mlAiCapFor`の92/96/102/112は据え置き）。
  「別の（もっと強い）選手が来る」ではなく**「同じ顔ぶれが本気を出す」**という意味論に
  合わせるため。

### 置き場所の技術的制約（調査済み）

- `mlStartRace`（`hooks/useMyLifeGame.js:202`）が **出走表を出す前に sim を組み終えている**
  （`ml.result = sim`）。
- したがって本気度を**出走表の画面で**動かすなら、`buildMyLifeSim` の再実行が必要。
  ⚠️**これは既に確立した挙動**——`RaceView`の判断カードが選択のたびに再simしている
  （`resimBusy`）。1回のsim再構築は実測 **約315ms**。
- 出走表で決められると、**本気度を上げると出走表の顔ぶれが実際に強くなるのが見える**
  ＝説明文を書かずに伝わる（§7・§8の「レイアウト・ビジュアルで伝える」）。
  ホーム（`hub.jsx`）で決める形はこの利点を失う。

## 計測（§10・before）

設計が2つの数値に依存するため、候補提示より前に測る。プローブは
`scratchpad/intensity_probe.mjs`（srcは一切変更せず、`DIFFICULTIES`へ計測用の行を
一時追加して `aiMul` だけを動かす）。

- **M1. 感度**：aiMul を +0/+0.08/+0.15/+0.25/+0.40/+0.55 と回したとき、プレイヤーの
  平均着順・勝率・3位以内率・Δ秒はどれだけ動くか。**動かなければ本気度は見た目だけの装置**。
- **M2. 素の達成率**：各キャリア段階（新人B1/y1 能力60、中堅A/y5 能力80、円熟PRO/y9 能力92、
  極みPRO/y9 能力100）で、素の3位以内率・10位以内率は何%か。
  ⚠️**閾値を置くにはこれを知らないと「必ず成功」か「絶対無理」になる。**

第98弾§4.2の教訓に従い、**着順とΔ秒を必ず併記**し、素の勝率が40%以上の条件には
飽和の警告を出す（着順は1着が天井なので、強い選手では判断の効果を隠す）。

## 設計上の未決事項（計測後に確定する）

1. **閾値の置き方**。固定（3位以内）か、レースのグレード・適性で動くか。M2の素の達成率が
   段階によって大きく違えば固定は成立しない。
2. **つまみの段数**。悪魔の釜は連続値だが、§7の引き算原則からは2〜3段が上限に見える。
3. **見返りの通貨**。出走経験の倍率は1レースでは**目に見えない**（+1能力が+1.6になるだけ）
   ＝§7の可読性問題。人気度（`popGain`・マイルストーンで金にもなる）とバッジ進捗は離散で見える。
   ⚠️**「見返りが見えない賭け」は賭けにならない**ので、ここは計測より設計の問題として扱う。
4. **桜井の反省点2つへの対処**。①常にギリギリを突きつけない（＝本気度0が常に正当な選択で
   あること）②「下げれば楽になる」の周知（＝本気度を上げない選択が罰されないこと）。

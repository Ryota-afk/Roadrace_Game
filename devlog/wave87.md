**①資金＝年俸に減額を入れる＋高額の使い道を足す／②人気度＝減衰＋獲得の逓減**。

## 診断：どちらも「減る仕組みが無い」という同じ形

| | 増える | 減る |
|---|---|---|
| **年俸** | `salary = s.salary + salaryGain`（毎年加算） | ⚠️**無い**（`Math.min`も減額処理も0箇所） |
| **人気度** | `popGain`（着順×グレード） | ⚠️**無い** |
| （比較）世界pt | 着順×グレード | **年×0.72で減衰**（`decayedWP`） |

⚠️**世界ptだけが減衰を持ち、年俸と人気度には無い。** 一貫性の欠如がそのまま破綻の原因になっている。

支出側（`mlLivingCost` ＝ 年俸税 + 車Lv×4 + 家Lv×4 + コーチ月給）は
⚠️**車・家・コーチのいずれも上限があるため定数で頭打ち**になる。
**収入は青天井・支出は天井あり**という構造。

## ①-a 年俸に減額と上限を入れる（確定）

### 現状

```js
// controllers/mylife/month.js:433-434
const salaryGain = Math.round(s.points * 2.2 + yearWins * 18 + yearPodiums * 7);
const salary = s.salary + salaryGain;
```

初期年俸は経歴別に 220／280／360万円（`createChar.js:208`）。移籍時のみ
`salary * offer.salaryMul` で変動する。**年俸が下がる経路は存在しない。**

年俸の使われ方は1箇所だけ：`month.js:263` の
`money += Math.round(s.salary / 12)`、および `mlLivingCost` の
`salaryTax = salary/12*0.5`。⚠️**差引き＝手取りは `salary / 24`（月）**。

### 変更

```js
// data/economy.js に追加
export const ML_SALARY_CAP   = [1200, 3000, 8000];  // B1 / A / PRO の年俸上限（万円）
export const ML_SALARY_FLOOR = [ 180,  400,  900];  // 同・下限

// controllers/mylife/month.js（上記2行を置き換え）
const perf = s.points * 2.2 + yearWins * 18 + yearPodiums * 7;   // その年の評価額
const salary = Math.round(Math.min(
  ML_SALARY_CAP[s.classIdx],
  Math.max(ML_SALARY_FLOOR[s.classIdx], s.salary * 0.9 + perf)
));
```

**設計の意図**：
- `s.salary * 0.9 + perf` の平衡点は `salary = 10 × perf`。⚠️**成績が落ちれば年俸も落ちる**
  （実績に見合わない分が毎年1割ずつ剥がれる）。世界ptの0.72減衰と同じ思想。
- クラス別の上限で、長期キャリアでも青天井にならない。
- 下限で序盤・不調期の破綻を防ぐ。
- ログ文言は現行の「戦績が評価され年俸+N万円」が**減額時に破綻する**ため、
  増減で分岐させる（下記「UI」参照）。

⚠️**計測必須（§10）**：`ML_SALARY_CAP`／`FLOOR`／減衰率0.9は⚠️**机上の値であり未検証**。
実装時に第86弾と同じ自動プレイを回し、**10年目・20年目の資金と年俸**をbefore/afterで
比較して調整すること。目標は「⚠️10年目時点で、資金がゲーム内最高額の買い物（900万円）の
数倍に収まる」。

## ② 人気度に減衰と逓減を入れる（確定）

### 現状

- 獲得：`mlFinishRace`／`mlFinishTeamTT`（第84弾）／アシスト成功／代表の役割／
  アンビション報酬の`reward.pop`／スポンサーの仕事
- **減衰：無い**
- 用途：月収 `floor(pop/10)*2` 万円／スポンサーの仕事の解禁（20以上）と報酬額／
  `POP_MILESTONES`（25・50・75・100で一時金80・150・250・400万円）／
  スターの道の段（40・60・80・95）

実測（第86弾）：年間獲得は +8 → +13 → +25 → +30 と伸び、**6年目に100（上限）到達**、
以後40年間ほぼ動かない。

### 変更

**(a) 獲得の逓減** — 第84弾で切り出した `domain/mylife/popularity.js` の
`applyPopGain` に集約する（⚠️**通常レースとチームTTの両方が通る唯一の合流点**なので、
ここ1箇所で両方に効く）。

```js
export function applyPopGain(player, popGain) {
  const cur = player.popularity || 0;
  // 人気度が高いほど上がりにくい（有名になるほど、さらに上げるのは難しい）
  const effective = popGain * (1 - cur / 100);
  ...（以降は現行どおり。popularity = clamp(cur + effective)）
}
```

**(b) 年次減衰** — `month.js` の `finalizeYearEnd` 内、⚠️**`decayedWP` を計算している
のと同じ場所**に置く（世界ptと同じ「年度末に減衰」の思想で揃える）。

```js
// data/economy.js
export const ML_POP_DECAY = 0.9;   // 年10%減。世界ptの0.72より緩やか
// finalizeYearEnd 内
player.popularity = Math.max(0, player.popularity * ML_POP_DECAY);
```

**平衡点の試算**：年間獲得 g のとき `dp = g(1 - p/100) - 0.1p` が0になる p が平衡。
g=30 なら `30 - 0.3p - 0.1p = 0` → **p ≈ 75**。
⚠️**スターの道の最終段（95）は、例外的な成績（g が十分大きい年）でのみ届く**ようになる。

⚠️**計測必須（§10）**：g=30 は第86弾の実測（4→5年目の+30）に基づくが、
⚠️**逓減を入れると g 自体が変わるため、この試算は循環している。**
実装後に自動プレイで**5年目・10年目・20年目の人気度**を実測し、
`ML_POP_DECAY` を調整すること。目標は「**10年目で70〜85に落ち着き、100に張り付かない**」。

⚠️**副作用の確認が必要な箇所**（実装時に必ず見ること）：
- `POP_MILESTONES` は `popMilestones` 配列で**一度到達したら再取得できない**設計。
  減衰で25を割っても再取得はされない（＝現行の意図どおり）。⚠️**これでよいかを確認する。**
- スポンサーの仕事は**人気度20以上で解禁**。減衰で20を割ると⚠️**解禁済みの行動が消える**。
  手触りとして許容できるかを実機で確認すること。
- 月収 `floor(pop/10)*2` も減る。

### ⚠️却下された案と理由（再提案しないこと）

| 案 | 却下理由（ユーザー判断・2026-08） |
|---|---|
| 資金で人気度を買う | スターの道が「金で買える道」になる。既存の「スポンサーの仕事」と逆方向の取引で往復ループの検算が要る |
| 弟子への育成投資 | ⚠️**リスクとリターンが無い。既存のものを少し広げただけ** |
| ホームを買う／僚友を引き留める | 同上。結局「倍率を買う」だけで家・車と同じ形 |
| レースを買う | 一戦で消えて何も残らない。倫理的にもグレー |
| 自分のレースを興す／育成アカデミー | 同上（リスクとリターンが無い・既存の延長） |
| 年間宣言の賭け | ⚠️**直接的な賭けは違う。** 金を入れて出てくるのがまた金で、ゲーム状態が何も変わらない |
| 特化改造（上限オフセットを歪める） | 方向は悪くないが⚠️**型にハマっている**（「片方を+、もう片方を−」は最も定型的なトレードオフ） |
| エース確約を買う（絆を失う） | ⚠️**論外** |

⚠️**この一覧から読み取るべき基準**：
1. **リスクとリターンがあること。** ただし⚠️**直接的な賭け（金→金）ではなく、
   ゲーム状態に不可逆な帰結が残る交換であること。**
2. **既存の仕組みの延長でないこと。**

⚠️採用された2案（ワンオフ機材の開発／科学トレーニング）が満たしているのはこの2点で、
**どちらも「終わったら何かが残る／何かを失う」プロジェクト**である。

## ⚠️スポンサーの仕事の扱い（ユーザーからの問い）

**現状は成立していない。** 人気度100で報酬 `30 + 100×1.2 = 150万円`。対して10年目の
所持金は6,525万円＝**2.3%**。しかも**1ヶ月と疲労+12**（レースも練習もできない）を消費し、
もう一方の報酬である**人気度+3も6年目以降は上限100で捨てられる**。
⚠️**報酬が2つとも飽和した資源なので、合理的なプレイヤーは絶対に選ばない。**

⚠️**ただし死因はこの機能ではなく経済の破綻の側にある。** ①-aで資金に天井が付き、②で
人気度に減衰が入れば、支払う2資源とも希少に戻る。それでも年俸上限8,000万＝手取り月333万に
対して150万は1ヶ月の対価として弱いままなので、**報酬式の作り直しか撤去のどちらかは要る**。

## （旧）①-b 高額の使い道（方向のみ・ユーザー却下済み）

⚠️**「資金で人気度を買う」案はユーザーが却下**（2026-08）。理由の記録：スターの道が
「金で買える道」になること、既存の「スポンサーの仕事」（人気度→資金）と逆方向の取引になり
往復ループの検算が必要になること。⚠️**再提案しないこと。**

⚠️**v20の前例（900万円の家を1段足して効かなかった）から、「もう1段高いグレード」は
解にならない。** 必要なのは**繰り返し投資でき、価格が上がり続けるシンク**。

**有力な方向：②と噛み合わせる。** ②で人気度に減衰を入れると、人気度は
⚠️**「維持するもの」に変わる**。そこへ**資金で人気度を買う手段**（メディア露出・地元支援等）を
置けば、**上限の無いシンクが自然に生まれる**（人気度が高いほど価格を指数的に上げる）。

⚠️**未確定の論点**（着手前にユーザーと詰めること）：
- 資金で人気度を買えると、⚠️**スターの道が「金で買える道」になる**。許容するか、
  買える上限を設けるか。
- 既存の「スポンサーの仕事」（人気度→資金）と**逆方向の取引**になる。
  往復で無限ループが成立しないか（⚠️**要検算**）。
- 月の行動を1つ消費するのか、資金だけで完結するのか。

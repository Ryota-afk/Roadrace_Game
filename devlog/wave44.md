# 第44弾（設計確定）: バッジの枠を増やし、付け替えを「失わない操作」として見せる

2026-08 設計。当初は「所持上限3個の撤廃」として計画していたが、調査の結果**前提そのものが
違っていた**ため、目的を組み替えた（第41弾・第42弾と同じパターン）。

## 発見：上限3個は既に「無料で付け替えられる装備スロット」だった

`ACQUIRE_CONDITIONS`は**累積実績**（通算◯勝・通算◯回）を見ているため、一度条件を満たした
バッジは外しても条件を満たしたまま＝**いつでも戻せる**。実測で確認済み：

```
習得後の所持: mount, closer, escape
mount を外して finisher を習得 → closer, escape, finisher
外した「mount」はまだ条件を満たしているか: true
戻した結果: escape, finisher, mount  → 取り戻せた
```

つまり機能としては既にロードアウトだったが、**UIが「習得」「所持は上限（3個）です。外す
バッジを選んでください」「これと入れ替える」という"失う"言葉**を使っていたため、
プレイヤーは怖くて動かせない。**窮屈さの正体は枠数ではなく言葉**だった。

## 発見：完全撤廃は目的そのものを壊す

- **AI選手のバッジ所持数は平均0.95個**（実測3000人：0個34.9%／1個40.7%／2個19.1%／3個5.4%、
  金特は平均0.00個）。**プレイヤーは3個で既にAIの3倍**持っており、撤廃は明確な強化。
- 各脚質が到達できるバッジは約10種。3枠なら組み合わせは**120通り**だが、**撤廃すると全員が
  同じ10個を持ち1通り＝個性が消える**。ユーザーの方向性（「能力値が横並びでも、持っている
  バッジが違えば別の選手」）と真っ向から矛盾する。

⚠️**上限こそが個性の源**。よって「撤廃」ではなく「キャリアで増やす＋言葉を直す」に変更した。

# 第45弾（設計確定・第44弾の後）: バッジの4段階化

## なぜ第44弾と分けたか

**4段階は梯子・マーク・効果が不可分**だから。「マークで銀・虹を見せるが効果は銅/金の2値の
まま」にすると、銀のマークが出ているのに効果は銅相当、虹なのに金相当という**嘘になる**。
効果は47箇所にべた書きされており、その置き換えが4段階化の本体。よって丸ごと第45弾に置く。

## 梯子（銅 → 銀 → 金 → 虹）

**現行の銅（取得条件）と金（`GOLD_REQS`）の値は動かさない。** 銀を間に挟み、虹を上に足す
（既存セーブのプレイヤーを弱くしないため）。

- 銀 = `round((銅 + 金) / 2)`
- 虹 = `金 × 2`

| 区分 | 種数 | 扱い |
|---|---|---|
| 4段が自然に並ぶ | **10種** | 銅の条件があるので上の式でそのまま刻める（例：山の申し子 2→**4**→5→**10**勝） |
| 要個別調整 | **9種** | オールラウンダー・岳人・鉄の心肺等。**配合限定で銅の条件を持たない**ため、銅＝「持っているだけ」とし、**銀 = `round(金 × 0.6)`** で置く |
| 刻めない | **5種** | 古典3種（石畳巧者・アルデンヌの狼・秋の女王＝表彰台の二値）＋鉄人・大舞台に強い（金条件なし）。**2段階のまま据え置く** |

⚠️虹の要求量が重いもの（無尽蔵のエンジン60回・鉄の心肺60回・食らいつく脚50回・
山の吸血鬼40回・吸収の天才40回・大舞台の申し子20勝）は、**実装前にキャリアで到達可能かを
実測すること**。→ **実測済み。下記「到達可能性の実測」を参照（結論：金×2の一律ルールは
勝利系で破綻するため要修正）。**

## 到達可能性の実測（2026-08・Opus・第44弾の実装後）

実際のゲームロジック（`mlCreateChar`→`buildMyLifeSim`→`mlRaceFinish`→`mlAdvanceMonth`）を
Nodeでそのまま回し、高校卒18歳CLM・難易度easy・出走計画=山岳で16年キャリアを複数回実行した。

### 実測の限界（正直な但し書き）

このシミュレーションは**機材（パーツ）購入・コーチ雇用・アイテム使用・才能開花などの
買い物を一切していない**。実プレイヤーはこれらで能力を上げるため、実際の勝利数は13勝より
伸びる。ただし上の理論値が示すとおり勝率は能力に対して急峻なので、**「どれだけ課金的に
強化したか」で虹への到達可否が決まる**設計になってしまう点は変わらない。

出走・役割ベース（8種）は`金×2`のままで問題ない。**勝利ベースは`金×1.5`（切り上げ）に緩める。**

|---|---|---|---|---|
| 地形系7種 | 2勝 | 4勝 | 5勝 | **8勝**（旧案10勝） |

### 計測ハーネスの注意（次に測る人へ）

⚠️**`player.cond`は1〜5の指数**（既定3・`condMul = [0.92,0.96,1.0,1.04,1.08][c-1]`）。
0〜100だと誤って100を入れると`condMul`が`undefined`→NaNになり、`sim/effects.js`の
NaNガード（`Number.isFinite(e[k]) ? ... : 50`）が**全能力を静かに50へ丸める**。
今回この誤りで「カンスト級の選手が192戦1勝」という異常値を一度出した。異常な測定値が出たら
まずcond/formの値域を疑うこと。`form`は0〜100（既定50）で正しい。

## マーク（菱形・名前の左）

⚠️**紅は使えない。** 実測で`bad`(H4°)と**16°しか離れておらず**（§9の基準は40°以上）、
最上位の勲章が「悪い結果」の色に読まれる。銅(#B87333)も`accent`と16°・`bad`と25°で、
さらに**金との色相差16°・明度差16%＝隣接段階なのに見分けられない**。
→ **色相で4段を作る道は塞がっている**ため、輪郭/塗り/二重という**形の情報量**で解いた。

| 段階 | 見た目 | 実装 |
|---|---|---|
| 銅 | グレーの輪郭 | `fill=none stroke=T.color.sub width=1.4`・10px |
| 銀 | 白の塗り | `fill=#C8CCD0`・10px |
| 金 | 黄の塗り | `fill=T.color.accent`・10px |
| 虹 | **虹の縁＋金の中** | 外枠 `stroke=url(rainbow) width=2`、中 `fill=T.color.accent`・14px |

差が3層（輪郭/塗り → 白/黄 → 一重/二重）に分散するので、どの隣接段階も10pxで見分けられる
（実測済み）。虹だけ一回り大きいこと自体も上位の合図になる。

⚠️**虹＝塗り（5色を10pxに詰める）は不採用。** 実際に描くと「黄緑青っぽい菱形」に潰れ、
金との連続性が切れて別カテゴリに見えた。二重なら縁に面積が稼げて虹色が判別でき、かつ
「金の上」であることが形で伝わる。

### 「虹」という名前について

自転車競技の**アルカンシエル（世界選手権王者ジャージ）**そのもので、文脈的に最適。
⚠️`moveEdge.js`が判断カードのレア度に`rainbow`（虹＝大勝負）を既に使っているが、
**「虹」「金」という語はプレイヤーに一度も表示されていない**（`DecisionCard`が出すのは
選択肢の文言と「不発」だけ）。よって**言葉の衝突は無い**。
配色は既存の`RAINBOW_STOPS`（`#e88bb0 / #F2C94C / #7FB069 / #4f8fe8 / #A76ADC`）を流用する。
⚠️現在`DecisionCard.jsx`にあるので、共有する際は`data/`へ移すこと（§5：データはdata/へ）。

## 効果（銅・金は現行値を据え置き）

- 加算系： 銀 = `銅 + (金−銅) × 0.5`、虹 = `金 + (金−銅) × 0.75`
- 乗算系も同じ内挿・外挿

## AIへの段階配布

第42弾で「AIへの段階配布は効果を伸ばす弾とセットが正しい」と整理した、まさにその弾。

⚠️**配布の分布は実装時に実測して決めること**（強いAIほど上の段階、虹はごく稀、等）。

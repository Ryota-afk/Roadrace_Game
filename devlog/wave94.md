## ⚠️フェーズ2と3は切り離せない（設計の核心）

ユーザー要望は「Lvをパーツごとに」（＝2）と「パーツもリセマラ要素に」（＝3）だが、
⚠️**2だけを入れると履き替えが常に損になり、追いかける動機が構造的に消える。**

現在の一点物の能力値は**ほぼ固定値**である（ランダムなのは「どの能力に付くか」の
シャッフルと大成功判定だけ）。フレームの実測値：

| 方針 | 能力値 | プラス合計 |
|---|---|---|
| 尖らせる | 平坦+20 / 登坂-8 | 20 |
| まとめる | 平坦+6 / 登坂+6 / スプリント+6 | 18 |
| 大成功 | 平坦+8 / 登坂+8 / スプリント+8 | 24 |

⚠️**Lv5まで上げた古いパーツ（×1.6＝平坦+32）を、新しく引いた同じ方針のパーツ（平坦+20）が
超えることは絶対にない。** ⚠️**3は2を機能させるための必須条件であって飾りではない。**

## フェーズ1：一覧に載せる（表示のみ・バランス変更なし）

### 並び順（ユーザー確定：候補C＋プラスの合計）

展開したスロットのリストを、⚠️**2グループ・各グループ内は「効果の大きい順」**にする。

1. **所持しているもの**
   - 装着中のパーツを**先頭に固定**
   - 残りを**プラス合計の降順**（一点物・静的パーツを混ぜて1つの並びにする）
2. **カタログ（未所持・買えるもの）**
   - **プラス合計の降順**

⚠️**見出しは置かない**（グループの区切りは並び順とボタンの文言で表現する。§8「説明文を
書く前に消す・別の見せ方を検討する」）。⚠️**`[所持]`バッジも置かない**——ボタンが
「装着する」か「28万」かで所持の有無は既に読めるため、二重になる。バッジは
`[装着中 Lv3]`だけ残す。

### プラス合計の定義

```
sortKey(p, lv) = Σ max(0, ab[k]) × (1 + ML_PART_LV_MUL * lv)
```

⚠️**マイナスは無視する**（ユーザー確定）。差し引きで並べると、尖らせたパーツ（+20/-8＝12）が
まとめたパーツ（+6×3＝18）の下に来てしまい、専門型にとっての実態と合わないため。

⚠️**Lvを掛けるのは意図的**：フェーズ2でLvがパーツごとになると、育てたパーツが上に来る
＝「今いちばん強いもの」順になる。フェーズ1の時点ではスロット内で全部同じLvなので
順序に影響しない（同じ式のままフェーズ2へ移行できる）。

⚠️**既知の限界**：`ab`が空で条件付き効果だけを持つパーツ（`nu_cool`＝冷感ボトルセット、
`heat`のみ）は`sortKey=0`で常に最下段になる。並び順は目安であって推奨ではないため
許容する。⚠️直すなら条件付き効果にも仮の重みを与える必要があり、それは別の設計判断。

### 画面の全要素（省略なしの列挙）

**折りたたみ時のヘッダー行**（現行から変更なし）：
- 左：`SLOT_LABEL[slot]`（フレーム／タイヤ／ホイール／補給食）
- 右：装着中なら `{パーツ名}　Lv{n}　›`、未装着なら `未装着　›`
- 2行目：装着中なら`partEffectParts(p, 1 + ML_PART_LV_MUL*lv, AB_LABEL).join(" / ")`、
  未装着なら`買える{n}点　{最安}万〜`（買えるものが0点なら`解禁されているパーツがありません`）

**展開時の各行**（`ShopRow`）：
- `label`：パーツ名
- `badge`：装着中の行のみ `装着中 Lv{n}`。他は無し
- `detail`：`partEffectParts(p, 1 + ML_PART_LV_MUL*lv, AB_LABEL).join(" / ")`
- `buyLabel` / `onBuy`：
  - 装着中かつLv上限未満 → `強化 {ML_PART_UPGRADE_COST[lv]}万` → `mlUpgradePart(slot)`
  - 装着中かつLv上限 → ボタン無し・`locked` に `Lv{maxLv} 最大`

  - 未所持 → `{p.price}万` → `mlBuyPart(pid)`
- `buyDisabled`：購入・強化は`ml.money`が足りなければtrue

⚠️**`quality`が未定義のものはマークを出さない**——後から`"silver"`等を割り当てると
実際の`ab`値と食い違う（旧データは倍率を掛けていない＝銀相当だが、断定せずに
無表示のほうが誠実）。⚠️一覧・強化・履き替えはすべて通常どおり動く。

### ⚠️大成功と開発方針の矛盾を同時に解消する

現行の`bigSuccessChance: 0.25`と`if (bigSuccess)`の分岐は⚠️**廃止する**。品質の抽選が
その役割を引き継ぎ、⚠️**形（尖らせる／まとめる）は常に方針どおりになる。**

### ⚠️このフェーズで測るもの（§10）

- 一点物の平均的な強さが上がるか下がるか（期待値1.10なので**上がるはず**）。
  ⚠️上がりすぎるなら倍率表を調整する。判断材料として**装着中パーツのab合計の年次推移**を測る
- 40年で「生涯の一本」を平均何本引くか（10%×開発回数）

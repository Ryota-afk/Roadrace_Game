1. **コメントを除去**する（⚠️最初に書いた版はこれを忘れ、`ticks.js`の57,529字＝全部コード

## ⚠️自分が破っていたルール：`npx vite build`で検証していた

⚠️**第84弾・第85弾とも、検証に`npx vite build`を使っていた。** DEVLOG冒頭の
「デプロイの規律」に**明文で禁止されている**——`npx vite build`は`dist/`へ書くだけで
リポジトリ直下の`index.html`（＝GitHub Pagesがそのまま配信する成果物）を更新しないため、
⚠️**ビルドが通っても配信物は古いまま**になる。

実害：`git log -- index.html`を見ると最終更新は**第83弾**で、⚠️**第84弾のチームTT修正
（人気度・絆・成績台帳）が配信物に一切入っていなかった。** 第85弾で気付いて
`npm run build`を実行し、第84・85弾の両方をまとめて成果物へ反映した。

⚠️**この規律は第41〜67弾の26弾分が未反映だった事故を受けて明文化されたもの**で、
つまり**同じ事故を小規模に再発させていた**。以後、ビルド確認は必ず`npm run build`を使う
（`npx vite build`は打たない）。あわせて**弾を締める前に`git status`で`index.html`が
変更されているかを確認**すれば、この取りこぼしは機械的に防げる。

## ⚠️この弾で得た教訓

⚠️**simの係数を変える弾は、その係数を説明している文言も同じ弾で直す。**
B-1（第80弾）・A-3（第82弾）はいずれも「数値を変えた弾がヘルプを見なかった」もの。
CLAUDE.md §10が「機能追加とバランス計測はセットで行う」と定めているのと同じ理屈で、
**「係数の変更」と「その係数を説明する文言の更新」もセット**にする必要がある。

⚠️**0始まりの内部インデックスを月名・順位名として画面に書かない**（A-1）。
月を書くときは必ず`MONTHS[i]`を経由するか、コード側の定数と突き合わせて確認する。

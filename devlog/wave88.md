## ①-b-1 ワンオフ機材の開発

### 既存システムの確認

- `PART_SLOTS = ["frame", "tire", "wheels", "nutrition"]`（`data/parts.js:9`）
- `PARTS`の形：`{ slot, tier, label, ab: { 能力: 増減 }, price }`
- ⚠️**第17弾で全パーツがトレードオフ化済み**（例：`fr_sprint` は `sprint+4, climb-2`）
- tier1〜3。⚠️**最高額は`fr_ult`の90万円**——つまりワンオフは**桁が違う別クラスの品**になる
- 所持は `ml.partsInv`

### 状態

```js
ml.devProject = {
  slot: "frame",        // PART_SLOTS のいずれか（開始時に選ぶ）
  policy: "sharp",      // "sharp"（尖らせる）| "broad"（まとめる）
  invested: 400,        // 累計投資額（万円）
  startYear: 7, startMonth: 3,
}
```

### 流れ

1. **開始**：スロットと方針を選ぶ。初期費用 **400万円**
2. **追加投資**：任意の月に **+200万** または **+500万** を追加できる（何度でも）
3. **完成**：開始から**3ヶ月**経過後、いつでも「完成させる」を選べる
4. **結果**：`成功率 = min(0.85, 0.30 + invested / 4000)`
   - 400万＝37.5% ／ 1,000万＝55% ／ 2,000万＝80% ／ 2,600万以上＝85%（上限）

| 結果 | 内容 |
|---|---|
| **大成功**（成功判定に通り、さらに1/4） | tier4パーツ。`ab`の合計が tier3 の約1.5倍で**マイナス無し** |
| **成功** | tier4パーツ。tier3相当＋α。マイナスは小さめ |
| **失敗** | ⚠️**何も得られず、投資額は戻らない** |

### ⚠️「賭け」にしないための工夫：方針が結果の形を決める

⚠️**確率分岐だけだと案11（却下）と同じ「金を入れて出てくるのが運」になる。**
そこで**開発方針**をプレイヤーが選び、**出来上がるパーツの形**を決めさせる：

- **尖らせる（sharp）**：1能力に大きく＋、別の1能力に大きく−。成功率 **−10%**
- **まとめる（broad）**：2〜3能力に小さく＋、−なし。成功率 **そのまま**

⚠️これで「何を作るか」がプレイヤーの設計行為になり、運任せではなくなる。
できたパーツは**その選手固有の一点物として残り続ける**（引退時は殿堂の記録に載る）。

## ①-b-2 科学トレーニング（バッジを賭ける）

### ⚠️設計を作り直した経緯

初案は `talentCap`（伸びしろの天井）を上げるものだった。⚠️**しかし第7弾B-3は
「練習だけしていても上限が勝手に伸びる」のを意図的に廃した**ので、それを金で開け直すのは
同じ設計思想に反する。⚠️**賭けの対象を「天井」から「特殊能力」へ移すことでこの矛盾は消える**
——成長キャップにも`talentCap`にも一切触らない。

さらにDEVLOGの「育成の方向転換」に**「能力値で個性を出すのをやめ、バッジで個性を出す方へ
舵を切る」**というユーザー明示があり、⚠️**この案はその方針そのもの**である。

### 既存システムの確認

- `mlAcquireAbility(r, id, swapOutId, maxSlots)`（`domain/mylife/cp.js:106`）
  ——⚠️**枠が満杯のときの入れ替えに既に対応済み**。`swapOutId`で捨てるものを指定する。
  ⚠️**体質（taishitsu）は外せない**仕様も入っている。
- `mlBadgeSlots(ml)` ＝ `ML_BADGE_SLOTS_BY_CLASS = [3, 4, 5]`（B1/A/PRO）
- 悪特能：`choke`（勝負弱い）・`nervous`（大舞台に弱い）・`heavy`（重量級）・
  `glass`（ガラスの体）・`moody`（ムラっ気）
- ⚠️**`ACQUIRE_CONDITIONS[id](r)` のゲートがある**ため`mlAcquireAbility`をそのまま使うと
  条件未達の能力は取れない。**科学トレーニング専用のプールと専用の付与関数**を用意する
  （条件ゲートを通さない。ここが「金とリスクで手に入れる」ことの意味になる）。

### 状態と流れ

```js
ml.sciProject = { invested: 500, startYear: 9, startMonth: 5 }
```

1. **開始**：初期費用 **500万円**
2. **追加投資**：+300万 / +800万（何度でも）
3. **完了**：開始から**4ヶ月**経過後、いつでも「結果を見る」
4. **結果**：`成功率 = min(0.80, 0.25 + invested / 5000)`
   - 500万＝35% ／ 1,500万＝55% ／ 2,750万以上＝80%（上限）

| 結果 | 内容 |
|---|---|
| **成功** | 専用プールから特殊能力を1つ獲得（一定確率で**金**）。⚠️**枠が満杯なら捨てるものを選ぶ（下記）** |
| **失敗** | ⚠️**悪特能を1つ背負う。** `createChar.js:143`の前例（「呪いは通常枠と別枠で背負う」）に倣い**バッジ枠を消費しない** |

⚠️**成功しても失うものがある**のがこの案の核心。枠は B1で3・PROでも5しかないので、
終盤は必ず「今持っているどれかを捨てる」判断になる。

### ⚠️枠が満杯のとき「今回は見送る」は出さない（ユーザー確定・2026-08）

成功して枠が満杯だった場合、⚠️**獲得を諦める選択肢は用意しない。必ず1つ手放す。**

⚠️**理由**：逃げ道があると緊張が消え、⚠️**この案の一番面白い部分（成功しても失う）が
薄まる**ため。「大金を払ったのに強制的に手放させられる」ことを理不尽と感じ得る点は
認識したうえでの判断。

⚠️**実装上の含意**：`mlAcquireAbility`は`swapOutId`が無いと何もせず`r`を返す（`cp.js:110`）。
そのため⚠️**「手放すものを選ぶまで先へ進めない」画面**が必要になる。
体質（taishitsu）は外せない仕様なので、⚠️**手放せる候補が0件になり得ないか**を実装時に
必ず確認すること（全枠が体質で埋まっている場合の挙動）。

### empty state

- **プロジェクト未開始** → 「開発を始める」「トレーニングを始める」の行のみ
- **進行中** → 経過月数・累計投資額・現在の成功率を出し、「追加投資」と
  （最低月数を満たしていれば）「完成させる」
- **最低月数に未達** → 完成ボタンは出さず、⚠️**あと何ヶ月かを明示**する
- **資金不足** → 既存の`ShopRow`の`buyDisabled`と同じ見え方

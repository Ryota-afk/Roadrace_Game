# tools/ — 開発補助スクリプト

ビルドには不要。手作業では現実的に確認できないことを機械にやらせるための道具置き場。

| ファイル | 用途 |
|---|---|
| `simcareer.mjs` | ⚠️**ヘッドレス・キャリアシミュレータ。バランスの実測はまずこちらを使う**（設計はdevlog/wave92.md） |
| `autoplay.mjs` | マイライフを実際にブラウザで通しプレイし、⚠️**UIが壊れていないか**（画面遷移・pageerror）を確認する |
| `money_demand.mjs` | マイライフの「買い切り（有限）の使い道」の総額を`data/`から機械的に合計する。⚠️**価格や段階を足したら流し直すこと**（第93弾で総額11,720万・尽きるのは約13.7年目と判明） |
| `ui_density.mjs` | 画面の情報密度（絵文字・角丸・枠線・フォント段階の数）の棚卸し |
| `verify_baseview.mjs` / `verify_radar.mjs` | 個別コンポーネントの描画確認 |
| `bike_sprites.py` / `render_bike_sheet.py` | ドット絵の抽出・シート書き出し |

## simcareer.mjs

```sh
node tools/simcareer.mjs --careers 20 --years 15 --out /tmp/sim   # 既定値。数十分かかる
node tools/simcareer.mjs --careers 1 --policy frugal --verbose    # 1本だけ詳しく見る
SIM_DEBUG=1 node tools/simcareer.mjs --careers 1 2> /tmp/dbg.log & tail -f /tmp/dbg.log  # 進捗を見ながら流す
```

⚠️**バランスの計測（CLAUDE.md §10）はブラウザ不要でここから行う。** `mlAdvanceMonth`等の
reducerをNodeから直接呼んでキャリアを進めるため、`autoplay.mjs`（1本30分・ブラウザ必須）
より大幅に速く、100キャリアのような複数本の比較もできる。詳しい設計・実測した前提・
「壊してはいけない点」の根拠は`devlog/wave92.md`を参照。

### ⚠️所要時間の実測（当初の見積もりは誤りだった）

設計段階では「40年キャリアが約1.6秒」と見積もったが、これは初回レース（年1本目の
軽いコース）だけを繰り返し計測した誤った前提に基づく。⚠️**実際にはレース1本の
`buildMyLifeSim`（コース生成＋物理ティック）が実測300〜600ms/本かかる**（コースの
距離・グレードで変動）。1キャリア15年（約1,000ステップ）で約1分。それでも
`autoplay.mjs`のレース1本＝実時間20分（アニメーション再生）に比べれば圧倒的に速い
——ヘッドレスはこのアニメーションを一切再現しない（レース結果はアニメ開始前に
`buildMyLifeSim`内で確定済み。詳細はdevlog/wave92.md）。既定を「20キャリア×15年」に
抑えているのはこのため。より深く見たい時は`--careers`と`--years`を上げて個別に流す
（時間がかかる分、バックグラウンド実行を前提にする）。

### 方策（policy）は必ず2つ以上を両方報告する

⚠️第89弾の誤りは方策（資金の使い方）を1つ（frugal＝一切使わない）しか用意しな
かったことで、「資金が余る」という逆の結論を出した。`frugal`と`spender`の差が
そのまま「プレイヤーの選択の幅」であり、それが無ければ資金の使い道は機能して
いないことになる。新しい方策を足すのはよいが、⚠️**既存の方策を削ってはいけない**。

### ⚠️検出器は既知の不具合で較正してから使う

新しい不変条件（`checkInvariants`のA1〜A4）を足したら、その不具合が実際にあった
過去のコミットに対して実行し、⚠️**検出できることを確認してから**「使える」と
判断すること。第83弾で、検出器が既知のバグを検出できないまま「問題なし」と
報告した前例がある。第92弾ではコミット`dd83e9a`の直前（`20b86bc`）に対して
A1・A2が実際に検出されることを確認した。

## autoplay.mjs

```sh
npm run dev                                          # 別のシェルで開発サーバを起動
node tools/autoplay.mjs --port 5173 --out /tmp/ap    # 実行（40年ぶんで20〜30分かかる）
tail -f /tmp/ap/log.txt                              # 実行中でも進捗が読める
```

引数はすべて省略可（`--port` 既定 5173、`--out` 既定 `$TMPDIR/roadrace-autoplay`、
`--steps` 既定 4000）。

### ⚠️このスクリプトを直すときに壊してはいけない2点

いずれも**実際に誤った結論を出した**事故の再発防止として入っている。

1. **破壊的な操作は色で判定してブロックする。文言の列挙に戻さない。**
   確定ボタンの背景色／危険なメニュー項目の文字色が `T.color.bad` かで判定し、確認
   ダイアログでは常に「やめる」を押す。⚠️旧版は押してはいけないボタンを文言で列挙して
   いたため「ラストレースで引退」「出走する」が漏れ、**何歳でも引退してしまった**
   （第89弾。同じ漏れを3回繰り返した）。文言は増えるたびに漏れる。
2. **ショップへ寄って資金の使い道（シンク）を実際に使う。**
   ⚠️これを省いた第89弾の計測は「資金が余る」という**逆の結論**を出し、年俸上限を
   下げる判断に進みかけた（第90弾で撤回）。押せる中で常に最大額を選ぶので、
   これは「使えるだけ使う」極端側の計測である点に注意。

`T.color.action` / `T.color.bad` の実際の値を変えたら、このファイル冒頭の `ACTION` /
`BAD` 定数も同じコミットで更新すること。⚠️**主ボタンは「紫かつ全幅」で判定している**
（選択チップも同じ紫なので、色だけでは進行ボタンを特定できない）。
